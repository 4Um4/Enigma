Everyone blames the model when an AI character contradicts its own past.

I did too. Then I spent a year building a life-simulation engine where NPCs *can't* lie about the world even if they want to — and I found out the bug was never in the LLM. It was in where we put the LLM.

**TL;DR:** If your agent's memory lives inside the LLM (context window, RAG over chat logs, "summarize what happened"), the model isn't remembering — it's *confabulating*, and your architecture gives it no way to be wrong about facts. The fix is boring and beautiful: make truth a database, make memory a derived view, make belief a first-class object that can be *false on purpose* — and then enforce all three with runtime exceptions, not code review.

## The bug nobody named

Here's a pattern you've probably shipped:

```python
# "Memory" for our NPC
messages.append({"role": "system", "content": f"You are Marta. Recap of your life: {summary}"})
reply = llm.chat(messages)
```

The recap is generated by the same model that has to act on it. So when the summarizer hallucinates that Marta's brother died in chapter 2, Marta will mourn a brother who is alive — cheerfully, consistently, *forever*, because the hallucination got written back into her memory.

This isn't a model failure. GPT-4, Claude, Llama — all of them do this. It's an **architectural** failure: we gave a probabilistic text generator authority over ground truth.

Ask yourself one question about your system: *if the LLM output "the brother died," what component physically prevents that from becoming part of the world state?*

If the answer is "prompt instructions" or "we'll catch it in review" — you don't have a memory system. You have a rumor mill.

## Three layers that must never touch

The engine I'm writing (half-finished game, fully-finished epistemology — more on that below) splits what most agent frameworks call "memory" into three separate stores:

```
WORLD TRUTH      → what actually happened (event log, causal spine)
MEMORY           → what the NPC witnessed of the truth (filtered, lossy)
BELIEF           → what the NPC concluded from memory (can be WRONG, by design)
```

The separation buys you two things:

1. **The LLM can never write to truth.** Truth is appended only by the simulation kernel as it processes ticks. An NPC lying to the player is now a *legible behavior* (belief ≠ truth), not a corruption of the database.
2. **Hallucination becomes detectable.** If belief is derived from evidence records with pointers back to events, you can diff `belief` against `truth` at any moment. A contradiction is a bug report, not a feature.

Belief doesn't get set from a single event either. In my aggregator, a belief like *"the master is hiding something"* crystallizes only after a *pattern* of evidence accumulates — suspicion from overheard fragments, contradictions, withheld answers. One bad perception can start a belief; time and counter-evidence revise it. That's what makes an NPC feel psychological instead of scripted.

## The part that actually made this work: architecture you can't ignore

Here's my real argument, the one I'd carve on a tombstone:

> **Documentation is decoration. Enforce your architecture at runtime or don't pretend you have one.**

Every team I've seen writes `ARCHITECTURE.md`, says "only StateApplicator mutates NPC state," and then watches some well-meaning PR violate it six weeks later. We turned the rule into an exception class:

```python
class ArchitecturalViolationError(Exception):
    """Raised on direct mutation of NPCState outside approved writers."""
    def __init__(self, field: str, writer_module: str):
        super().__init__(
            f"Direct write to NPCState.{field} from {writer_module} is forbidden. "
            f"Use StateApplicator."
        )
```

Any module other than the designated writer that touches a guarded field gets this thrown **at runtime, before the mutation lands**. Code review comments get forgotten; stack traces don't.

We did the same for the "LLM exile" rule — the LLM may narrate, reflect, and speak, but may never sit inside the decision loop. Instead of trusting humans, we wrote an AST linter that walks the kernel modules (`tick_orchestrator`, `decision_hub`, the NPC pipeline) and fails CI if it finds `.invoke(`, `.complete(`, `.chat(`, `.generate(` anywhere in them. The rule "the LLM is banned from the kernel" is now a machine-checkable fact, verified on every commit.

## Randomness is a liar too

One more confession: the same category of bug lives in your RNG.

A life sim calls `random.random()` for "did Marta notice the letter?" Great — now the simulation is non-reproducible, and so is your debugging. When a player reports "my NPC forgot my wedding," you cannot replay their session. When your test asserts a behavior, it flakes once a month.

Our kernel bans wall-clock randomness entirely. Every random draw goes through one object:

```python
rng = KernelRNG(tick=42, npc_id="maid_lusya")
if rng.random() < 0.4:  # deterministic for (42, "maid_lusya")
    ...
```

Same `(tick, npc_id)` → same sequence. Different NPC on the same tick → independent sequences. Seed is `sha256(f"{tick}:{npc_id}:{salt}")`. There's a lint rule (AST-based again) that rejects raw `random.*` in kernel files. Replay determinism stopped being a feature and became an invariant.

Notice the pattern: **every architectural promise is backed by something executable** — an exception, a linter, a seed derivation. Not a wiki page.

## "But your game isn't finished!"

Correct. The content pipeline, UX, and half the features are unfinished. What *is* finished is the epistemology: ~440 test files, the layer separation, the guards above. And honestly? That's the point of this post. Most agent demos fail not because the game wasn't polished but because the memory architecture was a prompt. If you take nothing else from this article, take the audit question:

**What happens to your agent's "memory" when the model that writes it lies?**

If there's no mechanical answer — you're shipping a rumor mill. And your NPC *will* look the player in the eye and mourn a brother who's standing right behind them.
