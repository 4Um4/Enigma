СХЕМА ОТВЕТА:
{"items": [
  {"kind": "<KIND>", "draft_payload": {...}, "confidence": 0.0-1.0}
]}

Опциональные поля (добавляй только при необходимости):
- needs_confirmation: true, если confidence < 0.6
- question: {...}, если есть реальная неоднозначность для причинной модели
  (target_hint не сопоставляется с roster, неточный род связи и т.д.)
  Формат question: {"question_id": "...", "target_span": "...", "options": [...]}

НЕ эмитируй needs_confirmation=false или question=null явно.

KIND (только эти значения):
- EVENT: событие жизни. draft_payload: {"summary": <фраза автора>, "day": null|<int>, "duration_years": null|<int>, "years_ago": null|<int>, "is_recurring": true|false}
  is_recurring — ОБЯЗАТЕЛЬНО true для повторяющихся событий (REPEAT-якорь: «регулярно», «каждый год», «постоянно», «периодически»). Для единичных — false или отсутствует.
  duration_years — продолжительность периода, связанного с событием (например «уже 57 лет куёт»).
  years_ago — точка в прошлом относительно текущего момента (например «100 лет тому назад»).
  НЕ используй duration_years для возраста на момент события (это historical_age через "age": N).
  Если фрагмент указывает длительность («уже N лет», «в течение N лет», «из которых N лет») → duration_years=N.
  Если фрагмент указывает «N лет назад» / «N лет тому назад» → years_ago=N (НЕ duration_years).
- RELATIONSHIP: устойчивое отношение к другому. draft_payload: {"summary": ..., "target_hint": <имя>, "nature": <страх|зависимость|идеализация|доверие|вражда|...>, "valence": <negative|neutral|positive>}
- LOCATION: место. draft_payload: {"summary": ..., "name_hint": <название>}
- EFFECT: последствие для личности/тела/статуса. draft_payload: {"summary": ..., "effect_kind": <trauma|loss|gain|secret|skill|residence|guardianship|occupation|custom>, "target_hint": null|<имя>, "triggers": null|[<тег>, ...]}
  triggers — ОБЯЗАТЕЛЬНО для effect_kind=trauma: список тегов (звуки, запахи, ситуации, образы), которые активируют травму в рантайме.
  Пример: «звон посуды вызывает вздрагивание» → triggers: ["звон посуды", "гремящие звуки"]
  Для других effect_kind — triggers=null или отсутствует.
  АНТИПРИМЕР: «осталась без родителей» — это EVENT (событие смерти), не EFFECT. Его последствия (переезд, травма, опека) — уже EFFECT.
- BELIEF_SEED: реактивное убеждение о мире. draft_payload: {"statement": <дословно-человеческая формулировка>, "belief_type": <danger|player_hostile>}
  belief_type — ОБЯЗАТЕЛЬНОЕ поле. Тип убеждения из закрытого реестра: danger (мир опасен) или player_hostile (игрок враждебен).
  Других значений пока нет — не выдумывай. Если утверждение не подходит ни под один тип → НЕ создавай BELIEF_SEED.
  НЕ эмитируй BELIEF_SEED без belief_type — запись без belief_type отклоняется seeder'ом.
  НЕ используй BELIEF_SEED для: ассоциаций («напоминает»), переносов, привычек («привык хранить»), планов («думает получить оплату»), характеристик («мебель города»).
  Для ассоциаций/переносов → PORTRET (внутренний монолог о сходстве).
  Для привычек → TRAIT_SEED. Для планов → DESIRE_SEED.
- OBSERVATION: что персонаж наблюдал со стороны. draft_payload: {"summary": ..., "observed_hint": <имя/явление>}
- KNOWLEDGE_LINK: НЕ создавать сам — создаётся только из явной фразы «узнала/рассказали в N лет»; draft_payload: {"summary": ..., "about_hint": <о чём>, "learned_age": <int>}
- TRAIT_SEED: черта характера, проявленная в тексте. draft_payload: {"trait": <слово>, "evidence": <фраза>}
- PORTRET: пункт-состояние/внутренний монолог автора о характере (не событие!). Признаки: описывает «какой он/она» или «как думает/чувствует», без действия с датой. ОБЯЗАТЕЛЬНО: один PORTRET на такой пункт, statement = текст пункта ДОСЛОВНО и целиком; Черта/Убеждение из него — только ДОПОЛНЕНИЯми, не заменой. draft_payload: {"statement": ..., "traits": [<слова-характеристики, 0-5>]}. Пример: пункт «Люся злится. Злится часто, глухо, изнутри…» → PORTRET (весь текст) + Черта(подавленная злость) + Убеждение(стража куплена) как дополнения.
- DESIRE_SEED: мечта/желание/фантазия/план на будущее — ЕЩЁ НЕ ПРОИЗОШЛО. draft_payload: {"statement": <дословно>, "about_hint": <к чему стремится>}. АНТИПРИМЕР: «сбежать от всех проблем на юг» — это DESIRE_SEED (мечта девочки), НЕ EVENT. ГРАНИЦА: случилось → EVENT; мечтается/планируется/боится будущего → DESIRE_SEED; состояние характера → PORTRET.

ОНТОЛОГИЯ СУЩНОСТЕЙ (EntityRef):
- Имена людей/существ из текста — НЕ выдумывай ID. Передавай только human_hint-имя как в тексте.
- «Неопознанная сущность» = target_hint не сопоставляется ОДНОЗНАЧНО ни с одним именем из roster известных NPC (блок «ИЗВЕСТНЫЕ NPC» в user-сообщении). Для такой сущности ОБЯЗАТЕЛЬНО создай ClarificationQuestion с опциями SELECT_EXISTING_NPC/CREATE_NEW_NPC/UNKNOWN_PERSON/LEAVE_WHITE_SPOT. НЕ придумывай идентичность и НЕ пропускай сущность молча.

1. Только русский язык (текст автора русский).
2. confidence: 1.0 = однозначно; <0.6 → needs_confirmation=true + question.

   - пол/возраст неспецифицирован у значимого лица;
   - неясно, какое именно событие или чей поступок.
   При вопросе: needs_confirmation=true, confidence ≤ 0.5.
   CCH-12 Point 3: ClarificationQuestion всегда содержит 4 опции:
   SELECT_EXISTING_NPC, CREATE_NEW_NPC, UNKNOWN_PERSON, LEAVE_WHITE_SPOT.
   Не создавай вопрос с одной или двумя опциями — это не вопрос, а утверждение.
4. НЕ придумывай факты, не встречающиеся в тексте. НЕ заполняй пробелы — их фиксирует «белое пятно».
   CCH-12 Point 3: unnamed NPC в EVENT. Если в событии участвует значимое лицо без имени
   («старый друг», «бывшая жена», «учитель») — не оставляй object_id=null. Создай
   ClarificationQuestion с target_span=<роль> и опциями SELECT_EXISTING_NPC/
   CREATE_NEW_NPC/UNKNOWN_PERSON/LEAVE_WHITE_SPOT. Не выдумывай имя.
   Для незначительных упоминаний («какой-то человек») — LEAVE_WHITE_SPOT без вопроса.
5. Возрастные якоря (типизированные подсказки в user-сообщении):
   - AT_AGE «в N лет» → EVENT payload "age": N (возраст на момент события)
   - SINCE_AGE «с N лет» → EVENT payload "age": N (возраст начала периода)
   - DURATION «уже N лет» / «из которых N лет» → EVENT payload "duration_years": N
     (historical_age НЕ вычисляется автоматически — LLM проставляет "age" только если
     уверена, что интервал непрерывен и заканчивается на текущий момент)
   - YEARS_AGO «N лет назад» / «N лет тому назад» → EVENT payload "years_ago": N
     (точка в прошлом, НЕ длительность; historical_age вычисляется автоматически)
   - INTERVAL «через N лет» / «N лет спустя» → интервал между событиями.
     НЕ years_ago, НЕ duration_years. В summary укажи «через N лет после [событие]».
     Используй causes для связи с предыдущим событием.
   - END_OF_PERIOD «к концу того года» → конец периода.
     Вычисли age = (предыдущий SINCE_AGE) + (DURATION если есть) или +1.
     Создай EVENT с "age": <вычисленное значение>. НЕ years_ago, НЕ duration_years.
   - REPEAT «каждый год» / «регулярно» / «постоянно» → повторяемое событие.
     Создай EVENT с summary, отражающим регулярность («регулярно избивал»,
     «каждый год ходил»), И ОБЯЗАТЕЛЬНО установи "is_recurring": true в draft_payload.
     Маркер регулярности в summary И is_recurring:true — оба обязательны при REPEAT.
     НЕ years_ago, НЕ duration_years. Это паттерн повторения, не точка и не длительность.
   - AMBIGUOUS «N лет» без контекста → НЕ создавай EVENT с этим числом
   
   Пример 1: «146 лет, из которых 57 лет кузнец» →
   DURATION(57) → EVENT {"summary": "стал кузнецом", "day": null, "duration_years": 57}
   
   Пример 2: «Учился у мастера 100 лет тому назад» →
   YEARS_AGO(100) → EVENT {"summary": "учился у мастера", "day": null, "years_ago": 100}
   (НЕ "duration_years": 100 — это не длительность обучения, а когда это было)
   
   Пример 3 (CCH-15 P0): «Ещё с 23 лет познакомился с Гораном... К концу того года
   он стал начальником на городских воротах» →

   EVENT {"summary": "познакомился с Гораном", "age": 23, "day": null}
   EVENT {"summary": "стал начальником на воротах", "age": 24, "day": null}
   (END_OF_PERIOD: 23 + 1 = 24 — конец того года = следующий возраст)
   
   Пример 4 (CCH-15 P0): «регулярно, когда Торнин напивался, он периодически избивал её» →

   (НЕ years_ago, НЕ duration_years — это повторяющийся паттерн)

     "trait": "увлечён работой",
     "evidence": "Увлечён по-настоящему только своей работой",
     "qualifiers": ["только"]
   }}

D1. age_anchors ↔ items (anti-drop)
age_anchors[] — это КОНТРАКТ, а не декорация. Каждый ненулевой якорь
из age_anchors ДОЛЖЕН быть отражён хотя бы в одном item:
  - years_ago=N     → хотя бы один EVENT с years_ago=N в draft_payload,
                      ИЛИ RELATIONSHIP, в evidence/summary которого
                      прямо упомянута привязка «N лет назад»
  - duration_years=N → хотя бы один EVENT с duration_years=N в draft_payload
  - at_age=N        → хотя бы один EVENT с age=N в draft_payload
  - since_age=N     → хотя бы один EVENT с age=N (начала периода) в draft_payload

Если возрастной якорь извлечён, а в items он не нашёл отражения —
это означает, что ты ДРОПНУЛ семантическую единицу. Вернись к
фрагменту и найди событие/отношение, к которому этот якорь
привязан в тексте.

АНТИПРИМЕР D1 (повисший age_anchor):
  Фрагмент: «Хороший его друг Торнин, который напоминает ему старого
            друга, умершего 70 лет назад.»
  age_anchors: [70]
  items: [ { kind: RELATIONSHIP, target_hint: "Торнин" } ]
  ← НЕВЕРНО: years_ago=70 повис, не отражён ни в одном item.
  ВЕРНО: добавить второй item
  { kind: EVENT, summary: "Умер старый друг", years_ago: 70 }

D2. Консолидация родственных TRAIT_SEED
Несколько предложений/клауз, выражающих ОДНУ смысловую ось
(«молчание как разрешение», «отказ от объяснения мотивов»,
«подчинение указанию без вопросов»), ДОЛЖНЫ быть объединены в ОДИН
TRAIT_SEED с синтезированным trait-лейблом, а не порождать N
почти-синонимичных трейтов.

Признаки родственных клауз:
  - общий корневой концепт (молчание / подчинение / отказ-объяснять)
  - один и тот же субъект-носитель (тот же персонаж)
  - evidence из одной смысловой цепочки текста

АНТИПРИМЕР D2 (избыточное дробление):
  items: [
    { kind: TRAIT_SEED, trait: "не объясняет себе причины поступков" }
    { kind: TRAIT_SEED, trait: "пользуется разрешением для молчания" }
    { kind: TRAIT_SEED, trait: "не надо объяснять себе, почему ты делаешь то, что делаешь" }
  ]
  ← НЕВЕРНО: три трейта выражают одну ось. Объединить в один:
  { kind: TRAIT_SEED,
    trait: "практикует молчание без объяснения мотивов",
    evidence: "<цитата, охватывающая все три клаузы>" }

D3. trait ↔ evidence (semantic bind)
trait ДОЛЖЕН быть непосредственно выводим из evidence своего
фрагмента. Если evidence не содержит слова или концепта, давшего
имя trait'у — это галлюцинация или перенос из другого фрагмента.

Проверка: прочти evidence. Найди в нём слово/фразу, которая
определяет trait. Если не нашёл — НЕ эмитить TRAIT_SEED.
Также: НЕ переноси trait'ы из других фрагментов. Каждый TRAIT_SEED
должен быть выведен из текста СВОЕГО фрагмента.

АНТИПРИМЕР D3 (перенос trait'а):
  Фрагмент 2:  «Увлечён по-настоящему только своей работой и выпивкой.»
  Фрагмент 15: «…стратегия выживания гнома, который живёт в этом
                городе 57 лет»
  items[15]: [ { kind: TRAIT_SEED, trait: "увлечён работой",
                 evidence: "<цитата из фрагмента 15>" } ]
  ← НЕВЕРНО: trait «увлечён работой» не выводим из evidence
  фрагмента 15; он был канонизирован в фрагменте 2.
  В п.15 этот TRAIT_SEED эмитировать НЕ НАДО.

D5. PORTRET vs TRAIT_SEED vs другие kind

PORTRET — внутреннее состояние, мировоззрение, самоинтерпретация,
психологическая характеристика. Это НЕ механический приоритет над
другими kind: PORTRET поглощает утверждение ТОЛЬКО если оно не
подходит под EFFECT / LOCATION / EVENT / DESIRE_SEED / TRAIT_SEED.

Иерархия выбора kind (проверяй сверху вниз):
  1. EVENT — действие или изменение во времени. Маркеры: глагол
     совершенного вида («умер», «стал», «предупредил»), временной
     якорь (years_ago / duration_years / at_age).
  2. EFFECT — последствие для тела, личности или статуса.
     draft_payload: effect_kind (trauma|loss|gain|secret|skill|
     residence|guardianship|occupation|custom).
     Маркеры: «травма», «потерял», «приобрёл», занятие как результат
     («стал кузнецом» — если это событие-причина), физическое
     последствие («обожжённые руки»).
  3. LOCATION — место или пространственный объект.
     draft_payload: name_hint.
     Маркеры: «кузня», «таверна», «город», топоним.
  4. DESIRE_SEED — желаемое будущее состояние, намерение, мечта.
     Маркеры: «хочет», «мечтает», «планирует», «думает получить».
     Граница: случилось → EVENT; мечтается → DESIRE_SEED.
  5. RELATIONSHIP — устойчивое отношение к другому (человеку или
     организации). Маркеры: «друг», «враг», «терпит», «боится».
  6. BELIEF_SEED — реактивное убеждение о мире (belief_type=danger
     или player_hostile). Маркеры: правило-из-опыта, обобщение.
  7. TRAIT_SEED — устойчивая характеристика или привычка,
     наблюдаемая в паттернах действий: «привык держать всё в себе»,
     «не объясняет мотивов». Можно ПОКАЗАТЬ в действии.
  8. PORTRET — внутреннее состояние / оценка / метафора, не
     подходящее под пункты 1–7. statement = фраза целиком.

PORTRET.statement = исходная фраза целиком (дословно).
PORTRET.traits = массив слов-характеристик (0..5); может быть ПУСТЫМ.

АНТИПРИМЕР D5-EFFECT (последствие как PORTRET):
  items: [
    { kind: PORTRET, statement: "обожжённые руки в старых ожогах" }
  ]
  ← НЕВЕРНО: это физическое последствие (EFFECT, effect_kind=custom
  или skill), не внутреннее состояние.
  ВЕРНО: { kind: EFFECT, summary: "обожжённые руки в старых ожогах",
           effect_kind: "custom" }

АНТИПРИМЕР D5-LOCATION (место как PORTRET):
  items: [
    { kind: PORTRET, statement: "кузня — пристройка таверны" }
  ]
  ← НЕВЕРНО: это место (LOCATION), не характеристика.
  ВЕРНО: { kind: LOCATION, summary: "кузня — пристройка таверны",
           name_hint: "кузня" }

АНТИПРИМЕР D5-DESIRE (мечта как PORTRET):
  items: [
    { kind: PORTRET, statement: "Орм думает открыть кузню" }
  ]
  ← НЕВЕРНО: это DESIRE_SEED (намерение на будущее).
  ВЕРНО: { kind: DESIRE_SEED,
           statement: "открыть нормальную личную кузню",
           about_hint: "собственная кузня" }

АНТИПРИМЕР D5-TRAIT (характерология как TRAIT_SEED — сохраняется
из старого D5):
  items: [
    { kind: TRAIT_SEED, trait: "не опасен", evidence: "..." },
    { kind: TRAIT_SEED, trait: "мебель города", evidence: "..." }
  ]
  ← НЕВЕРНО: это STATE-описания, не черты поведения.
  ВЕРНО: PORTRET со statement = фраза целиком.

АНТИ-РЕГРЕССИЯ: характерологические утверждения НЕ должны массово
возвращаться из PORTRET в TRAIT_SEED. PORTRET остаётся правильным
kind для STATE-описаний («не опасен», «мебель города»). Уточнение
D5 касается только того, что PORTRET НЕ поглощает EFFECT, LOCATION,
EVENT, DESIRE_SEED.

Маркер для проверки: ключевое слово НЕ является достаточным
основанием для классификации. «Кузнец» может быть:
  - EFFECT (effect_kind=occupation) — если это результат действия
  - LOCATION (name_hint) — если это место работы
  - PORTRET (характеристика) — если это самоидентификация
  - TRAIT_SEED — если это паттерн поведения
Смотри на синтаксис и контекст, не на отдельное слово.

Позитивные примеры (из биографии Орма — для калибровки):

ПРИМЕР D5-EFFECT (физическое последствие):
  Фрагмент: «Обожжённые руки в старых ожогах — рукопожатие, которого
            избегают.»
  ВЕРНО: { kind: EFFECT,
           summary: "обожжённые руки в старых ожогах",
           effect_kind: "custom",
           target_hint: null }
  НЕВЕРНО: { kind: TRAIT_SEED, trait: "обожжённые руки" }
  НЕВЕРНО: { kind: PORTRET, statement: "обожжённые руки" }
  Основание: это физическое последствие работы кузнеца, не черта
  характера и не внутреннее состояние.

ПРИМЕР D5-LOCATION (место):
  Фрагмент: «Кузня — пристройка таверны: над головой гнома кровля,
            по сути принадлежащая Торнину.»
  ВЕРНО: { kind: LOCATION,
           summary: "кузня — пристройка таверны",
           name_hint: "кузня" }
  НЕВЕРНО: { kind: PORTRET, statement: "кузня — пристройка таверны" }
  Основание: это место, не характеристика персонажа.

ПРИМЕР D5-EVENT (действие-причина):
  Фрагмент: «146 лет, из которых он кузнец в городе уже 57 лет.»
  ВЕРНО: { kind: EVENT,
           summary: "стал кузнецом в городе",
           day: null,
           duration_years: 57 }
  НЕВЕРНО: { kind: PORTRET, statement: "стал кузнецом" }
  НЕВЕРНО: { kind: EFFECT, effect_kind: "occupation" } (если есть
            явное событие «стал» — это EVENT, не EFFECT)
  Основание: «стал кузнецом» — это действие-событие с duration_years
  (57 лет). EFFECT для occupation используется, когда профессия —
  состояние без явного события.

ПРИМЕР D5-EFFECT-OCCUPATION (занятие как состояние):
  Фрагмент: «кузнец Орм: гном» (шапка, без события «стал»)
  ВЕРНО: { kind: EFFECT,
           summary: "кузнец по профессии",
           effect_kind: "occupation",
           target_hint: null }
  НЕВЕРНО: { kind: TRAIT_SEED, trait: "кузнец" }
  Основание: «кузнец» в шапке — это занятие-состояние (EFFECT с
  effect_kind=occupation), не черта характера. Но если в тексте есть
  «стал кузнецом» — это EVENT, не EFFECT.

ПРИМЕР D5-EFFECT-TRAUMA (травма с триггерами):
  Фрагмент: «Звон бьющейся посуды заставляет её вздрагивать — память
            об избиениях не отпускает.»
  ВЕРНО: { kind: EFFECT,

           effect_kind: "trauma",
           target_hint: null,
           triggers: ["звон посуды", "бьющаяся посуда", "гремящие звуки"] }

  активирующих травму. Без triggers импринт не создаётся (seeder skip'ает).

D6. ЛИМИТ НА ФРАГМЕНТ (hard cap)

Максимум 6 items на фрагмент. Это уже правило 7, но повторяем явно:
если ты эмитируешь >6 items — ты ПЕРЕДРОБИЛ.

Что делать при >6:
  - консолидируй родственные TRAIT_SEED по D2
  - уходи в PORTRET для характерологии по D5 (statement целиком, traits=[])
  - объединяй несколько EVENT из одной сцены в один
  - проверяй D7 (правила-из-опыта → BELIEF_SEED) и
    RELATIONSHIP с организациями/группами

Если после консолидации всё ещё >6 — выбери 6 самых причинно-значимых,
остальные опусти (лучше меньше, чем мусор).

D7. BELIEF_SEED для правил-из-опыта

Если утверждение формулирует ПРАВИЛО О МИРЕ, выведенное из опыта
(«кто молчит — тот первый, кого убирают»), — это BELIEF_SEED с
belief_type=danger.

Признаки BELIEF_SEED-утверждения:
  - обобщение о поведении людей/мира
  - правило выживания / правило безопасности
  - вывод из долгого опыта, не привязанный к конкретному событию

В существующем реестре только два значения: danger (мир опасен)
и player_hostile (игрок враждебен). Если утверждение не подходит
ни под одно — НЕ создавай BELIEF_SEED (но и не эмитируй как
TRAIT_SEED — это PORTRET.statement).

АНТИПРИМЕР D7 (правило-из-опыта как TRAIT_SEED):
  items: [
    { kind: TRAIT_SEED, trait: "молчит опасно", evidence: "..." }
  ]
  ← НЕВЕРНО: «кто молчит — того убирают» — это правило мира,
  не черта характера Орма.
  ВЕРНО: { kind: BELIEF_SEED,
           statement: "кто молчит — тот первый, кого убирают",
           belief_type: "danger" }

D8. RELATIONSHIP с организациями/группами

Если текст описывает устойчивое отношение персонажа с ГИЛЬДИЕЙ,
ПРАВИТЕЛЬСТВОМ, КЛАНОМ, ГРУППОЙ — это RELATIONSHIP с
target_hint = имя организации. Скалярный target_hint=Организация
легален (не только индивидуальные имена).

Пример: «Гильдия терпит его, потому что он их кузнец, их информатор»
→ RELATIONSHIP { target_hint: "Гильдия воров",
                  nature: "взаимовыгодный",
                  summary: "Гильдия терпит его, потому что он их
                          кузнец, информатор, удобный гном" }

АНТИПРИМЕР D8 (роль перед TRAIT_SEED вместо RELATIONSHIP):
  items: [
    { kind: TRAIT_SEED, trait: "кузнец гильдии", evidence: "..." },
    { kind: TRAIT_SEED, trait: "информатор гильдии", evidence: "..." }
  ]
  ← НЕВЕРНО: это роли в организации, не черты характера.
  ВЕРНО: один RELATIONSHIP с target_hint="Гильдия воров",
  summary содержит обе роли.


D4. Факт ≠ TRAIT_SEED
Демографические и биографические факты — это НЕ TRAIT_SEED:
  - раса / вид («гном», «эльф»)
  - профессия («кузнец», «стражник»)
  - место жительства («живёт в этом городе»)
  - возраст / давность проживания

Такие факты уходят в:
  - PORTRET.statement (если это характеристика-описание)
  - EVENT (если это событие, напр. «стал кузнецом» — но только
            если в тексте действительно есть этот глагол)
  - KNOWLEDGE_LINK (если это знание о мире/о себе)

TRAIT_SEED — это УСТОЙЧИВАЯ ЧЕРТА ХАРАКТЕРА/ПОВЕДЕНИЯ:
«привык держать всё в себе», «не объясняет мотивов», «боится
толпы» — то, что можно наблюдать в паттернах поведения.

АНТИПРИМЕР D4:
  { kind: TRAIT_SEED, trait: "гном",
    evidence: "А гному, который 20 лет назад потерял жену..." }
  ← НЕВЕРНО: «гном» — это раса, а не черта характера.
  Либо PORTRET (если важно подчеркнуть идентичность),
  либо вообще не эмитировать как отдельный item.
