## Что было добавлено (архитектурно значимое)

### 1. Agent Runner — выделение runtime-слоя исполнения агента
**Файл:** `backend/app/services/game_loop/agent_runner.py`

- Логика исполнения шага агента вынесена из общего loop-контекста в отдельный модуль.
- Снижена связность `game_loop/__init__.py`, что уменьшает риск каскадных регрессий при доработках тика.
- **Почему важно:** это переход от «всё в одном месте» к управляемым точкам расширения.

### 2. Working Memory Tick — выделенный цикл деградации/резонанса памяти
**Файл:** `backend/app/services/memory/working_memory_tick.py`

- Добавлены функции `write_npc_reactions_to_memory()` и `run_decay_and_resonance()`.
- В `EventMemory` добавлен `decayed(game_days)` как атомарный механизм временного распада значимости.
- **Почему важно:** память начинает жить как самостоятельная подсистема с детерминированным шагом обновления.

### 3. NPC Tick Contracts — контракты долговременных обязательств NPC
**Файл:** `backend/app/services/npc/npc_tick_contracts.py`

- Добавлен слой работы с контрактами: извлечение активных обязательств, модификаторы поведения, фильтрация «забытых»/неактуальных.
- Добавлен метод `get_unfulfilled_contracts()` и интеграция в decision-механику.
- **Почему важно:** NPC получают устойчивую причинность поведения, а не только реактивные решения текущего тика.

### 4. Scene Event Layer — слой эмиссии и агрегации событий сцены
**Файл:** `backend/app/services/scene/scene_event_layer.py`

- Добавлен `emit_and_accumulate_scene_events()` как централизованный шлюз событий.
- **Почему важно:** события сцены становятся явной шиной данных, что упрощает наблюдаемость и расширение рендер/DM-слоёв.

### 5. Player Target Pipeline — структурный пайплайн выбора цели игрока
**Файл:** `backend/app/services/spatial/player_target_pipeline.py`

- Добавлены `PlayerTargetResult`, `extract_player_target()`, `detect_and_publish_spatial_transitions()`, `build_spatial_data_for_dm()`.
- Обновлён `TransitTracker` (`get_current_node`, `get_current_priority`) под новый контур spatial-контекста.
- **Почему важно:** снижает неоднозначность target-resolution и улучшает качество пространственного контекста для DM/вербализации.

### 6. NPC↔NPC memory signal — расширение меж-NPC семантики
**Файлы:** `memory_manager.py`, `topic_extractor.py`, `verbalization_context.py`, `npc_state.py`

- Добавлен `detect_npc_patterns()` и связанные поля контекста для взаимодействий NPC между собой.
- **Почему важно:** система сдвигается от player-centric памяти к multi-agent памяти с richer social signal.

## Тестовое усиление (качество, не «пустой код»)

**Файлы:** `test_contracts_stage6.py`, `test_npc_npc_stage7.py`, обновления `test_event_memory.py`, `test_working_memory.py`

- Закрыты критичные контуры: contract tags, decay modifiers, recall по target_npc_id, приоритизация сигналов, fallback-сценарии.
- **Почему важно:** изменения не остались «декларативными» — зафиксированы инварианты поведения.

## Ключевые вторичные и третичные эффекты

1. **Снижение архитектурного риска:** меньше монолитной логики в game loop, проще локально править без побочных эффектов.
2. **Рост предсказуемости NPC:** контракты + decay/resonance повышают консистентность решений по времени.
3. **Усиление трассируемости событий:** scene/spatial-слои дают более прозрачный путь данных до DM/рендера.
4. **Новый класс рисков:** увеличение числа промежуточных слоёв требует строгой синхронизации форматов событий и порядка фаз.

## Что ценно сделано за день (по сути, а не по объёму)

- Выполнен **архитектурный шаг в глубину**: выделены отдельные runtime-подсистемы (agent/memory/scene/spatial).
- Добавлена **новая причинная логика поведения NPC** (контракты + npc↔npc memory patterns).
- Повышена **инженерная надёжность** через целевые тесты на новые инварианты.

Это не «написание пустого кода», а консолидация ядра симуляции в более управляемую и расширяемую форму.
