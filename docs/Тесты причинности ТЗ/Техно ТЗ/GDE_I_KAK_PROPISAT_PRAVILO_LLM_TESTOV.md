### 2.1. Закон §19 — добавить В КОНЕЦ файла (после последнего абзаца §18)

```markdown
---

## §19. LAW OF SINGULAR LLM RUNTIME AUTHORITY (Закон Единого Владения LLM-Runtime)
Статус: Генеральный закон. Рождён из оплаченных инцидентов: дубль llama-server
2026-08-30 (VRAM 96% → 503 на всех NARRATIVE), взаимное разрушение «IPT ∥ pytest ∥ игра»
(исходный мотив TZ-GHOST-1), окно тишины §3.12 РЕЖИМА РАБОТЫ. Полное исследование —
`docs/architecture/LLM_RUNTIME_UNIFICATION_PROPOSAL.md` (карта механизмов §1,
доказанные сценарии разрушения §2.2 A–F).

В ENIGMA может существовать много ПОТРЕБИТЕЛЕЙ llama-server (игра, backend, pytest,
IPT, harness-сценарии), но ровно ОДИН владелец его жизненного цикла.

llama-server — не собственность теста. Тест — КЛИЕНТ LLM-runtime: запрашивает
доступность через единый механизм, честно регистрируется (client label), освобождает
(release). Тест НЕ порождает процесс, НЕ убивает его и НЕ владеет портом.

Нарушение = класс S-конфликтов «взаимное разрушение тестов» (ПРОПОЗАЛ §2.2,
сценарии A–F): atexit-kill переиспользованного сервера, дубль на порту,
KILLER_SPIRIT против живых клиентов.

### §19.1 Запрещено (дублирует и разворачивает §7.21–7.22)
1. Собственный `Popen`/`subprocess` llama-server внутри теста, сценария или скрипта
   (мимо единого механизма).
2. Kill по имени или порту: `taskkill /IM llama-server.exe`,
   `Stop-Process -Name llama-server`, убийство «владельца порта».
3. `atexit`-kill сервера, которым могут пользоваться другие процессы: `atexit`
   клиента делает только `release_lease()` (после этапа 2 ПРОПОЗАЛА — kill только
   при нуле живых HTTP-клиентов).
4. Вторая конфигурация модели/порта: порт и модель — только из
   `app.core.config.settings` (SSOT). Хардкоды `8181`/`8080` и
   `data/runtime_ports` в новых файлах запрещены.
5. Тиражирование IPT-шапки (копипаста `scripts.llm_server_manager` + atexit) в
   новые файлы как способ получить LLM.

### §19.2 Канонический путь (как ОБЯЗАН создаваться LLM-тест)
1. По умолчанию тест LLM-сервер не поднимает вовсе — моки `backend/tests/conftest.py`
   (`mock_model_router`, `initialized_model_pool`). Живой сервер — привилегия, а не база.
2. Тесту нужен живой сервер — единый механизм: фикстура `llm_runtime` /
   `ensure_llm(label="pytest:<nodeid>")` (после этапа 3 ПРОПОЗАЛА); до этапа 3 —
   `scripts.llm_server_manager` через общий spawn-lock, без собственного kill-кода.
   Операционный протокол — `РЕЖИМ РАБОТЫ.md, §3.13`.
3. Клиент именуется (`label`), тест помечается маркером `llm_live` (CI без LLM
   пропускает через существующий exe-guard).
4. Kill/рестарт сервера как часть сценария (доктрина D61) — только через API
   владельца (`/restart` брокера), не собственноручно.

### §19.3 Один владелец — один источник истины
Запрещено вводить конкурирующий механизм управления LLM-runtime или вторую
конфигурацию модели. Структурный аналог §18: одна власть — много проекций;
здесь — один владелец — много клиентов. Нарушение = DOUBLE TRUTH уровня
инфраструктуры (класс S206).
```

## 3. ВСТАВКА 2 — `РЕЖИМ РАБОТЫ.md`

### Протокол §3.13 — добавить ПОСЛЕ §3.12 (в конец файла)

````markdown
### 3.13 СОЗДАНИЕ НОВОГО LLM-ТЕСТА (обязательный протокол; закон — Устав §19)

**Когда применяется:** пишешь или меняешь любой тест/сценарий/скрипт, который так или
иначе касается llama-server (спавн, остановка, живые вызовы, рестарт, порт 8181).
Пропустил протокол — шаг не закрыт (симметрично IPT, §3.8).

**База по умолчанию — моки.** Обычный pytest-тест LLM-сервер НЕ поднимает:
`mock_model_router` / `initialized_model_pool` из `backend/tests/conftest.py`.
Тест проверяет логику, а не генерацию → он не имеет права касаться llama-server.

**Если живой сервер действительно нужен — единый механизм, никакого собственного владения:**

До внедрения LLM Host (этапы 0–2 ПРОПОЗАЛА):
```python
# ДОПУСТИМО (переходный путь) — единый тестовый менеджер через общий spawn-lock:
from scripts.llm_server_manager import start_llama_server
start_llama_server()
# atexit-kill из старой шапки в новые файлы НЕ копировать (Устав §19.1.5):
# для существующих ~30 шапок семантику чинит этап 2 ПРОПОЗАЛА, новые так не пишем.
```

После этапа 3 ПРОПОЗАЛА (LLM Host MVP) — единственный путь:
```python
# КАНОНИЧНО — тест = клиент брокера:
def test_dialogue(llm_runtime):        # session-scoped фикстура из conftest
    url = llm_runtime                  # внутри: ensure_llm(label="pytest:<nodeid>")
    ...
# Никаких Popen / kill / atexit в тесте. Release делает фикстура.
```
- Маркер `llm_live` обязателен: CI (ubuntu, без LLM) пропускает такие тесты через
  существующий exe-guard «exe не найден → continue».

**ЗАПРЕЩЕНО в новых LLM-тестах (гейт ревью; модель запретов — phenomenology-блоки S6):**
1. `Popen`/`subprocess`/`os.system` llama-server внутри теста.
2. `taskkill /IM llama-server.exe`, `Stop-Process -Name llama-server`, kill по порту.
3. Копипаста IPT-шапки с atexit-kill в новый файл.
4. Смена порта/флагов сервера ради теста: порт, модель, флаги — только из `settings`;
   хардкоды `8181`/`8080` в новом коде запрещены (Устав §19.1.4).
5. Собственный kill/рестарт сервера как часть сценария — только через API владельца
   (`/restart` брокера; прецедент — d61-доктрина, транспорт меняется на этапе 5).
   Новый сценарий класса «владею жизнью сервера» — сначала вердикт Мастера.

**Обязательные гейты приёма нового LLM-теста:**
1. **Парный регресс:** тест + IPT (или второй pytest-процесс) запускаются одновременно —
   оба доводятся до конца, llama-server жив (критерии 3/5/6 ПРОПОЗАЛА §8). Один — INVALID
   (§3.12) — повтор в окне тишины, GREEN с параллельной чужой смертью не засчитывается.
2. **Окно тишины (§3.12)** — для GREEN-прогонов, идущих в MUTATIONS/вердикт.
3. **IPT после добавления** — 0 CRITICAL (§3.8).

**ПРИНУЖДЕНИЕ (план, этап 6 ПРОПОЗАЛА):** точечный линтер `scripts/lint_llm_runtime.py`
(grep/AST: `taskkill /IM llama-server`, `Stop-Process -Name llama-server`,
`Popen(...llama-server`, `atexit.register(kill_llama_server)` вне разрешённых файлов)
+ IPT-инвариант `INV-LLM-SSOT-SPAWN` по образцу `INV-LLM-EXILE` (§3.8). До появления
линтера — ручной grep при ревью:
```powershell
Get-ChildItem backend/tests, scripts -Recurse -Include *.py | Select-String -Pattern 'taskkill /IM llama-server|Stop-Process .*llama-server|Popen.*llama-server|atexit.register\(kill_llama_server\)'
```

**Источники:** Устав §19 (закон), `docs/architecture/LLM_RUNTIME_UNIFICATION_PROPOSAL.md`
§6 (таблица «Потребитель: сегодня → после»), §7 (этапы 0–6), §8 (критерии 1–9).
Открытые вопросы ПРОПОЗАЛА §9 (B1–B6) не решаются этим протоколом — вердикт Мастера.
````
