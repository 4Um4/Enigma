# 1. ЦЕЛЬ ЗАДАНИЯ

Сделать так, чтобы NPC действительно использовал собственную память, пережитые события, секреты и индивидуальный стиль при формировании речи.

Сейчас ENIGMA уже вычисляет значительную часть необходимого когнитивного контекста, но теряет его при передаче в LLM.

В результате NPC может:
- иметь воспоминания, но говорить так, словно ничего не помнит;
- хранить сведения о собственных секретах, но не учитывать их при формировании реплики;
- иметь индивидуальный речевой стиль, который не доходит до генерации;
- повторять одинаковые реплики;
- формировать речь без полноценного учёта ограничений собственного состояния.

**Задача архитектора — замкнуть существующий контур, а не построить параллельную систему памяти или общения.**

Итоговая схема:

NPC EXPERIENCE → MEMORY → RECALL → COGNITIVE CONTEXT → SPEECH GENERATION → VALIDATION → NPC_SPOKE → WORLD.

Память должна влиять не только на содержание реплики, но и на то, что NPC предпочитает сказать, умалчивает, вспоминает и каким образом выражает свои мысли.

# 4. ТЕХНИЧЕСКИЕ ИЗМЕНЕНИЯ

## 4.1. Передача когнитивного контекста

Основные файлы:

- `app/services/phases/post_decision.py`
- `app/services/npc/npc_tick_pipeline.py`
- `app/services/execution/dialogue_executor.py`

Необходимо устранить разрыв между формированием VerbalizationContext и фактической генерацией реплики.

В промпт должны попадать:

1. Личные воспоминания NPC.
2. Значимые нарративные события.
3. Извлечённые факты.
4. Сведения о собственных секретах.
5. Индивидуальный речевой стиль.
6. Эпистемическое происхождение сведений.

Не превращать весь контекст в безразборный дамп памяти.

Контекст должен оставаться компактным, структурированным и соответствовать ситуации.

Не допускать телепатии: NPC не должен получать сведения, к которым у него нет эпистемического доступа.

## 4.2. Секреты

Использовать существующий get_suppressed_secrets().

Не создавать новую систему секретности.

NPC должен учитывать собственные секреты при выборе содержания речи, но наличие секрета в памяти не означает автоматическое раскрытие.

Существующие механизмы disclosure остаются авторитетными.

## 4.3. Индивидуальная речь

Подключить уже вычисляемый speech_style.

Расширить:
- max_tokens: 100 → 220;
- max_sentences: 2 → 3.

Не превращать каждую реплику в длинный монолог.

Цель — предоставить модели пространство для естественной речи, сохранив индивидуальный голос и контекст ситуации.

## 4.4. Валидация

В реальный вызов ResponseValidator передавать:

- can_speak;
- can_move;
- recent_text.

Подключить существующие механизмы, не создавать второй валидатор.

Проверить:
- невозможность речи при can_speak=false;
- отсутствие повторяющихся реплик;
- сохранение LANG_LEAK-защиты;
- отсутствие раскрытия запрещённых секретов;
- сохранение существующих NPC-инвариантов.
