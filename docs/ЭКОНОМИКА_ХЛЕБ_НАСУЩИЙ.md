### 1.1 Где живёт экономика

```
backend/
├── app/
│   ├── core/
│   │   └── constants.py          # Единые цены (GOODS_PRICES), зарплаты (WAGES), TICKS_PER_DAY, DAILY_EXPENSES_MIN
│   ├── models/
│   │   └── economy.py            # Dataclass'ы: Need, EconomicProfile, Transaction, Contract

│       ├── game_loop.py          # ИНТЕГРИРОВАНО: EconomyTracker.check_daily_needs() после LifeEngine.tick()
│       └── economy/
│           ├── need_engine.py        # Decay потребностей, генерация драйвов
│           ├── psycho_economy.py     # Связь psychology drives → экономическое поведение
│           ├── stress_calculator.py  # Единая функция расчёта стресса от экономики
│           ├── trade_resolver.py     # NPC→NPC торговля по потребностям (НЕ подключена к game_loop)
│           ├── transaction_engine.py # Исполнение сделок, контрактов, выплат (НЕ подключена к game_loop)
│           ├── market_state.py       # Конечный автомат "quiet/active" для странников (только sandbox)
│           ├── traveller.py          # Генерация визитов странников (только sandbox)
│           ├── profile_factory.py    # Создание EconomicProfile из NPC JSON
│           ├── economic_modifier.py  # Модификаторы решений от экономики
│           └── economy_tracker.py    # НОВОЕ: Трекинг доходов/разговоров, дневные проверки INCOME/SOCIAL
└── npc_sandbox.py                     # Автономная симуляция для калибровки баланса
```

```

economy_tracker.py ← (импортирует) economy.py, constants.py, psycho_economy.py
game_loop.py ← (импортирует) economy_tracker.py, need_engine.py, economic_modifier.py, stress_calculator.py

КРИТИЧЕСКОЕ ПРАВИЛО: Цены только из constants.py. Дубликатов нет.

### Фаза 2: Цепочка кражи для thief (3-5 часов)

**Цель:** Thief получает возможность красть → INCOME satisfied → record_income() заработает

**Предусловие:** Определить механику кражи (навык? случайность? риск-оценка?)

**Задачи:**
1. Определить что такое "кража" механически
2. Thief видит цель через `scene_facts`
3. DecisionHub оценивает intent="steal" с учётом `risk_tolerance`
4. Успех: thief получает gold → `record_income()` → flow → INCOME satisfied
5. Провал: thief получает стресс, возможно конфликт с guard

**Архитектурное решение:**
- НЕ создавать отдельную "steal system"
- Использовать существующий DecisionHub + scene_facts
- Успех/провал через DiceRoll из constants.py
