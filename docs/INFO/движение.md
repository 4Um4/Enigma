# ADR-060: Embodied Topology & Adaptive Ecology (ETKE + AEEL) — Physical Locomotion First

**Дата:** 19.05.2026  
**Статус:** Принято  
**Суперседирует:** ADR-010 (Макро/Микро зоны), ADR-019 (Traversal State), ADR-052 (LOD0 Movement), патчит ADR-060 (ранние редакции)

## Контекст

Существующая пространственная архитектура (NavMesh, `MovementIntent`, `SceneChange`) мертва. Она рассматривает пространство как пустой контейнер с узлами, а NPC — как точку, телепортирующуюся по ребрам графа. Тело — это стат (`speed=2.0`), а анимация — косметический слой.

Это убивает эмерджентность. NPC не могут "перепрыгнуть через ящик", потому что ящика нет в графе. Они не могут "привыкнуть к темноте", потому что их тело неизменяемо. Они не могут "вытоптать тропу", потому что среда не обладает памятью.

**Феноменологическое основание (Мерло-Понти):** Тело — это не объект в пространстве, это наш способ обладания пространством. Телесная схема (Body Schema) — это пред-рефлексивный моторный навык, сопротивляющийся среде. Пространство для NPC должно быть не координатами, а полем моторных возможностей и сопротивлений (аффордансов). Движение должно порождать феромонную логику муравьев — топтать тропы, оставлять следы страха, формировать социальный грунт.

**Критический архитектурный долг:** Ранее мы пытались вырастить нервную систему (интеллект, память, экология) поверх мертвого дискретного перемещения. Построение эволюции и морфологии поверх `teleport to node` обречено. Живость рождается не из 40 когнитивных коэффициентов, а из момента: *"Она почти добежала, споткнулась о ящик, замедлилась, обернулась и продолжила бежать"*. 

Узкое горлышко ENIGMA сейчас — отсутствие непрерывной интеграции позиции: `npc.position += velocity * dt`. Пока существо не способно стабильно пройти 15 метров, споткнуться и ускориться, любые уровни памяти и морфологии бесполезны.

## Решение

Переход к **Топосемантике** (пространство значений) и **Коэволюции** (взаимное изменение Агента и Среды), но строго поэтапно, от физики к сознанию.

1. **Движение = Непрерывная Кинематика (Physical Locomotion First)**. Интеграция скорости, инерции, трения и уклонения от препятствий. Замена телепортации физическим шагом.
2. **Тело = Динамический Фильтр (Телесная Схема)**. Моторное сопротивление и усталость. Тело — не стат, а инерционная функция, ограничивающая желания психики.
3. **Пространство = Поле Аффордансов**. Геометрия как генератор сил отталкивания и притяжения. Преобразование когнитивного желания в физический вектор.
4. **Среда = Стигмергическая Память (Феромонная логика)**. Следы использования уплотняются в тропы, страхи — в проклятые места. (Внедряется после физического ядра).
5. **Коэволюция**. Взаимная деформация Агента и Среды под давлением времени и опыта. (Внедряется последним).

## I. Новые Домены и DTO

### 1.1. AffordanceVector (Физика Возможностей и Сопротивлений)
Примитивная единица смысла пространства. Излучается каждой микро-зоной. Это не просто флаг "можно пройти", это физическое поле, в которое погружено тело.

```python
@dataclass(frozen=True)
class AffordanceVector:
    # Физические возможности (Моторика)
    can_stand: float = 0.0       # 1.0 = твердый пол, 0.0 = пропасть (гравитация)
    can_vault: float = 0.0       # 1.0 = высота таза, 0.0 = глухая стена
    can_climb: float = 0.0       # 1.0 = карниз, 0.0 = гладкий лед
    can_conceal: float = 0.0     # 1.0 = за стеной, 0.0 = центр площади
    can_pass: float = 0.0        # 1.0 = широкая улица, 0.3 = щель
    
    # Кинематическое сопротивление (Физика среды)
    surface_grip: float = 0.8    # 0.0 = лед (скольжение), 1.0 = камень (сцепление)
    drag_coefficient: float = 0.0# 0.0 = нет сопротивления, 1.0 = болото/кусты
    
    # Сенсорные градиенты (L0)
    light_level: float = 0.5     # 0.0 = тьма, 1.0 = слепящий свет
    thermal_mass: float = 0.5    # 0.0 = холод, 1.0 = жар
    exposure: float = 0.5        # 0.0 = скрыт, 1.0 = на виду
    mana_resonance: float = 0.0  # -1.0 = хаос/тьма, 1.0 = порядок/свет
```

### 1.2. DynamicAffordanceField (Пластичная Среда)
Поле возможностей, эволюционирующее под давлением Агентов. Содержит базовую геометрию (статику) и динамические наслоения (следы, деформации).

```python
@dataclass
class DynamicAffordanceField:
    # Базовые значения (генерируются геометрией уровня при загрузке)
    base: AffordanceVector
    
    # Текущие значения (эволюционируют при включенной экологии)
    active: AffordanceVector
    
    # Мета-параметры пластичности (Активируются на Этапе 4)
    plasticity: float = 0.1       # Скорость изменения от действий (0 = камень, 1 = вода)
    persistence: float = 0.99     # Инерция следа (1.0 = вечен, 0.9 = забудется за 10 тиков)
    deformation_sources: List[str] = field(default_factory=list) # Кто менял
```

### 1.3. SocialTraceField (Стигмергия - Феромонная Память Популяции)
Слой компрессии истории перемещений и действий в кластере. Муравьиная логика: пространство учится через использование.

```python
@dataclass
class SocialTraceField:
    movement_density: float = 0.0      # 0.0 = никто не ходит, 1.0 = магистраль (вытоптанная тропа)
    safety_confidence: float = 0.5     # 0.0 = место смертей (феромон страха), 1.0 = безопасная зона
    taboo_strength: float = 0.0        # 0.0 = нейтрально, 1.0 = проклятое/святое
    authority_presence: float = 0.0    # 0.0 = анархия, 1.0 = контроль стражи
    dominant_emission_tag: str = ""    # "shadow_magic", "blood", "prayer"
```

### 1.4. BodySchema (Телесная Схема по Мерло-Понти)
Расширение `NPCState`. Физическое присутствие, инерция и моторные лимиты. Тело — это не просто `speed=2.0`, это сопротивление изменениям и усталость. Желания психики ограничены физикой тела.

```python
@dataclass
class BodySchema:
    # Физические лимиты локомоции (Этап 1 — Физическое Ядро)
    max_velocity: float = 4.0          # Абсолютный предел скорости
    acceleration: float = 6.0          # Сила, с которой тело набирает скорость (инерция разгона)
    braking_force: float = 8.0         # Сила торможения (инерция остановки + трение)
    
    # Моторные возможности (Этап 1 база, расширяются на Этапе 3)
    vault_capability: float = 0.8      # 0.0-1.0 (перепрыгнуть препятствие)
    climb_capability: float = 0.8      # 0.0-1.0 (залезть на вертикаль)
    concealment_volume: float = 0.8    # 0.0-1.0 (насколько компактно может спрятаться)
    
    # Ресурс усталости (Связь кинематики и психики)
    stamina: float = 1.0               # 1.0 = свеж, 0.0 = обессилен. Падает от бега, влияет на max_velocity.
    
    # Когнитивные модификаторы (Этап 2+ — Травмы меняют восприятие)
    tunnel_vision_factor: float = 0.0  # 0.0-1.0 (при панике периферическое зрение сужается)
    
    # Магический аппарат (Этап 4+)
    mana_channel: float = 0.0          # -1.0 (тьма) до 1.0 (свет)
    mana_capacity: float = 0.0
```

### 1.5. DriveVector (Вектор Желания)
Выход `DecisionHub`. Не точка назначения, а направленное усилие психики. Заменяет дискретный `MovementIntent(target_xy)`. Мозг хочет, тело сопротивляется.

```python
@dataclass
class DriveVector:
    direction: Tuple[float, float] # Нормализованный вектор (x, y) направления желания
    intensity: float               # 0.0 - 1.0, сила желания двигаться (от трусости 1.0 до любопытства 0.3)
```

### 1.6. SteeringResolver (Навигационное сопротивление)
Центральный элемент, отсутствовавший в ранних итерациях. Переводит Желание (Drive) в Желаемую Скорость, учитывая геометрию среды. Если психика хочет бежать прямо в стену — Резолвер отклоняет вектор вдоль стены (скольжение).

```python
class SteeringResolver:
    def resolve(
        self,
        drive: DriveVector,
        affordances: AffordanceVector, # Аффордансы текущей микро-зоны
        body: BodySchema
    ) -> Tuple[float, float]:
        """Возвращает желаемую скорость (vx, vy) с учетом препятствий."""
        # Масштабируем желание физическими возможностями тела
        desired_velocity = (
            drive.direction 
            * drive.intensity 
            * body.max_velocity 
            * body.stamina # Усталость режет амбиции
        )
        
        # Генерация сил отталкивания от непроходимых зон (can_pass < 0.5)
        obstacle_force = self._avoid_obstacles(affordances)
        
        # Учет сопротивления среды (болото, кусты)
        drag = self._calculate_drag(affordances.drag_coefficient)
        
        return desired_velocity + obstacle_force - drag
```

### 1.7. MotionIntegrator (Физический Шаг)
Непрерывная интеграция позиции. Та самая строчка `npc.position += velocity * dt`, вокруг которой строится жизнь. Никакой телепортации. Только инерция.

```python
class MotionIntegrator:
    def integrate(
        self,
        npc_position: Tuple[float, float],
        npc_velocity: Tuple[float, float],
        steering: Tuple[float, float],
        body: BodySchema,
        dt: float
    ) -> Tuple[Tuple[float, float], Tuple[float, float]]:
        """Применяет ускорение, инерцию и возвращает новые позицию и скорость."""
        # Разница между тем, куда мы хотим, и тем, куда мы идем
        acceleration = (steering - npc_velocity)
        
        # Ограничение по силе разгона/торможения тела (Тело не может мгновенно сменить направление)
        if magnitude(acceleration) > 0:
            if magnitude(steering) < magnitude(npc_velocity):
                # Тормозим
                acceleration = clamp_magnitude(acceleration, body.braking_force)
            else:
                # Разгоняемся
                acceleration = clamp_magnitude(acceleration, body.acceleration)
                
        # Учет сцепления с поверхностью (на льду тело скользит)
        grip_factor = body.surface_grip 
        effective_acceleration = acceleration * grip_factor
        
        new_velocity = npc_velocity + (effective_acceleration * dt)
        new_position = npc_position + (new_velocity * dt)
        
        # Расход стамины при беге
        if magnitude(new_velocity) > body.max_velocity * 0.7:
            body.stamina = max(0.0, body.stamina - (0.01 * dt))
            
        return new_position, new_velocity
```

## II. Пайплайн Интеграции (TickOrchestrator v2) — Этапы Внедрения

Новые фазы внедряются строго последовательно. **Запрещено** строить Экологию (Этап 3), пока не работает Непрерывная Кинематика (Этап 1).

### ЭТАП 1: ФИЗИЧЕСКОЕ ЯДРО (Physical Locomotion First)

Замена дискретного `MovementIntent` на непрерывный цикл интеграции позиции. NPC учится ходить, падать и ускоряться.

**Новый Пайплайн Тика:**
```
1. DecisionHub → Генерация DriveVector (Желание)
2. SteeringResolver → Преобразование Желания в Ускорение (с учетом стен)
3. MotionIntegrator → Интеграция позиции (velocity * dt)
4. Observation → Обновление восприятия на основе новой позиции
5. Feedback → Влияние усталости/травмы на психику
```

**Интеграция в TickOrchestrator:**
*   **Фаза 5.5: Locomotion Step** (Вместо старого Фаза 5.5: Affordance Resolution)
    *   `DriveVector` передается в `SteeringResolver`.
    *   `MotionIntegrator` обновляет `npc.position` и `npc.velocity` напрямую.
    *   Формируется `KinematicProfile` для фронтенда.

### ЭТАП 2: ФЕРОМОННАЯ ЛОГИКА И ПАМЯТЬ (Stigmergy & Imprints)

Добавление памяти пространства и стратегий выживания. NPC оставляет следы и учится на чужих.

*   **Фаза 0.25: Ecology Deformation (Среда помнит)**
    *   **Вызов:** После `Action` и `MotionIntegrator` (пространство меняется от движения).
    *   **Логика:** `EcologySubscriber` читает тип действия и скорость.
        *   `WALK (velocity > 2.0)` → `StateDeltas(domain=SPATIAL_TRACE, payload=TracePayload(movement_density=+0.01))`.
        *   `CAST_SHADOW` → `StateDeltas(domain=SPATIAL, payload=SpatialDeformPayload(target="mana_resonance", delta=-0.05))`.
        *   `KILL / INJURY` → `StateDeltas(domain=SPATIAL_TRACE, payload=TracePayload(safety_confidence=-0.3, taboo_strength=+0.2, emission_tag="blood"))`.
*   **Обновление SteeringResolver:** Резолвер начинает учитывать `SocialTraceField` (двигаться по вытоптанным тропам проще, избегать "проклятых" мест).

### ЭТАП 3: МОРФОЛОГИЧЕСКИЙ ДРЕЙФ И ЭВОЛЮЦИЯ (Morphological Drift)

Тело начинает адаптироваться к хроническому давлению среды. Пространство деформирует агента.

*   **Фаза 0.5: Morphological Drift (Тело эволюционирует)**
    *   **Условие:** Если `ClusterPressureField` имеет устойчивый градиент (например, `active.light_level < 0.3` долгое время).
    *   **Логика:** `MorphologicalDriftHandler` применяет микродельты к `BodySchema` всех NPC в кластере.
        *   `StateDeltas(domain=MORPHOLOGICAL, payload=MorphologicalPayload(tunnel_vision_delta=-0.001, mana_channel_drift=-0.001))`.
        *   Хронический страх снижает `max_velocity` и `braking_force` (тело становится суетливым, дерганым).

### ЭТАП 4: ПЛАСТИЧНОСТЬ МИРА (World Plasticity)

Динамическое изменение базовой геометрии через `DynamicAffordanceField.plasticity`. Следы становятся физическими препятствиями или проходами.

## IV. НЕИЗБЕЖНЫЙ МОСТ: ТОПОСЕМАНТИЧЕСКИЙ РЕЗОЛВЕР (L1 → L2 Рендер)

`x, y` неприкосновенны, потому что экран их требует. Но NPC мыслит аффордансами. Значит, между мозгом (L1) и экраном (L2) обязан стоять **переводчик**.

**Проблема:** `DecisionHub` выдает "Искать укрытие с высоким `can_conceal`". Фронтенд не понимает `can_conceal`. Фронтенд понимает `(x: 45, y: 120)`.

**Решение: Геометрический Резолвер** (Компонент внутри `SteeringResolver`).

1. `DecisionHub` формирует `DriveVector` (направление) и `AffordanceFilter` (условия: `can_conceal > 0.8`).
2. `SteeringResolver` сканирует `DynamicAffordanceField` вокруг NPC.
3. Найденная ячейка, удовлетворяющая аффордансу, становится `аттрактором` — генерирует силу притяжения для `DriveVector`.
4. `MotionIntegrator` физически тянет NPC к этой координате.

## V. Критерии Приемки (Тест "Убегающая Девушка")

Сценарий реализуется **без единой строки скрипта**.

1. **Старт:** Преследователь в кластере. `SocialTraceField.safety_confidence` падает. `DriveSystem.survival = 1.0`.
2. **Ускорение:** Тело свежее `max_velocity=4.0`, `stamina=1.0`. `KinematicProfile: velocity=(0, 4.0), posture=UPRIGHT`. Инерция разгона занимает 0.5 сек.
3. **Ящики:** `can_vault=0.5`, `BodySchema.vault=0.8`. Разрешено. `KinematicProfile: vertical_velocity=+3.0, posture=VAULTING`.
4. **Усталость:** `stamina` падает до 0.4. `vault_cap` падает до `0.4`. Бег замедляется `velocity=2.5`. Девушка тяжело дышит (`exertion_level=0.8`).
5. **Поворот:** Впереди стена (`can_pass=0.0`). `SteeringResolver` генерирует боковую силу. Девушка не врезается, а "скользит" вдоль стены, теряя скорость на торможение (`braking_force`).
6. **Карниз:** `can_climb=0.3`, `climb_cap=0.3`. Погранично. `Drive(survival=1.0)` заставляет сканировать. Разрешено. `posture=CLIMBING`.
7. **Укрытие:** `can_conceal=0.9`. `KinematicProfile: posture=PRONE, velocity=crawl`.
8. **Магия:** `mana_resonance=-0.4`, `BodySchema.mana_channel=-0.8`. Резонанс. Восстановление маны.
9. **Контратака:** `Drive(autonomy)` + Мана. `posture=CROUCHED`, выстрел Тьмой.
10. **Побег:** Переулок `light_level=0.1`, `mana_resonance=-0.9`. `Affordance: Merge_With_Darkness`. `posture=CROUCHED, visual_distortion=high`.

## VI. Интеграционные риски и вопросы (Для реализации)

1. **Разрешение Поля:** Вычислять `AffordanceVector` для каждой (x,y) каждый тик — смерть CPU. Статичное поле рассчитывается при загрузке. Динамическое — через диффузию (раз в N тиков). `SteeringResolver` делает локальные запросы только в радиусе 2-3 метров от NPC.
2. **Фронтенд:** Нет 3D скелета. `SpriteCompiler` собирает позу из слоев (База + Эмоция + Эффект). "Прыжок" = смазанный спрайт + `vertical_velocity`. "Торможение" = наклон назад + пыль.
3. **Spatial Memory:** `SurvivalImprint` требует добавления `SpatialMemory` в `LivingNPC`. Запоминание стратегий, а не координат.
4. **Физика скольжения:** При `surface_grip < 0.5` (лед) `MotionIntegrator` должен сохранять инерцию движения даже при отсутствии `DriveVector` (NPC скользит мимо точки остановки).
