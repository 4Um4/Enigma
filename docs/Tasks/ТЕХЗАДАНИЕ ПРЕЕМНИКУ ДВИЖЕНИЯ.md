## 0. АРХИТЕКТУРНЫЙ ВЕКТОР

ENIGMA перешла от симуляции реакций к **симуляции доступности реальности**.

**Установленные инварианты:**
- `BODY_STATE_DISABLED` — sentinel состояние для NPC без тела (NPIC).
- Тело определяет **возможность** когнитивного парсинга, а не модулирует результат.
- `location_id` — инфраструктура загрузки, не онтология мира.
- `adjacency` — связи между чанками для будущей сшивки навигационных графов.
- **Каноническая цель движения — не координата и не узел, а Semantic Target.**

## 1. ЧТО СДЕЛАНО В S76

### 1.1 P0: ДОЛГ 5 ЗАКРЫТ — Приказ сквозь Боль (ADR-O-139)
**Root Cause:** `DirectiveInterpretationSubscriber` имел два разрыва:
1. Fallback без `body_state` создавал "логических призраков" (NPC с социальной массой, но без физики).
2. Проверка `shock` стояла ПОСЛЕ семантического парсинга (тело модулировало результат, а не доступность).

**Фикс (четыре слоя):**

**Слой 1 — NPIC Gate (directive_interpretation_subscriber.py):**
- Убит fallback `{"social_stats": {"fear_of_player": 0.1}}`.
- Добавлена проверка `_body.get("disabled")` — sentinel состояние блокирует интерпретацию.
- Somatic Interpretation Gate перемещён ВВЕРХ: тело проверяется ДО семантического парсинга.

**Слой 2 — Sentinel State (npc_state.py):**
- Добавлена константа `BODY_STATE_DISABLED` — явное состояние инертной материи.
- Отсутствие данных ≠ нейтральное состояние (§ENIGMA-003).

**Слой 3 — Normalization Gate (tick_orchestrator.py):**
- Перед использованием `ctx.all_npcs_raw` все NPC без `body_state` получают `BODY_STATE_DISABLED`.
- Устранён State Starvation Collapse при холодном старте.

**Слой 4 — Full Veto в pressure_translator.py:**
- `if not body_state` → `constraints[action] = 0.0` для всех физических действий.
- Нет тела = нет действий (а не "нулевое влияние").

### 1.2 P0: БАГ U — КОРЕНЬ НАЙДЕН (room_2)
**Root Cause:** `room_2` в `tavern.json` (x=2, y=2, w=16, h=10) полностью поглощала `room_0` и `room_1`. `graph_compiler` фильтровал контейнеры, но топология уже была сломана — NPC не мог навигировать.
**Источник:** Редактор автоматически создаёт комнату при рисовании стен (`_try_auto_room`). Удаление `room_2` из JSON — обязательно.

### 1.3 P1: Map Editor — три фикса
1. **Shift+ЛКМ** — перетаскивание локаций на карте мира (смещение `origin`).
2. **"Удалить локацию"** — диалог удаления текущего JSON из кампании.
3. **Outdoor поддержка** — объекты, NPC и надписи разрешены вне комнат для `is_outdoor=true`.

### 1.4 P1: Новые карты (как чанки, не уровни)
- `city_gate.json` — 4 навигационных узла, `is_outdoor=true`, `rooms=[]`
- `market_square.json` — 4 навигационных узла, `is_outdoor=true`, `rooms=[]`
- Обе содержат `adjacency` для будущей сшивки графов.
- `tavern.json` обогащён `adjacency`.

## 2. ЧЕТЫРЕ ОТКРЫТИЯ S77 (Археология ДОЛГ 6)

Археология показала, что проблема World Partition — только поверхностный симптом. Настоящий вопрос:

> **Что является канонической целью движения в ENIGMA?**

### Открытие 1: Location ≠ Room

Локация является **чанком сериализации и подзагрузки**.

Комната является **внутренней топологической структурой чанка**.

Эти сущности не должны автоматически порождать друг друга.

**Доказательство:**
- `data_manager.py:530` — `create_location()` автоматически пишет `player_spawn` и `rooms`
- `city_gate.json` уже доказал, что `rooms=[]` — валидное состояние
- `_try_auto_room` в редакторе создаёт комнату при рисовании стен — это источник БАГ U (room_2)

**Следствие:** `create_location()` должен создавать `{"rooms": []}` и только это. Комнаты появляются только когда пользователь рисует стены.

---

### Открытие 2: Каноническая цель движения не может быть координатой

Игрок мыслит:
- «к Люсе»
- «в таверну»
- «в город»
- «туда, где безопасно»
- «туда, где был волк»

Ни одно из этих намерений не является координатой или узлом навигационного графа.

**Следствие:** Конечным входом движения должен быть **Semantic Target** — типизированная смысловая цель, которая резолвится в пространственную цель через слой знаний.

**Отвергнутые модели:**
- **Node-Centric:** Игрок никогда не мыслит узлами.
- **Coordinate-Centric:** Координаты — внутренний механизм движка.
- **Entity-Centric:** Лучше, но не покрывает «где безопасно», «ближайшая таверна», «туда где был волк».

---

### Открытие 3: Навигация должна иметь три слоя

```text
Semantic Layer          ← «куда я хочу?» (Semantic Target)
       ↓
Spatial Layer           ← «как туда добраться?» (Spatial Goal + Boundary Nodes)
       ↓
Traversal Layer         ← «как физически двигаться?» (Pathfinding + MovementEngine)
```

Каждый слой имеет свою ответственность:
- **Semantic Layer** — резолвит смысл в пространственную цель. Зависит от знаний и убеждений агента.
- **Spatial Layer** — резолвит пространственную цель в маршрут. Зависит от графа и топологии.
- **Traversal Layer** — исполняет маршрут физически. Зависит от тела и локомоции.

**Ключевое свойство:** Слои независимы. Semantic Layer может ошибаться (знать устаревшее). Spatial Layer может не найти путь (граф разорван). Traversal Layer может не смочь (тело ранено).

---

### Открытие 4: World Knowledge Graph ещё не существует, но уже требуется двумя доменами

**Домен 1 — Player Intent Resolution:**
```text
Игрок: "иди в таверну"
      ↓
IntentCompressor → ActionType.MOVE, target_reference="таверна"
      ↓
Target Reference Resolver → ??? (не может найти локацию по смыслу)
```

**Домен 2 — NPC Strategic Movement:**
```text
NPC: threat_gradient=0.7
      ↓
DecisionHub → FLEE
      ↓
MovementEngine → get_furthest() → ??? (бежит наугад, не к известному безопасному месту)
```

Оба страдают от одной проблемы: **нет представления субъективного знания о мире**.

По §ENIGMA-002 (Правило Двух Доменов) — гипотеза World Knowledge Graph считается подтверждённой.

## 3. РЕКЛАССИФИКАЦИЯ ДОЛГ 6

Первоначально ДОЛГ 6 формулировался как «World Partition» — сшивка JSON-чанков в единый граф.

Археология показала, что это **транспортный слой** более глубокой проблемы.

**Новая классификация:**

```text
ДОЛГ 6 (World Partition) → реклассифицирован в ДОЛГ 6.1 и ДОЛГ 6.2
```

### ДОЛГ 6.1: Semantic Navigation Architecture ⚠️ НОВЫЙ — СТРАТЕГИЧЕСКИЙ
**Приоритет:** СТРАТЕГИЧЕСКИЙ (определяет форму всего движения в мире).
**Статус:** Фаза исследования. ADR отложен до завершения.
**Область исследования:**
- Semantic Target — типизированная смысловая цель движения
- Semantic Resolver — резолюция смысла в пространственную цель
- World Knowledge Graph — граф знаний и убеждений (не навигации!)
- Subjective Geography — «Known World ≠ Physical World»
- Memory References — «туда, где был волк»
- Cross-Chunk Navigation — Boundary Nodes + Causal Sync Point

**Критическое разделение:**
```text
Physical World (SpatialService)     ← как мир устроен на самом деле
       ≠
Known World (World Knowledge Graph) ← как агент думает, что мир устроен
```

### ДОЛГ 6.2: Chunk Architecture ⚠️ ПОДЗАДАЧА 6.1
**Приоритет:** ВЫСОКИЙ (транспортный слой для 6.1).
**Статус:** Готов к прототипированию. Данные подготовлены.
**Область:**
- Boundary Nodes — виртуальные узлы на границах чанков
- Graph Stitching — сшивка через `adjacency` в `graph_compiler`
- Seamless Transition — координатный переход (замена door_transition)
- Causal Synchronization Point — глубокий просчёт при подходе к чанку

## 4. ПОЧЕМУ ADR-O-144 ОТЛОЖЕН

ADR фиксирует архитектурное решение, которое уже прошло фазу исследования.

Мы находимся на этапе **открытия пространства решений**.

ADR отвечает: «Как мы решили делать?»
ТЕХЗАДАНИЕ отвечает: «Что нам предстоит понять, проверить и доказать?»

Сейчас мы во втором состоянии. Преждевременный ADR = архитектурный долг с процентами.

**Условие выпуска ADR-O-144:** Завершение исследования ДОЛГ 6.1 + первый рабочий прототип Semantic Target.

## 9. НАВИГАЦИОННАЯ МОДЕЛЬ (Текущая → Целевая)

**Текущая:**
```text
Локация = замкнутый мир
Переход = door_transition (телепорт)
NPC заперт в location_id
Цель движения = координата или узел
```

**Целевая (Semantic Navigation Architecture):**
```text
Цель движения = Semantic Target (смысл)
       ↓
Semantic Resolver (знания + убеждения агента)
       ↓
Spatial Goal (пространственная цель)
       ↓
Chunk Graph + Boundary Nodes (топология)
       ↓
Pathfinding (маршрут)
       ↓
MovementEngine (физическое движение)
```

**Критическое разделение:**
```text
Physical World (SpatialService)     ← как мир устроен
       ≠
Known World (World Knowledge Graph) ← как агент думает, что мир устроен
```

**DRF (Dynamic Recompression Field) — Текущее состояние:**
```text
Слой 1 (ДОЛГ 4.2 ✅): Аддитивный скоринг
Слой 2 (ДОЛГ 4.3 ✅): Viability Pre-Generation Gate
Слой 3 (ДОЛГ 4.4 ⚠️): Vector Conflict — не реализован
```

**NPIC (NPC Physical Integrity Contract) — Внедрён:**
```text
Слой 1: Sentinel State (BODY_STATE_DISABLED)
Слой 2: Normalization Gate (tick_orchestrator)
Слой 3: Somatic Gating (directive_interpretation_subscriber)
Слой 4: Full Veto (pressure_translator)
```

### graph_compiler — текущее состояние:

- `container_ids` фильтрация — удаляет чёрные дыры типа room_2

### scene_state_manager — текущее состояние:

- `SceneChange.target_location_id` — бэкенд уже поддерживает переход NPC между локациями
- `campaign_id` инжектируется в scene_state (ADR-102)

### Структура данных adjacency:
```json
"adjacency": {
  "east": "city_gate",
  "south": "market_square"
}
```
Это **декларативная карта соседства**. НЕ содержит: граничных узлов, координатного шва, направления перехода.

### Структура данных nodes (city_gate — целевая модель):
```json
"nodes": {
  "gate_road":     {"x": 5.0,  "y": 10.0, "connections": ["gate_arch"]},
  "gate_arch":     {"x": 11.5, "y": 10.0, "connections": ["gate_road", "guard_post", "gate_courtyard"]},
  "guard_post":    {"x": 16.0, "y": 3.5,  "connections": ["gate_arch"]},
  "gate_courtyard":{"x": 21.5, "y": 13.5, "connections": [...]}
}
```
`rooms=[]`, `is_outdoor=true` — чанк без комнат, только навигационные узлы.
