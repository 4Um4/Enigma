## 0. АРХИТЕКТУРНЫЙ ВЕКТОР (Долгосрочное видение)

Это НЕ задача текущего спринта. Это компас для всех будущих решений.

### Cognitive-Causal Combat & Interaction Model

ENIGMA строит не RPG-бой и не скриптованный нарратив, а **когнитивно-каузальную симуляцию взаимодействий**. Ключевые принципы:

**1. Любое действие проходит 4 стадии (Commitment Pipeline):**
```
Intent Formation → Commitment Window → Execution Point → Consequence Resolution
```
- `Commitment Window` — NPC меняет позу, сокращает дистанцию, достаёт нож. Действие ещё прерываемо.
- `Execution Point` — точка необратимости. После — rollback запрещён.
- Каждое действие имеет: `windup`, `execution_time`, `recovery`. NPC не может spam-attack из-за `recovery`.

**2. Direct MOVE убит полностью (цель).**
Вместо `MOVE command` — `Social Stimulus`:
```
PLAYER_SPOKE(semantic="summon", target="shadow")
→ legitimacy → emotional_impact → pressure_field
→ intent_formation → traversal → speech
```
Речь — ПОСЛЕ физики, не до. Speech is part of embodiment.

**3. Elastic Time во время ввода игрока:**
- Мир не замирает пока игрок пишет
- Tactical dilation: скорость мира снижена, commitment windows растянуты
- Игрок успевает ввести "я закрываюсь стулом" и это реально влияет на `hesitation`, `disgust`, `shock` у NPC

**4. Конкурентные процессы (не линейная очередь):**
Движение, речь, страх, атака, реакция, поза, дистанция, внимание — **конкурируют** одновременно, не выстраиваются в очередь.

**5. Traversal — interruptible:**
```
approach → увидел кровь → остановился → передумал
```
Должно быть возможно через pressure-check на каждом шаге traversal.

**Почему это важно:** Без этого fear/trust/willpower — декоративны. NPC либо телепортируется, либо игнорирует игрока. С этим — мир думает, а не исполняет скрипты.

**ADR который нужно написать перед реализацией:** `ADR-059: Commitment Pipeline & Interruptible Traversal`

## 1. ЧТО СДЕЛАНО (Текущая сессия)

1. **Рефакторинг MovementEngine (Sourcery compliance):**
   - Метод `process_intents` разбит на `_resolve_spatial_service`, `_process_single_intent`, `_resolve_micro_movement`, `_resolve_macro_relocation`.
   - Сложность снижена, тесты проходят стабильно (37/37).

2. **БАГ A (Root Cause 1): UTF-8 BOM в `inn_rooms.json`:**
   - Файл имел BOM (`EF BB BF`), `json.loads("utf-8")` выбрасывал `JSONDecodeError`, `try/except` молча проглатывал файл.
   - **Фикс:** В `graph_compiler.py:227` кодировка заменена на `utf-8-sig`, которая корректно обрабатывает BOM.

3. **БАГ A (Root Cause 2): Дубликат ключа `location_id` в `tavern.json`:**
   - Строка 3: `"location_id": "tavern_silver_wolf"`, строка 1248: `"location_id": ""`.
   - Python парсер брал последнее значение (`""`), что включало fallback-условие `if data.get("nodes") and not lid` → таверна подменяла `inn_rooms`.
   - **Фикс:** Удалён дубль `location_id: ""` из `tavern.json`.

4. **БАГ A (Root Cause 3): Опасный fallback в `load_editor_json`:**
   - **Фикс:** Удалено условие `if data.get("nodes") and not lid: return data`. Теперь файл без `location_id` не может стать источником графа для произвольной локации.

5. **БАГ F (Player as NPC): ЗАКРЫТ:**
   - **Фикс:** В `world_snapshot_builder.py` добавлен `if npc_id == "player": continue`.

6. **Кросс-локационное перемещение (ADR-060):**
   - В `SceneChange` добавлено поле `target_location_id: str = ""`. `MovementEngine` передаёт `location_id` из `MovementIntent`. `SceneStateManager` собирает `SpatialService` для целевой локации.

7. **LOD1 Macro-jitter (БАГ E - частичный фикс):**
   - В `scene_state_manager.py` добавлен `random.uniform(-0.4, 0.4)` для макро-узлов.

8. **БАГ G: Первый idle_tick без интентов — ЗАКРЫТ:**
   - **Root Cause 1:** `LifeEngine.get_npc_states()` возвращал `([], [])` (кортеж) вместо `[]` (список) при пустом кэше. Оркестратор получал кортеж из двух пустых списков вместо NPC-диктов.
   - **Root Cause 2:** `idle_tick()` вызывал `get_scene_state()` напрямую вместо `ensure_scene_initialized()`, пропуская инициализацию сцены.
   - **Фикс G-1:** `return []` вместо `return [], []`.
   - **Фикс G-2:** `idle_tick()` теперь вызывает `ensure_scene_initialized(self, campaign_id)`.

9. **БАГ H: Время сбрасывается при диалоге — ЗАКРЫТ:**
   - **Root Cause:** При `scene_state is None` (реинициализация сцены), время сбрасывалось к дефолту "07:00". Абсолютное `game_time_seconds` из `shared_context` не сохранялось.
   - **Фикс:** Перед `get_scene_state()` сохраняется `_preserved_game_time` из `shared_context`. При создании новой сцены время наследуется.

10. **БАГ I: NPC исчезают/0,0 при смене локации — ЗАКРЫТ:**
    - **Root Cause 1:** `_extract_npc_positions` не фильтровал NPC по локации.
    - **Root Cause 2:** `apply_changes` ставил `entry["location"]` но не `entry["location_id"]` — рассинхрон ключей.
    - **Фикс I-1:** Добавлена фильтрация `npc_loc != current_location → continue`.
    - **Фикс I-2:** Унификация `entry["location_id"] = target_loc` рядом с `entry["location"]`.

11. **ДОЛГ 2: DecisionHub даёт 0 решений — ЗАКРЫТ:**
    - **Root Cause:** `tick_decisions()` передавал `EventType.IDLE` вместо `EventType.WORLD_TICK`. Это убивало все PROACTIVE_INTENTS и подавляло давление (decay вместо аккумуляции). За 18 тиков — 0 решений.
    - **Фикс:** `EventContext(event_type=EventType.WORLD_TICK, ...)`. Теперь NPC генерируют проактивные интенты в idle tick.

12. **Sourcery: Рефакторинг `scene_init.py`:**
    - Сложность снижена с 48 до ~6 на функцию.
    - `init_scene_state` разрезан на 11 подфункций: `_resolve_initial_time`, `_extract_preserved_time`, `_materialize_npc_inventory`, `_update_player_position`, `_sync_game_time`, `_inject_spatial_service`, `_reconcile_elapsed_time`, `_apply_life_changes`, `_run_life_engine_tick`, `_check_economy_tracker`, `_load_or_create_scene`.

13. **Тесты: Обновление под новый контракт движения:**
    - `test_micro_macro_locomotion.py`: убрана проверка `target_node_id` (нет у `LocalSteeringGoal`).
    - `test_lod0_collision_avoidance.py`: `MovementIntent` заменён на `LocalSteeringGoal`.
    - Все 37 sandbox-тестов зелёные.

## 2. АКТИВНЫЕ БАГИ (Блокеры)

### БАГ D: NPC телепортируются вместо ходьбы ⛔ КРИТИЧЕСКИЙ
**Статус:** АКТИВНЫЙ. Единственный геймплейный блокер.

**Симптом:** Игрок говорит "Тень иди сюда" → NPC мгновенно оказывается у входа в таверну. Никакой анимации ходьбы. Все NPC телепортируются при любом перемещении.

**Pipeline-анализ:**
```
"Тень иди сюда"
→ DirectiveInterpretationSubscriber: pressure + initiative_suppression
→ DecisionHub: APPROACH intent (теперь работает после WORLD_TICK фикса)
→ _resolve_reactive_movement: MacroMovementGoal(target_node_id=???)
→ MovementEngine: SceneChange(field="position", value=target_node_id)
→ SceneStateManager: TraversalState создан → active_traversals
→ Frontend: _resolve_visual_xy() должен lerp'ать
```

**Подозреваемые места (нужна трассировка):**
1. **Точка А:** `_resolve_reactive_movement` для `approach` — какой `target_node_id` он выбирает? Если `entrance` — почему не `position` игрока?
2. **Точка Б:** `TraversalState` — создаётся ли он вообще? Или позиция мутируется напрямую?
3. **Точка В:** `active_traversals` в `WorldSnapshotDTO` — пробрасывается ли на фронтенд?
4. **Точка Г:** Фронтенд `_resolve_visual_xy` — получает ли он traversals и lerp'ает ли?

**Ключевой вопрос:** После фикса WORLD_TICK — заработает ли APPROACH автоматически, или есть разрыв между "DecisionHub решил APPROACH" и "NPC физически пошёл"?

### Отсутствующие карты: `city_gate.json`, `market_square.json`
**Статус:** АКТИВНЫЙ. Блокирует перемещение `guard_borko` и `merchant_goran`.

## 3. АРХИТЕКТУРНЫЙ ДОЛГ

### ДОЛГ 1: Cognitive Causal Timing — Stale Cognition
**Приоритет:** ВЫСОКИЙ.

**Проблема:**
```
Tick N:   DirectiveInterpretationSubscriber создал pressure → delta_buffer
          DecisionHub НЕ видит этот delta (он в будущем commit)
Tick N+1: pressure применилась → но ситуация уже изменилась
```
NPC думают о реальности прошлого тика. Это не баг реализации — это онтологическая ошибка pipeline.

### ДОЛГ 3: `location_templates.json` vs Editor JSON — двойной источник истины
**Приоритет:** СРЕДНИЙ.

Нет единого правила "откуда брать узлы". Нужно зафиксировать: editor JSON = единственный источник.
