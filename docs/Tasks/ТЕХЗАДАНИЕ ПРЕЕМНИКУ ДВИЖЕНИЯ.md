**Статус:** Спринт 34 в процессе. БАГ C (WASD→DM) — ЗАКРЫТ. БАГ A/B (нули + телепортация) — НЕ ЗАКРЫТ, обнаружена новая root cause (см. раздел 2).

## 0. АРХИТЕКТУРНЫЙ ВЕКТОР (Долгосрочное видение)

Это НЕ задача текущего спринта. Это компас для всех будущих решений.

### Cognitive-Causal Combat & Interaction Model

ENIGMA строит не RPG-бой и не скриптованный нарратив, а **когнитивно-каузальную симуляцию взаимодействий**. Ключевые принципы:

**1. Любое действие проходит 4 стадии (Commitment Pipeline):**
```
Intent Formation → Commitment Window → Execution Point → Consequence Resolution
```
- `Commitment Window` — NPC меняет позу, сокращает дистанцию, достаёт нож. Действие ещё прерываемо.
- `Execution Point` — точка необратимости. После — rollback запрещён.
- Каждое действие имеет: `windup`, `execution_time`, `recovery`. NPC не может spam-attack из-за `recovery`.

**2. Direct MOVE убит полностью (цель).**
Вместо `MOVE command` — `Social Stimulus`:
```
PLAYER_SPOKE(semantic="summon", target="shadow")
→ legitimacy → emotional_impact → pressure_field
→ intent_formation → traversal → speech
```
Речь — ПОСЛЕ физики, не до. Speech is part of embodiment.

**3. Elastic Time во время ввода игрока:**
- Мир не замирает пока игрок пишет
- Tactical dilation: скорость мира снижена, commitment windows растянуты
- Игрок успевает ввести "я закрываюсь стулом" и это реально влияет на `hesitation`, `disgust`, `shock` у NPC

**4. Конкурентные процессы (не линейная очередь):**
Движение, речь, страх, атака, реакция, поза, дистанция, внимание — **конкурируют** одновременно, не выстраиваются в очередь.

**5. Traversal — interruptible:**
```
approach → увидел кровь → остановился → передумал
```
Должно быть возможно через pressure-check на каждом шаге traversal.

**Почему это важно:** Без этого fear/trust/willpower — декоративны. NPC либо телепортируется, либо игнорирует игрока. С этим — мир думает, а не исполняет скрипты.

**ADR который нужно написать перед реализацией:** `ADR-059: Commitment Pipeline & Interruptible Traversal`

## 2. АКТИВНЫЕ БАГИ (Спринт 34 — починить в первую очередь)

### БАГ A: NPC на нулевых координатах (x=None / x=0.0)
**Статус:** АКТИВНЫЙ. Блокирует симуляцию.

**Root Cause:**
`SpatialService.build_for_location()` вызывает `load_editor_json(campaign_id, location_id)`.
Для `inn_rooms` editor JSON **не существует** — есть только `tavern.json`.
`load_editor_json` возвращает `None` → `compile_graph(None, ...)` → пустой граф → `get_node("bed")` = None → `continue` в MovementEngine → SceneChange не создаётся → NPC остаётся на стартовых координатах (None или 0.0).

**Затронутые NPC:** все кто спят (`maid_lusya`, `thief_shadow`, `tavern_keeper_tornin`, `merchant_goran`, `guard_borko`) — у всех `activity_map.sleeping.position = "bed"`, `location = "inn_rooms"`.

**Правильное решение (не ручной ввод координат):**
Создать `inn_rooms.json` в map_editor для кампании, **используя Map Editor** — это задача геймдизайнера/редактора карт. Редактор сам сгенерирует JSON с узлами и координатами.

Альтернатива (временная): добавить секцию `"positions"` в `location_templates.json` для `inn_rooms` — но это ручной хардкод, который нарушает принцип "editor JSON = источник истины".

**Файлы:**
- `backend/app/services/spatial/spatial_service.py:55` — `load_editor_json(campaign_id, location_id)`
- `backend/app/services/spatial/graph_compiler.py` — `load_editor_json()`
- `frontend/map_editor/campaigns/Open_road/locations/` — здесь должен появиться `inn_rooms.json`

**Как проверить после фикса:**
```
[TRACE][ENGINE_RECEIVED] npc=maid_lusya reason=schedule:sleeping local_xy=None
[TRACE][SCENE_CHANGE_CREATED] npc=maid_lusya x=3.0 y=3.0   ← должно появиться
[TRACE][SNAPSHOT] npc=maid_lusya x=3.0 y=3.0               ← не None
```

### БАГ C: WASD вызывает DM — нарратив на движение игрока
**Статус:** АКТИВНЫЙ. Архитектурное нарушение.

**Симптом:** Игрок нажимает WASD → фронтенд отправляет `action_queue.submit("идти восток")` → бэкенд запускает полный pipeline включая DM → LLM генерирует нарратив на "идти восток".

**Root Cause:**
`game_screen.py:517`: `action_queue.submit(campaign_folder, player_name, f"идти {dir_name}", px, py)`
После этого в `tick_orchestrator.py:594` бэкенд логирует `"Treating as player spatial action"` но **нет `return`** — pipeline продолжается и DM вызывается безусловно в `_phase_8_player_handlers`.

**Правильное решение:** Движение игрока по сторонам света — локальная физика фронтенда. Оно НЕ должно вызывать DM. Два варианта:
1. **Фронтенд:** убрать `action_queue.submit` для WASD-направлений. Только `_set_player_xy()` локально, без бэкенда.
2. **Бэкенд:** после строки 594 добавить флаг `ctx.suppress_dm = True` и проверять его в `_phase_8_player_handlers`.

**Вариант 1 предпочтительнее** (меньше изменений, правильная архитектура — бэкенд не должен знать о нажатиях WASD).

**Файлы:**
- `frontend/game_screen.py:493-521` — WASD-блок, строка 517 — submit
- `backend/app/services/tick_orchestrator.py:593-622` — player turn pipeline

**Побочный эффект текущего состояния:** `[TICK_DECISIONS] end: 0 decisions, 0 intents` — DecisionHub не выдаёт решений. Причина может быть связана с этим же: NPC получают "стимулы" от WASD-событий, но их когниция не готова к таким inputs.

## 3. АРХИТЕКТУРНЫЙ ДОЛГ (Не блокируют сейчас, но накапливаются)

### ДОЛГ 1: Cognitive Causal Timing — Stale Cognition
**Приоритет:** ВЫСОКИЙ. Объясняет почему NPC "игнорируют" игрока.

**Проблема:**
```
Tick N:   DirectiveInterpretationSubscriber создал pressure → delta_buffer
          DecisionHub НЕ видит этот delta (он в будущем commit)
Tick N+1: pressure применилась → но ситуация уже изменилась
```
NPC думают о реальности прошлого тика. Это не баг реализации — это онтологическая ошибка pipeline.

**Правильная архитектура (требует отдельного спринта):**
```
Phase 2: EventBus
→ Pressure Resolution
→ Perceptual Kernel Mutation (uncommitted overlay)
→ Decision Snapshot Rebuild с overlay
→ Phase 5: DecisionHub (видит текущий тик)
→ Phase 8: Physicalization
→ Phase 10: Commit
```

Ключевой паттерн — **Cognitive Overlay Layer:**
```python
decision_ctx = build_decision_context(
    snapshot_t,
    delta_overlay=current_tick_deltas  # uncommitted, только для Decision
)
```
DecisionHub видит `snapshot_t + cognitive_deltas` но мир ещё не мутирован. Детерминизм сохранён.

**Почему это важно:** Без этого fear, trust, willpower, irritation — декоративны. NPC реагирует на прошлое.

**Файлы для будущего аудита:**
- `backend/app/services/tick_orchestrator.py` — фазы 2, 5, 8, 10
- `backend/app/services/npc/decision_hub.py` — как строится decision context
- `backend/app/services/social/directive_interpretation_subscriber.py` — delta_buffer

---

### ДОЛГ 2: WASD как Semantic Bridge — Bypass Cognition
**Приоритет:** ВЫСОКИЙ (связан с БАГ C).

**Проблема:** Текущая архитектура:
```
PLAYER_SPOKE "Подойди сюда" → MOVE → MovementIntent → Traversal
```
Это disguised scripting, не симуляция. Правильный контур:
```
PLAYER_SPOKE → semantic_stimulus → social_legitimacy → emotional_reaction →
perceptual_pressure → DecisionHub → goal_formation → movement_desire → traversal
```
EventBus должен переносить `meaning` (disturbances, stimuli), но НЕ `imperative locomotion`.

**Связанные ADR:** CAUSAL_CONTRACT.md — §3 "Запрещённые паттерны", пункт 2: "SceneChange как триггер".

### ДОЛГ 3: `location_templates.json` vs Editor JSON — двойной источник истины
**Приоритет:** СРЕДНИЙ.

`city_gate` имеет `"positions"` в `location_templates.json`. Tavern имеет editor JSON. `inn_rooms` — нигде. Нет единого правила "откуда брать узлы". Нужно:

2. Убрать `"positions"` из `location_templates.json` (или пометить `@deprecated`).
3. Создать все локации в Map Editor.

## КРИТИЧЕСКОЕ ОТКРЫТИЕ СПРИНТА 34 (прочитать первым)

### Реальная root cause БАГ A/B: `load_editor_json` не фильтрует по `location_id`

**Симптом:** `load_editor_json('Open_road', 'inn_rooms')` возвращает узлы таверны (`entrance`, `main_hall`, `bar_area`...), а не `inn_rooms`.

**Root cause:**
`graph_compiler.py:225` делает `loc_dir.glob("*.json")` и перебирает **все** JSON в папке `locations/`. Он ищет файл у которого внутри есть `"nodes"` — и находит `tavern.json` первым (алфавитный порядок: `i` > `t`... нет, `i` < `t`, но `inn_rooms.json` создан после). Фактически функция не проверяет `location_id` внутри файла — берёт первый подходящий.

**Проверить строки 220-242 `graph_compiler.py`:**
```powershell
Get-Content "backend\app\services\spatial\graph_compiler.py" | Select-Object -Index (200..245) | ForEach-Object -Begin {$i=201} -Process {"$i`: $_"; $i++}
```

**Правильный фикс:** В `load_editor_json` добавить проверку `data.get("location_id") == location_id` при переборе файлов. Тогда `inn_rooms.json` с `"location_id": "inn_rooms"` будет найден корректно.

**Файл для патча:** `backend/app/services/spatial/graph_compiler.py`, функция `load_editor_json`, строки ~225-240.

**БЫЛО (предположительно):**
```python
for json_file in loc_dir.glob("*.json"):
    data = json.loads(json_file.read_text(encoding="utf-8"))
    if data.get("nodes"):  # берёт первый файл с nodes
        return data
```

**СТАЛО:**
```python
for json_file in loc_dir.glob("*.json"):
    data = json.loads(json_file.read_text(encoding="utf-8"))
    if data.get("location_id") == location_id and data.get("nodes"):
        return data
```

4. **[АРХИТЕКТУРА] Синхронизация `map_editor` ↔ `data/`**

   - `load_editor_json` ищет в обоих (строки 218-219 graph_compiler.py)
   - Нужно зафиксировать в ADR: `map_editor/campaigns/` = единственный источник истины для карт
   - `backend/data/` = только runtime данные (saves, memory, campaign_state)
   - Создать ADR-059 перед реализацией


   🎯 ОБА ROOT CAUSE НАЙДЕНЫ!

1. inn_rooms.json имеет UTF-8 BOM
Байты ef bb bf — это BOM (Byte Order Mark). json.loads() с кодировкой utf-8 выбрасывает JSONDecodeError на BOM. Функция load_editor_json ловит это исключение и делает continue, полностью пропуская inn_rooms.json.

2. tavern.json удовлетворяет fallback-условию
Поскольку inn_rooms.json пропущен, цикл доходит до tavern.json. По какой-то причине location_id в нём читается как пустая строка (возможно, дубликат ключа в JSON). Срабатывает условие if data.get("nodes") and not lid: return data, и таверна возвращается как граф для inn_rooms!
