# ТЕХЗАДАНИЕ ПРЕЕМНИКУ (Спринт 19: WillpowerGate & Avatar Runtime)

**Дата обновления:** 11.05.2026  
**Текущий статус:** CFRM Layer 1 реализован. Игрок внедрен в симуляцию как Гибридная Сущность (npc_id="player"). UI перешел на frame-deterministic модель.  
**Архитектурный сдвиг:** Переход от "игрок-наблюдатель" к "игрок-аватар". Воля игрока фильтруется через психику аватара.

---

## I. ГЛОБАЛЬНАЯ АРХИТЕКТУРА

Система работает как конвейер (Tick Orchestrator), обрабатывающий 10 фаз за тик.
1. **Фазы 0-2:** Симуляция мира (LifeEngine, SpatialService) и ввод (EventBus).
2. **Фазы 3-7:** Когнитивный пайплайн NPC (Память → Топик → Решение → Событие).
3. **Фаза 8:** Каузальная редукция (Perception → Combat → Reaction → Social). Разделена на слои (Layered Reduction), чтобы физика (боль) предшествовала эмоциям (страх).
4. **Фазы 9-10:** Интеграция (CFRM Reducer) и Коммит (StateApplicator, SQLite).

**Доменная модель (DRSL):** Мутации состояния происходят ТОЛЬКО через `StateDeltas` с типизированными Payloads. Физиология — инерционная система (`PHYSICS_COMPOSITE`), социальность — алгебраическая (`ADDITIVE`).

---

## II. КРИТИЧЕСКИЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ (Законы)

1. **Player = Hybrid Consciousness Entity (ADR-030):** Игрок — это `npc_id="player"` в `all_npcs_raw`. Имеет `body_state` и `psyche`. Управление не прямое, а через `WillpowerGate`.
2. **CFRM (ADR-025/029):** Глобального объекта World нет. Мир = локальные причинные пузыри (кластеры). Восприятие ограничено мембранами.
3. **WillpowerGate:** Не булева проверка, а Dynamic Identity Preservation Engine. Аватар сопротивляется воле игрока, если действие разрушает его идентичность. Возвращает `WillResponseDTO` (RESISTED, DISSOCIATED, ADAPTED).
4. **Frame-Deterministic UI:** UI = pure function of input state. Никаких "залипаний" подсветки и состояния.

## III. ПРИОРИТЕТЫ СЛЕДУЮЩЕГО СПРИНТА (Спринт 19)

### Приоритет 0: Backend WillpowerGate & Intent Pipeline
**Проблема:** Фронтенд отправляет текст, бэкенд сразу генерирует `EventDTO`. Нет фильтрации через волю аватара.
**Задача:**
- Создать `WillpowerGate` (Pure Function). Сигнатура: `compute(player_snapshot: NPCStateSnapshot, intent: IntentDTO) -> WillResponseDTO`.
- Интегрировать в Фазу 1 (или между Фазой 1 и 2): если `WillResponseDTO.outcome == "RESISTED"`, событие не публикуется в шину, вместо этого публикуется событие `WILL_CONFLICT` (передается counter_offer).
- Если `outcome == "DISSOCIATED"`, действие выполняется, но `identity_damage > 0`, и генерируется травма.

### Приоритет 1: Frontend Avatar State Visualization
**Проблема:** Фронтенд не отображает физиологию и психику аватара.
**Задача:**
- Считывать `body_state` игрока из `world_snapshot` (pain, fatigue, blood_loss, consciousness).
- UI эффекты: при `pain > 50` — красная виньетка; `consciousness < 0.3` — помутнение (blur/alpha экрана).
- Отображение конфликта воли: при получении `WillResponseDTO(RESISTED)`, блокировать действие и показывать пузырь аватара ("Я не могу...").

### Приоритет 2: Perceptual Kernel & Fog of War
**Проблема:** Игрок слышит все события на карте (нарушение CFRM).
**Задача:**
- На бэкенде: фильтровать `WorldSnapshotDTO.visible_events` и `npc_reactions` на основе `ClusterOccupancy`. Игрок получает только факты из своего кластера + слухи (ослабленные мембраной).
- На фронтенде: скрыть NPC, которые находятся в других кластерах (если они не источают громкий звук/событие).

## IV. ИЗВЕСТНЫЕ АРХИТЕКТУРНЫЕ ПРОБЛЕМЫ (Баги и Долги)

1. **Teleportation vs Continuous Movement (ADR-0013):** NPC телепортируются в центр макро-зоны. `TraversalState` не реализован. Движение = state relocation.
2. **Micro-positioning:** `LocalSteeringIntent` не реализован. NPC не могут подойти к игроку ближе 1 метра внутри одной макро-зоны.
3. **Speaker Extraction:** Парсинг спикера из `dm_response` эвристический (ищет имя в начале строки). Бэкенд не разделяет нарратив по NPC.
4. **Avatar Affective Memory:** Память аватара (затухание эмоций, травмы) еще не отделена от памяти игрока формально в коде.

## V. КЛЮЧЕВЫЕ ФАЙЛЫ ПРОЕКТА

### Backend (Ядро симуляции)
- `backend/app/services/tick_orchestrator.py` — Сердце тика. 10 фаз. _build_npc_snapshots, delta_buffer, aggregate_deltas.
- `backend/app/services/game_loop/__init__.py` — Оркестратор верхнего уровня. `_load_npcs_with_runtime()` — точка инъекции Аватара.
- `backend/app/services/combat/impact_engine.py` — Физика повреждений. Pure function.
- `backend/app/services/social/propagation.py` — Социальная физика (слухи).
- `backend/app/models/state_delta.py` — Контракты мутаций (DRSL, ReductionPolicy).
- `backend/app/models/cfrm.py` — Структуры CFRM (ClusterGraph, EventBuffer).

### Frontend (Призма восприятия)
- `frontend/game_screen.py` — Главный игровой цикл Pygame. Обработка ввода, состояние _MoveState, рендер.
- `frontend/character_select.py` — Генератор Вектора Начальных Условий (Архетип + Темперамент).
- `frontend/scene_renderer.py` — Compositing pipeline (Lerp, индикаторы внимания, спрайты).
- `frontend/narrative_renderer.py` — Cinematic Layer (пузыри, DeliveryType, фейд-аут).

### Документация (Карта памяти)
- `АРХИТЕКТУРНЫЙ_УСТАВ_ENIGMA.md` — Законы (нарушение = баг).
- `ADR (Architecture Decision Records).md` — ПОЧЕМУ приняты решения (до ADR-030).
- `DTO Registry (Реестр контрактов).md` — АКТУАЛЬНЫЕ контракты данных.
- `ARCHITECTURE_FLOW.md` — Топологическая карта Mermaid.

## VI. ФИЛОСОФИЯ ПРОЕКТА (От Мастера Тая)

Игрок не управляет марионеткой. Он предлагает волю аватару.
Если аватар сломлен — он адаптируется. Личность перестраивается под насилие.
Ценность системы не в садизме, а в сопротивлении причинности.
Игрок должен страдать от последствий, фрикции, вины и утраты контроля.
