### ТЕХЗАДАНИЕ ПРЕЕМНИКУ (Спринт 18: CFRM Foundation & Perception Prism)

**Текущий статус:** Базовый рендер работает. Пузыри и внимание NPC отрисовываются. Lerp стрелки игрока реализован.
**Архитектурный сдвиг:** Фронтенд больше не "отражает" мир. Он расщепляет его на слои истины. Map Editor больше не "рисует уровень". Он задает физические законы тайлов.

#### Приоритет 0: Map Editor TileDTO (Source of Truth)
**Проблема:** Сейчас тайлы — это картинка (`img`), а физика мира хардкодится или отсутствует. Это убивает CFRM (Causal Field Resolved Mapping), так как визуал диктует логику.
**Задача:** Внедрить двойной контракт в сериализацию Map Editor. Логика первична, визуал производен.
- Найти точку сериализации карты в `frontend/map_editor/` (обычно `editor.py`, `scene.py` или `serializer.py` — места `json.dump` / `save_map`).
- При сохранении перехватывать тайлы и обогащать их через `enrich_tile(tile)`, добавляя блоки `logic` и `visual` (если их нет).
- При загрузке нормализовать через `normalize_tile(tile)`, гарантируя наличие полей даже в старых картах.
- **Контракт TileDTO:**
  ```json
  {
    "tile_id": "tavern_wall_01",
    "pos_x": 10,
    "pos_y": 5,
    "logic": {
      "surface_type": "solid",
      "base_noise": 0.3,
      "base_friction": 0.8
    },
    "visual": {
      "material": "medieval_brick",
      "dirt": 0.4,
      "seed": 12345
    },
    "render_placeholder": "debug_wall.png"
  }
  ```
- **Критический запрет:** Поле `img` (или `render_placeholder`) НЕ является источником физики. `ImpactEngine` не знает о картинках.
- **Ключевые файлы для поиска:** `frontend/map_editor/editor.py`, `frontend/map_editor/serializer.py`.

#### Приоритет 1: DebugSurface API (Domain Layer)
**Проблема:** Будущая боевка и перемещение не могут запрашивать физические свойства у пикселей.
**Задача:** Создать заглушку среды, которая читает `TileDTO.logic`.
- Создать `backend/app/domain/surface.py` (Домен не знает сервисов!).
- Определить `Protocol Surface` с методами: `get_collision(x, y) -> float`, `get_noise(x, y) -> float`, `get_friction(x, y) -> float`.
- Создать `DebugSurface`, реализующий этот протокол и берущий данные из словаря `logic_data`.
- В будущем `SpatialService` будет возвращать `Surface` для координат, а `ImpactEngine` вызывать `surface.get_friction()` (например, мокрый пол = шанс падения).

#### Приоритет 2: Layered Rendering Engine (Подготовка базы)
**Проблема:** Рендер монолитен. Нельзя отделить физику от восприятия.
**Задача:** Начать разделение `SceneRenderer.render()` на независимые проходы (compositing pipeline).
- **Base Layer:** Геометрия, `SpatialService`, `PhysiologyPayload` (черно-белая/серая истина).
- **Membrane Layer:** Градиенты затухания событий (пока заглушка-heatmap).
- **Perception Layer:** Субъективный POV (искажения, fog of war).
- **Narrative Layer:** LLM-вербализация (текст/эффекты).
- Добавить в `SceneRenderer` флаги `self.debug_layers = {"base": True, "membrane": False, "perception": True, "narrative": True}` для независимого включения/выключения слоев.

#### Приоритет 3: Perception Mode Switcher (Debug Tool)
**Проблема:** Игрок и разработчик видят только один (свой) слой реальности.
**Задача:** Добавить UI-переключатель режимов восприятия (как DevTools).
- Клавиша `F1` циклично переключает `PerceptionMode`: `REALITY` (физика), `PLAYER_POV` (дефолт), `NPC_POV` (выбранный NPC), `RUMOR_FIELD` (тепловая карта слухов), `STRESS_FIELD` (напряжение).
- В режиме `NPC_POV` рендерер использует данные из `PerceivedScene` конкретного NPC (что он видит, что считает правдой, его слепые зоны).
- В режиме `RUMOR_FIELD` / `STRESS_FIELD` отрисовывать полупрозрачный overlay поверх `Base Layer` (цвет: красный для стресса, желтый для слухов, интенсивность по значению из `StateDeltas`/социального графа).

### Архитектурная Доктрина (Законы CFRM для Фронтенда)

1. **Фронтенд НЕ знает правду.** Он всегда получает проекцию: `truth_projection`, `perception_projection`, `narrative_projection`. Он обязан визуально различать их.
2. **Map Editor — Автор Физических Законов.** Тайл = набор констант (трение, шум, проходимость). Картинка — производная от этих законов.
3. **Каузальная Мембрана видима.** Распространение событий не абстрактно. Если событие затухает при переходе в другой кластер, Membrane Layer должен это показывать (fade-out, искажение).
