# ТЕХНИЧЕСКОЕ ЗАДАНИЕ ПРЕЕМНИКУ: Каузальная Физика Движения и Власти

## 1. Текущий статус архитектуры

Мы находимся на границе перехода от "RPG скриптов" к "Каузальной Симуляции". Архитектор А (Движение/География) пытался заставить NPC ходить через прямую мутацию `SceneChange`, что привело к телепортациям, прыгающим тикам и нарушению CFRM (обход шины событий). 

Архитектор Б (Воля) внедрил `WillpowerGate` и `IntentPressureProfile`, но они пока изолированы от пайплайна ввода.

Я (Архитектор С — Сжатие и Семантика) реализовал Слои 1 и 2, а также создал Физику Власти (Social Physics), чтобы связать речь игрока с волей NPC без прямых команд.

### Что уже работает:
1. **Слой 1 (Сжатие языка):** `IntentCompressor` использует `pymorphy3` для лемматизации русского языка. Извлекает `action_type` (MOVE, ATTACK) и `target_reference` ("тень").
2. **Слой 2 (Резолв цели):** `TargetReferenceResolver` через `difflib` связывает "тень" -> `thief_shadow`.
3. **Строгий DTO:** `IntentParametersDTO` (убита дыра `Dict[str, Any]`).
4. **Интеграция в EventBus:** В `publish_classified_player_event` проброшены `semantic_action`, `target_id`, `social_pressure`.
5. **Песочница Онтологии:** `backend/tests/sandbox/test_causal_movement.py` — 7 тестов, верифицирующих законы реальности (нет прямой мутации, давление — не команда).

## 2. Каузальный Контракт v1.1 (Исполняемый закон)

**Главное правило:** `SceneChange` — это РЕЗУЛЬТАТ локомоции, а не КОМАНДА на перемещение. Мир нельзя приказать изменить, можно только создать причины.

**Допустимый поток реальности:**
1. **Сжатие:** `Text -> IntentSemanticField (MOVE, target_ref, social_pressure)`.
2. **Деобъективация:** `Intent -> EventDTO -> FieldDisturbance (KINETIC, SOCIAL, BEHAVIORAL)`.
3. **Физика Власти (NEW):** `DirectiveInterpretationSubscriber` читает `FieldDisturbance` с `semantic_action`. Вычисляет *легитимность* и *цену отказа*. Генерирует `PsychologicalPressure(directive_obedience=0.8)` и `StateDeltas(Emotion, Social)`.
4. **Акт Воли:** `DecisionHub` (следующий тик) читает обновленный utility-space (высокий страх, давление подчинения) и *сам* решает сгенерировать `MovementGoal(target_entity="player")`.
5. **Локомоция:** `SpatialReasoner -> TraversalState (WorldRuntimeState) -> SpatialDelta -> State Mutation`.

**Запрещено:**
* Прямая мутация `npc["position"]`.
* Вызов `scene_manager.apply_changes()` из подписчиков.
* Генерация `MovementIntent` напрямую из приказа игрока (это aggro-controller).

## 3. Ключевые новые сущности

### `IntentParametersDTO` (backend/app/domain/intent.py)
Строгий контракт семантики, убивающий `Dict[str, Any]`.
```python
@dataclass(frozen=True)
class IntentParametersDTO:
    semantic_action: Optional[str] = None
    target_reference: Optional[str] = None
    target_id: Optional[str] = None # ID из Слоя 2
    physical_force: float = 0.1
    emotional_charge: float = 0.1
    social_pressure: float = 0.0
    commitment_level: float = 0.8
```

### `PsychologicalPressure` (backend/app/models/cfrm.py)
Добавлен вектор `directive_obedience` — давление подчинения речевому акту.
```python
@dataclass(frozen=True)
class PsychologicalPressure:
    fear: float = 0.0
    uncertainty: float = 0.0
    aggression_trigger: float = 0.0
    dominance_shift: float = 0.0
    directive_obedience: float = 0.0 # Физика власти
```

### `DirectiveInterpretationSubscriber` (backend/app/services/social/directive_interpretation_subscriber.py)
Трансформатор социальной воли. Не знает о движении. Искривляет utility-space цели через страх и подчинение.

## 4. Известные баги Продакшена (Зона Архитектора А)

1. **Тень не идет физически:** `DecisionHub` не имеет правила, читающего `directive_obedience` для генерации `MovementGoal`. Это следующая задача.
2. **`[DIRECT_REFLEX]` Bypass:** В продакшене висит опасный код, который пытается применить `SceneChange` напрямую в обход шины. Он должен быть удален.
3. **Прыгающие тики:** `[TICK_CATCHUP] applying=10` заставляет `LifeEngine` скачкообразно менять голод с 0.70 до 1.00, что ведет к телепортациям NPC к еде.
4. **Игрок не в кластере:** `Cannot generate SceneChange: player node not found`. Игрок не интегрирован в `ClusterOccupancy` как полноправный spatial node.

## 5. Приоритеты следующего спринта

1. **Интеграция DirectiveInterpretationSubscriber в TickOrchestrator:** Подключить его к Фазе 8 как полноправный обработчик каузальных событий.
2. **DecisionHub Utility Modulation:** Научить `DecisionHub` читать `directive_obedience` из эмоций/давления NPC и повышать скоринг `MovementGoal(approach_player)`.
3. **Убийство Direct Reflex:** Удалить обходные пути `SceneChange`.
4. **Починка TICK_CATCHUP:** Ограничить применение дельт голода/усталости внутри одного хода.

Да. ТЗ для приемника должно быть расширено. Текущая Песочница верифицирует Слои 1-3 (от текста до давления), но **обрывается** на самом важном этапе — превращении давления в решение. Преемник должен понимать, что Песочница — это не просто набор пройденных тестов, а инструмент для пошаговой сборки каузальной цепи.

### Дополнение к ТЗ: Песочница Каузальной Цепи (Causal Chain Debugger)

**Статус Песочницы:** 7/7 тестов проходят. Онтология Слоев 1-3 защищена. Обнаружена и верифицирована Физика Власти (`DirectiveInterpretationSubscriber`).

**Критический разрыв:** Давление (`directive_obedience`) генерируется, но **не потребляется** `DecisionHub`. Преемник должен использовать Песочницу для починки этого разрыва, добавляя тесты *до* написания продакшен-кода.

#### Следующие тесты, которые обязан написать преемник:

**1. Тест 8: Интеграция DirectiveInterpretation в Фазу 8 (EventBus -> Pressure)**
*   **Цель:** Убедиться, что `DirectiveInterpretationSubscriber` подключен к конвейеру оркестратора и читает события из шины, а не только вызывается вручную.
*   **Суть:** Опубликовать `EventDTO(PLAYER_SPOKE, semantic_action=MOVE)` в мокнутый `EventBus` оркестратора. Убедиться, что в `delta_buffer` появились дельты с `directive_obedience`.

**2. Тест 9: DecisionHub Utility Modulation (Давление -> Скоринг)**
*   **Цель:** Проверить, что `DecisionHub` (Фаза 5) реагирует на изменение utility-space.
*   **Суть:** 
    *   GIVEN: NPC `thief_shadow` имеет высокий `directive_obedience` (страх перед приказом) и базовый скоринг `approach_player = 0.1`.
    *   WHEN: `DecisionHub` вычисляет решения.
    *   EXPECT: Скоринг `approach_player` возрастает (например, до 0.7). `MovementGoal` сгенерирован, но `MovementIntent` ещё нет (требуется SpatialReasoner).

**3. Тест 10: Запрет DIRECT_REFLEX Bypass (Убийство легаси Архитектора А)**
*   **Цель:** Гарантировать, что старый обходной путь (`[DIRECT_REFLEX] Cannot generate SceneChange`) удален навсегда.
*   **Суть:** Инжектить событие с `semantic_action=MOVE` и проверять, что НИ В КОЕМ СЛУЧАЕ не вызывается `scene_manager.apply_changes()` или прямая мутация позиции. Тест должен падать при обнаружении вызова `SceneChange` до завершения `TraversalState`.

**4. Тест 11: TraversalState Materialization (Решение -> Локомоция -> Результат)**
*   **Цель:** Замкнуть цепь. `MovementGoal` конвертируется в пространственный факт.
*   **Суть:**
    *   GIVEN: `DecisionHub` вернул `MovementGoal(target_entity="player")`.
    *   WHEN: `SpatialReasoner` вычисляет узел, и `MovementEngine` начинает движение.
    *   EXPECT: Создан `TraversalState`. Позиция NPC *еще не изменилась*. Изменение позиции произойдет только когда `TraversalState` завершится и сгенерирует `SpatialDelta`.

### Главное правило для преемника:
Песочница — это не тест багов. Это **каузальный осциллограф**. Если вы хотите починить движение NPC, вы сначала пишете тест в `test_causal_movement.py`, который проваливается на нужном слое (например, "DecisionHub не видит давления"), и только потом пишете код `DecisionHub`.
