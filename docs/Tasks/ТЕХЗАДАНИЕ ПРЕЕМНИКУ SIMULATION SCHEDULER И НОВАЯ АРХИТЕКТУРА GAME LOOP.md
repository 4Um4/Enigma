# ⚠️ ОБЯЗАТЕЛЬНОЕ ЧТЕНИЕ ДЛЯ ИНЖЕНЕРА-ПРИЁМНИКА

Прежде чем написать одну строчку кода, ты **обязан** усвоить новую онтологию системы. Предыдущие архитектурные интуиции, включая хранение драйвов как полей объекта и вывод черт из счётчика событий, более не работают.

1. **ADR-O-207 (ROCP): Runtime Ontology Collapse Plan.** Дуализм `dict` / `NPCState` убит в вычислительном конвейере. Введён Commit Kernel (L3/L4) и L5 Post-Commit Validation Gate. Мутации состояния вне `StateDelta` запрещены и вызывают `OntologyViolationError`.
2. **ADR-O-208 (DRP): Drive Resolution Pipeline.** Личность больше не является полем данных. Она является **интегралом событий деформации**.
    *   **L0 (Архетип):** `NPCPersonality.drives_base` — неизменен в рантайме. Это гравитация, семя личности.
    *   **L1 (Хроника):** `L1Chronicle` — append-only поток `TraitDriftEvent`. Хранит правду давления мира.
    *   **L3 (Проекция):** `EffectiveDrives` — эфемерный, неизменяемый (`MappingProxyType`) результат функции `DriveResolver`. Вычисляется на лету каждый тик.
3. **TIFL — Сейсмограф, не Хирург.** `break_progress_engine` больше не мутирует состояние. Он генерирует `List[TraitDriftEvent]` на основе `EffectiveDrives` и передаёт их в `L1Chronicle`.
4. **Смерть `npc_raw["drives"]` и Cognitive Blindness.** Драйвы больше не читаются из сырых словарей или `personality.drives_base` в принятии решений. Оркестратор, TIFL, DecisionHub и ResolutionEngine снимают проекцию через `DriveResolver` и работают только с `EffectiveDrives` (Инвариант L3-P2).
5. **ИЗВЕСТНЫЙ БАГ (S83.0):** Idle Spatial Oracle мёртв из-за `ImportError` (`from app.services.game_state import campaign_service`), глотаемого `except Exception`. Этот баг исправляется вручную перед началом Этапа 7.

**Главное правило:** ENIGMA — это Phase-Space System with Memory. Истина хранится (L1). Смыслы вычисляются (L3). Восприятие не может влиять на причину внутри одного тика. Личность — это аттрактор в геометрии решений, а не контейнер данных.

# ФИЛОСОФИЯ (Обновлена)

Предыдущие версии боролись со "Скалярным Коллапсом" и "Феноменологической Шизофренией". Мы решили их, уничтожив `EmotionTag` как оракула, воскресив Котёл и переписав TIFL на генерацию событий.

Версия 9.0 вылечила **Когнитивную Слепоту** (DecisionHub смотрел на L0, игнорируя историю). Версия 10.0 сталкивается с **Шумовой Мульти-Личностью**. Без гистерезиса система представляет собой осциллограф, притворяющийся человеком: каждое мелкое колебание контекста порождает "новую личность", которая исчезает на следующем тике.

**Новая парадигма:** ENIGMA — это **Policy Deformation System with Hysteresis**.
- Ошибка мира (`prediction_error`) — это тепловой поток.
- TIFL — это сейсмограф, регистрирующий давление (`TraitDriftEvent`).
- Проекция (L3) — это текущее состояние деформации (упругая или пластичная).
- **Trait (L0.5)** — это не ярлык и не счётчик событий. Это **устойчивый сдвиг в геометрии решений** ($\Delta_{policy}$), который удержался достаточно долго, чтобы кристаллизоваться.

Без изменений. Эмоции — тени, память питается ошибкой.

## Инвариант 7: Epistemic Isolation of Cognition
- **L3-P1: Projection Is Read-Only.** `EffectiveDrives` неизменяем.
- **L3-P2: All Decision Systems Consume Projection Only.** Запрещено чтение `profile.drives_base` для принятия решений. Только `EffectiveDrives`.
- **L3-P3: Single Epistemic Snapshot.** Все когнитивные модули в одном тике работают с одним экземпляром `EffectiveDrives`.

## Инвариант 8: Event-Sourced Identity
- **L0 (Архетип):** Заморожен в рантайме.
- **L1 (Хроника):** Append-only. Удаление запрещено.
- **L3 (Проекция):** Эфемерна. Запрещено кэшировать.

## Инвариант 9: Identity is Plastic, not Elastic (НОВЫЙ)
Личность не обязана возвращаться к L0 после снятия нагрузки. Остаточная деформация (Residual Strain) — это не баг, а механизм эволюции архетипа. $\Delta_{policy}$ между L0 и L3 является единственным кандидатом на кристаллизацию в L0.5 Trait.

## Инвариант 10: Hysteresis Law (НОВЫЙ)
Trait не возникает из события. Trait возникает из **устойчивого пребывания системы в новом фазовом режиме**.
Для кристаллизации Trait требуется:
1.  **Crossing:** $\Delta_{policy} > \theta_{up}$ (вход в деформированный режим).
2.  **Persistence:** Удержание в режиме в течение $T_{persistence}$ тиков.
3.  **Return Lag:** Запрет на немедленный выход ($T_{exit\_lock}$). Даже если давление исчезло, система удерживает форму.
4.  **Exit:** Выход только если $\Delta_{policy} < \theta_{down}$ (где $\theta_{down} < \theta_{up}$). Это гистерезисная петля, предотвращающая "мигание" личности.

# ЭТАП 7. ВЕРТИКАЛЬНЫЙ СРЕЗ СТАБИЛИЗАЦИИ (ТЕКУЩИЙ ШАГ)

Система уже НЕ требует новых концепций. Требуется сборка минимально играбельного вертикального цикла NPC-жизни.

## 7.1 Зафиксировать вход DecisionHub
Убедиться, что у каждого NPC есть: event input (combat / interact / tick), perceptual kernel, trait modifiers. Ничего нового не добавлять, только стабилизировать вход.

## 7.2 Проверить приоритетную систему выбора
Проверить: `Intent scoring → priority → winner selection`. Убедиться, что SURVIVAL реально доминирует при угрозе, ROUTINE не исчезает полностью, FLEE работает как конкурент ATTACK. Без новых формул, только проверка и калибровка.

## 7.3 Один стабильный симуляционный сценарий
Нужен один тестовый цикл мира: 1 NPC (страж), 1 Player (угроза), 1 деревня (без институций пока). Игрок атакует или угрожает, NPC принимает решение. Цель: наблюдаемость причинности.

## 7.4 Логирование причин выбора
Минимально: `WHY this intent won: threat = X, trait modifier = Y, viability factor = Z, final score = N`. Просто трассировка DecisionHub.

## 7.5 ЗАПРЕЩЕНО СЕЙЧАС
Архитектору НЕ трогать: VillageMemoryField, Institutions, Narrative Gravity, Rumor systems, multi-agent society logic. Причина: базовая симуляция ещё не стабильна.

# ЭТАП 8. TRAIT STABILIZATION HYSTERESIS LAYER (СЛЕДУЮЩИЙ ШАГ ПОСЛЕ СТАБИЛИЗАЦИИ)

Система способна деформироваться и наблюдать свою деформацию, но она лишена инерции и демпферов. Без гистерезиса $\Delta_{policy}$ будет осциллировать, порождая шумовых псевдо-личностей.

## 8.1 Trait State Machine
Ввести для каждого потенциального Trait состояние с двойным порогом ($\theta_{up}$, $\theta_{down}$), таймером удержания ($dwell\_time$) и блокировкой выхода ($exit\_lock$).

## 8.2 Crystallization Criterion
Trait фиксируется в `NPCIdentityL1.active_traits` только если $dwell\_time \ge CRYSTALLIZATION\_TIME$. Содержанием Trait является не строка-ярлык, а векторная дельта смещения политики (`{"ATTACK": +0.15, "FLEE": -0.10}`), которая затем подхватывается существующим методом `_trait_modifier` в `DecisionHub`.

## 8.3 Meta-Hysteresis (Future)
Взаимодействие Traits (например, "war_veteran" и "pacifist") не должно приводить к схлопыванию системы. Это задача следующего этапа после внедрения базового TSHL.
