# ТЗ: ПРЕЕМНИКУ ФИЗИОЛОГИИ ЖИЗНИ (Сессия 66+)

## ТЕКУЩИЙ СТАТУС СИСТЕМЫ
**Vital State Pipeline ЗАМКНУТ (S66, ADR-123).**
`ImpactEngine → InjuryDTO → InjuryProcessor(+blood_loss/tick) → DeltaBuffer → StateApplicator → body_state["life_status"] → DecisionHub guard`.

Смерть = процесс, не событие. Между ударом и смертью — окно из нескольких тиков.
Кровотечение из ран — непрерывный процесс (InjuryProcessor), конкурирующий со свёртыванием (DecayHandler).
DecisionHub блокируется для DEAD/UNCONSCIOUS NPC.

**Оставшиеся проблемы:** Legacy dead-проверки в perception_filter/scene_state_manager,
отсутствие лечения, отсутствие CorpseState.

## КРИТИЧЕСКИЕ РАЗРЫВЫ (Приоритеты на исправление)

### 1. Legacy dead-проверки не читают life_status
- **Баг:** `perception_filter._npc_is_conscious()` читает `pos.get("state")` из `npc_positions`.
  `scene_state_manager:1779` и `world_state.py:103,154` проверяют `pos.get("state") == "dead"`.
  Но никто НЕ ПИШЕТ `state = "dead"` в `npc_positions` — эти проверки мёртвые ветки.
- **Требование:** Все проверки смерти/сознания должны читать `body_state["life_status"]`
  через `evaluate_vital_state()` / `is_conscious()`. Нужно понять, как body_state
  попадает в npc_positions (или не попадает) и создать правильный мост.
- **ADR:** ADR-123

### 2. combat_math.apply_damage — мёртвый код
- **Баг:** `combat_math.py:266-277` содержит `if hp <= 0: status = "dead"`.
  Никто не вызывает эту функцию (ImpactEngine заменил). Но она создаёт путаницу.
- **Требование:** Удалить или пометить как `# DEPRECATED: ADR-123`.
- **Риск:** Низкий — никто не вызывает.

### 3. Отсутствие лечения (перевязка)
- **Проблема:** Кровотечение из ран никогда не останавливается.
  InjuryProcessor производит +blood_loss каждый тик.
  DecayHandler обеспечивает свёртывание, но для тяжёлых ран этого мало.
- **Требование:** Механизм лечения: удаление Injury или изменение critical_effects
  останавливает InjuryProcessor → кровотечение прекращается.
  Это следующий причинный узел: `ранение → перевязка → восстановление → долг жизни`.
- **ADR:** ADR-124 (будущий)

### 4. Отсутствие CorpseState
- **Проблема:** После смерти NPC не удаляется, но и не становится причиной.
  Труп должен: лежать, пахнуть, быть найденным, создавать страх, быть уликой.
- **Требование:** `CorpseState` — проекция BodyState(dead) в мир.
  Труп как причинный объект: `нашли → расследование → месть → война`.
- **ADR:** ADR-125 (будущий)

### 5. vital_state evaluation только после PHYSIOLOGY domain
- **Проблема:** `StateApplicator` вычисляет `life_status` только при `DeltaDomain.PHYSIOLOGY`.
  Будущие процессы (InfectionProcess, PoisonProcess) могут менять body_state
  через другие домены → evaluator не вызовется.
- **Требование:** Перенести evaluation в end-of-tick reconciliation phase
  (после применения ВСЕХ доменов).
- **TODO:** В StateApplicator

## ДИНАМИКА КРОВОТЕРИ (справочно)

| Рана | bleeding_rate/tick | Смерть через | Свёртывание побеждает? |
|------|-------------------|-------------|----------------------|
| Порез шеи (0.5) | 0.026 | ~34 тиков | Нет |
| Порез груди (0.5) | 0.019 | ~47 тиков | Нет |
| Ушиб руки (0.5) | 0.0009 | ~1000 тиков | Да |
| Ожог ноги (0.7) | 0.0005 | Никогда | Да |
| Укол в пах (0.6) | 0.018 | ~50 тиков | Нет |
| Удар по черепу (0.8) | 0.0006 | Никогда | Да |

Формула: `bleeding_rate = structural_damage * zone_rate * damage_type_modifier`
Зональные ставки: neck=0.035, chest=0.025, groin=0.030, arm=0.012, leg=0.015, skull=0.005, face=0.015
Типовые модификаторы: slash=1.5, puncture=1.0, blunt=0.15, burn=0.05, crush=0.3
