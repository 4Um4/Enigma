**Дата обновления:** 06.06.2026  
**Спринт:** 72 (Transition: Engine Interprets → Personality Interprets)

---

## 0. Стратегическая оценка состояния

Система совершила онтологический переход от **"Движка Иллюзий"** (где движок решает, что значат события для всех NPC одинаково) к **"Многолинзовой Субъективной Физике"** (где каждый NPC собирает свою реальность через структуру личности).

**Что замкнуто:**
- State Collapse (Vacuum Bias устранён, `0.0` больше не маскирует отсутствие данных)
- Ghost Causality (Shadow Referential System ампутирована, EventContext зависит только от Intent)
- Identity Entropy (`drives_base` мутирует под воздействием травм)
- Engine Interpretation Monopoly (движок лишён права назначать смысл, эмоции и реакции)

**Что НЕ замкнуто:**
- Epistemic Coherence (система ещё не измеряет, не распалась ли она на несколько несовместимых реальностей)
- Temporal Divergence (нет мониторинга расхождения интерпретаций между NPC во времени)
- Causal Loop Detection (нет обнаружения замкнутых петель действий без внешнего триггера)

## 1. Архитектурные Законы (Исполняемые контракты)

### §ENIGMA-S72: Закон Релятивистского Восприятия

Движок производит только сырые сигналы (raw features). Смысл сигнала возникает в момент взаимодействия структуры личности (drives_base + trauma_markers) и сырого сигнала.

1. **CFRM = сырой сенсор.** ОБЯЗАН передавать `threat_level` и `anomaly_score` как есть (0-1), без фиксированных множителей (×40, ×20). Interpretation делегирована личности.

2. **Веса affective_load из drives_base.** ОБЯЗАН вычислять `affective_load` с весами из `drives_base` (`fear→threat`, `control→uncertainty`, `significance→anomaly`), а не из хардкода (0.6/0.3/0.1).

3. **DecisionHub модулируется через drives_base.** ОБЯЗАН модулировать `_context_relevance` через `drives_base`, а не через фиксированные семантические веса (+0.5/+0.7/+0.2).

4. **ЗАПРЕЩЕНА конвертация Vacuum в глобальные аккумуляторы.** `uncertainty_delta → stress_delta` в `LegacyStateDeltaAdapter` нарушает §ENIGMA-004.

5. **ЗАПРЕЩЕНО назначение dominant_emotion_hint из движка.** Эмоция резолвится только через Affective Pipeline → EmotionTransition.

6. **Все три порога эмоций персонализированы.** `anxious/fearful/panic` ОБЯЗАНЫ зависеть от `fear_drive + willpower`.

7. **Эмоция = энергия, личность = направление разрядки.** Конвертация эмоции в действие ОБЯЗАНА модулироваться через `drives_base`. Страх не всегда означает бегство: `control-heavy` перенаправляет страх в превентивную агрессию, `significance-heavy` — в предупреждение, `desire-heavy` — в поиск помощи.

- **Изменение:** Убита конвертация `uncertainty_delta × 5.0 → stress_delta`. Vacuum больше не протекает в глобальный стресс.

### Слой Аффекта (Affective Pipeline)

- **Изменение:** Веса `incoming` давления вычисляются из `psyche` (`fear`, `control`, `significance`), а не хардкод `0.6/0.3/0.1`.
- **Файл:** `backend/app/services/tick_orchestrator.py` (строки ~2037-2064)

- **Изменение:** Порог `anxious_threshold` персонализирован: `0.3 - fear_drive × 0.05 + willpower × 0.03`. Все три порога (anxious/fearful/panic) теперь зависят от личности.

- **Изменение:** `_context_relevance` модулируется через `drives_base`: `fear→насилие`, `control→кража`, `significance→свидетели`, `desire→диалог`. Хардкод `+0.5/+0.7/+0.2` убит.
- **Файл:** `backend/app/services/npc/decision_hub.py` (строки ~1056-1140)
- **Изменение:** `_emotion_modifier` принимает `drives` и перенаправляет эмоциональную энергию: Controller при страхе атакует (+0.125), Coward бежит (+0.445). Эмоция = энергия, личность = направление.

### Мёртвый код
- **Файл:** `backend/app/services/affective/emotion_resolution.py`
- **Статус:** DEPRECATED. Ни один модуль не импортирует `resolve_emotion_from_pressure`. Активный путь — `emotion_transition.py`. Помечен для удаления в S73.

## 4. Полный конвейер восприятия (после S72)

```text
RAW SIGNAL (CFRM: threat_level=0.7, anomaly=0.3)
    ↓ без множителей, без emotion hint

    ↓ веса из drives_base

    ↓ персонализированные пороги (fear_drive, willpower)

    ↓ перенаправление через drives_base
ACTION (controller→ATTACK, coward→FLEE, significance→WARN, desire→HELP)
```

## 6. Известные риски и следующие шаги

### Риск S72-R1: Renormalization Collapse Mode
При многократных мутациях один драйв может поглотить остальные (например, `fear` станет 0.95). Это "вымораживание" поведения.
- **Смягчение:** Энтропийный пол `0.01`.
- **Мониторинг:** Требуется CDS-хук на логирование `max(drives_base.values()) > 0.8`.

### Риск S72-R2: Temporal Divergence (Критический)
S72 создал распределённую систему интерпретации. Теперь NPC могут расходиться в "версиях реальности" во времени:
- NPC A интерпретирует событие как THREAT → FLEE
- NPC B интерпретирует то же как OPPORTUNITY → APPROACH
- Через 3-5 тиков их реальности перестают быть согласованными
- **Это не баг S72. Это новое системное свойство, требующее наблюдения.**

### Риск S72-R3: Causal Loop (Дрейф причинности)
Действия NPC теперь могут образовывать замкнутые петли без внешнего триггера:
```text
Attack → Fear → Retreat → Misinterpretation → New Attack
```
Это emergent behavior, но может стать "магическим багом" через 5-20 тиков.

### Риск S72-R4: Semantic Desync
Один и тот же `event_type` → разные `emotional_phase` → разные `action weights` → разные `world updates`. Система начинает генерировать разные миры внутри одного мира.

## 7. Горизонт S73: Epistemic Coherence Layer (ECL)

### Цель
НЕ исправлять поведение. А фиксировать: где и как система начинает жить в разных "версиях реальности".

### Ключевой принцип
ECL = наблюдатель, не участник. Он НЕ влияет на симуляцию. Он измеряет её когерентность.

### Три метрики

**Метрика 1: Reality Split Index (RSI)**
```text
RSI = variance(NPC_interpretations over time)
```
Если RSI растёт — система перестаёт быть одной симуляцией.

**Метрика 2: Causal Loop Detection**
Обнаружение замкнутых цепочек `A → B → C → A` в действиях NPC без внешнего триггера.

**Метрика 3: Semantic Stability Window**
Сколько тиков событие сохраняет одинаковую "значимость" в системе.

### Новый тип сущности: Epistemic Trace
Каждый event получает:
```text
event_id
→ interpretation_chain per NPC
→ divergence_index
→ drift_trajectory
```

### Критерий запуска S73
S73 легитимен только если runtime-наблюдение покажет:
1. RSI > порога (система распадается на несовместимые реальности)
2. Causal loops без внешнего триггера (эмерджентная патология)
3. Semantic desync > N тиков (интерпретации не сходятся)

**БЕЗ доказательства из runtime — S73 НЕ ЗАПУСКАЕТСЯ** (§ENIGMA-002).

### Минимальный MVP S73
1. Добавить `EpistemicTrace` в CDS (только запись, без влияния на симуляцию)
2. Вычислять RSI после каждого тика
3. Логировать в `LAST_SESSION.md` при RSI > порога
4. Causal Loop Detection через анализ DeltaBuffer за последние 5 тиков

## 10. Формула верификации S72 (smoke test)

```python
# A1: uncertainty не протекает в stress
pp = PerceptionPayload(uncertainty_delta=0.3)
d = StateDeltas(npc_id='t', domain=DeltaDomain.PERCEPTION, payload=pp, source='t')
r = LegacyStateDeltaAdapter.collapse([d])
assert r.stress_delta == 0.0

# I2: drives определяют нагрузку
pk = PerceptualKernel(threat_gradient=0.5, uncertainty=0.2, anomaly_score=0.1)
l_f = integrate_affective_pressure(pk, 0.0, {'fear': 0.6, 'willpower': 0.5})
l_b = integrate_affective_pressure(pk, 0.0, {'fear': 0.05, 'willpower': 0.5})
assert l_f > l_b

# S72.5: персонализированный порог тревоги
r_p = resolve_emotion_transition(0.29, 0.25, {'fear': 0.6, 'willpower': 0.3})
r_b = resolve_emotion_transition(0.29, 0.25, {'fear': 0.05, 'willpower': 0.8})
assert r_p.emotion_tag == 'anxious'
assert (r_b.emotion_tag if r_b else 'none') == 'none'

# S72-F: emotion_modifier персонализирован
hub = DecisionHub()
d_ctrl = {'fear': 0.1, 'control': 0.5, 'significance': 0.2, 'desire': 0.2}
d_cow = {'fear': 0.6, 'control': 0.1, 'significance': 0.15, 'desire': 0.15}
atk_ctrl = hub._emotion_modifier(Intent.ATTACK.value, EmotionTag.FEARFUL, d_ctrl)
flee_cow = hub._emotion_modifier(Intent.FLEE.value, EmotionTag.FEARFUL, d_cow)
assert atk_ctrl > 0    # Controller ATTACKS when fearful
assert flee_cow > 0.4  # Coward FLEES when fearful
```
