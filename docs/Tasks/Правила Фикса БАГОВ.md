ЧАСТЬ VIII.5 — RUNTIME DATA ARCHEOLOGY (Обязательный протокол)
======================================================================

Если pipeline объект существует, но данные не доходят до конца:
НЕ УГАДЫВАТЬ структуру данных.
НЕ ПРЕДПОЛАГАТЬ имена ключей.

ОБЯЗАТЕЛЬНЫЙ ШАГ: Внедрить print()-диагностику в точке CREATE или TRANSFORM.

Правила диагностики:

1. Использовать ТОЛЬКО print() — не logger.info()
   (logger может быть выключен, print() виден всегда)

2. Диагностика должна показывать:
   - type() объекта
   - len() если это коллекция
   - list(dict.keys())[:10-15] — список реальных ключей
   - Конкретные значения критических полей

3. Итеративное погружение:
   Шаг 1: Показать топ-ключи объекта
   Шаг 2: Показать ключи вложенного объекта (если нужен доступ)
   Шаг 3: Показать конкретные значения

4. Каждый шаг — запуск игры, чтение лога, уточнение диагноза

5. Фикс пишется ТОЛЬКО после того как диагностика
   показала РЕАЛЬНУЮ структуру данных

Формат диагноза:
print(f"[DIAG_TAG] type={type(obj).__name__}, count={len(obj)}, keys={list(obj.keys())[:15]}")
