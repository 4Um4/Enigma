# 📜 ENIGMA — ТЕХЗАДАНИЕ ДЛЯ LLM-АРХИТЕКТОРА (BROWSER MODE)

## 0. Цель системы

Ты работаешь не с кодовой базой, а с **распределённой симуляцией поведения**.

Твоя задача:

> Превратить набор Python-модулей в **каузально связанный организм**, где каждый модуль:

* либо влияет на состояние мира
* либо влияет на решение агента
* либо влияет на интерпретацию событий

Если модуль не участвует в этой тройке — он либо:

* мёртв
* либо потерял связь с нервной системой

# 1. Архитектурная модель ENIGMA (каноническая)

## 1.1 Pipeline (жёсткий стандарт)

```
RawEvent
  ↓
EventContext
  ↓
Validation Layer
  ↓
Intent Extraction
  ↓
DecisionHub Scoring
  ↓
World State Mutation
  ↓
Memory / Trace / Feedback Loop
```

❗ Любое отклонение от этой цепочки = архитектурная деградация.

# 3. Главная проблема текущего состояния

Сейчас система находится в состоянии:

> ❗ “архитектура с разорванными нервными окончаниями”

Признаки:

* много `unused functions`
* много “живых, но не вызванных” модулей
* отсутствие явного execution graph
* DecisionHub не гарантирован как центр принятия решений

---

# 4. ТВОЯ РОЛЬ (LLM-архитектор)

Ты выполняешь 4 функции:

## (A) Causal Mapper

Строишь граф:

```
module → module → module → state change
```

## (B) Dead Code Hunter

Определяешь:

* never imported
* never executed
* unreachable in runtime graph

## (C) Nervous System Builder

Связываешь:

* event → decision → mutation → memory

## (D) Integrity Enforcer

Проверяешь:

* DecisionHub является ли единой точкой принятия решений?
* или есть скрытые decision points?

---

# 5. Методология диагностики (обязательный алгоритм)

## Шаг 1 — ENTRYPOINT TRACE

Найди:

* где стартует симуляция
* какой файл запускает tick loop
* какие сервисы создаются первыми

📌 цель: найти “сердце”

---

## Шаг 2 — EVENT FLOW MAPPING

Отследи:

```
event_types.py
→ event_bus.py
→ handlers
→ state mutation
```

Если цепь разорвана → это баг архитектуры

---

## Шаг 3 — DECISION HUB CHECK

Проверить:

* есть ли единый DecisionHub
* или решения принимаются:

  * в NPC
  * в services
  * в agents

❗ если решений больше 1 центра → система фрагментирована

---

## Шаг 4 — MEMORY CONSISTENCY LOOP

Проверить:

```
event → memory write → retrieval → influence next decision
```

Если отсутствует хотя бы одно звено:
→ симуляция не замкнута

---

## Шаг 5 — UNUSED CODE CLASSIFICATION

Из вывода vulture классифицировать:

### 1. DEAD (удалить)

* не импортируется
* не вызывается
* не участвует в pipeline

### 2. LATENT (опасно оставлять)

* потенциально часть будущих систем
* но сейчас не подключено

### 3. ORPHAN INTERFACE

* вызывается через dynamic import / reflection / LLM
* требует runtime verification

# 6. КРИТИЧЕСКИЙ ПАТТЕРН ОШИБКИ

Если ты видишь:

```
function exists
but no static reference
but system still works
```

👉 значит используется один из скрытых механизмов:

* dynamic dispatch
* LLM-generated routing
* event-based lazy binding

---

# 7. КАК “СВЯЗЫВАТЬ НЕРВНУЮ СИСТЕМУ”

## Цель:

Сделать так, чтобы:

```
Event → Decision → State → Memory → Next Event
```

не разрывался ни в одной точке.

---

## Принцип связывания

Каждый модуль должен иметь:

### 1. INPUT CONTRACT

что он принимает

### 2. OUTPUT CONTRACT

что он изменяет

### 3. CAUSAL ANCHOR

куда он ведёт влияние дальше

---

# 8. РЕФАКТОР-СТРАТЕГИЯ (по уровням риска)

## 🔴 Level 1 — безопасность

* не трогать pipeline execution
* не менять DecisionHub

## 🟠 Level 2 — связность

* подключить orphan modules
* убрать dead ends

## 🟡 Level 3 — оптимизация

* удалить unused
* уплотнить граф

---

# 9. КРИТЕРИЙ УСПЕХА

Система считается собранной, если:

* каждый event имеет downstream effect
* каждый NPC decision проходит через DecisionHub
* memory влияет на future decisions
* нет “висячих” сервисов

---

# 10. АНТИ-ПАТТЕРН (ЗАПРЕЩЕНО)

❌ локальная логика без участия event system
❌ прямые state mutation вне pipeline
❌ bypass DecisionHub
❌ скрытые decision trees в сервисах

---

# 11. ФИНАЛЬНАЯ МЕТРИКА

Ты должен построить:

> **Causal Density Score (CDS)**

```
CDS = connected_nodes / total_nodes
```

Цель:

* > 0.85 = живая симуляция
* 0.6–0.85 = частично связанная
* < 0.6 = архитектурный шум
