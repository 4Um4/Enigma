## S78 ARCHAEOLOGICAL DISCOVERY — WAKE PRESSURE GAP

**Статус:** АРХЕОЛОГИЧЕСКОЕ ОТКРЫТИЕ. Не реализовывать до завершения проектирования.

### Суть открытия

Во время расследования R1 (Schedule Wake-Up) обнаружено отсутствие каузального узла между источниками возбуждения и состоянием сна.

Существующие источники пробуждения:

```text
DirectiveInterpretationSubscriber  →  interrupts_routine=True
Threat Gradient (ADR-081)          →  threat_gradient > 0.7
Pain (body_state)                  →  НЕ СВЯЗАНО СО СНОМ
Acoustic/environmental stimuli     →  БЛОКИРОВАНО perception_filter
```

Все они способны генерировать сигнал «не следовать расписанию».
Ни один из них не способен генерировать состояние пробуждения.

### Текущая система содержит:

```text
cause → interrupts_routine → schedule bypass (return [], None)
```

### Но НЕ содержит:

```text
cause → wake_pressure → arousal_threshold → SLEEPING → AWAKE
```

### Три конкретных разрыва

**Разрыв 1: Нет перехода SLEEPING → AWAKE**

Единственный писатель `routine["current"]` — `life_engine.py:1404`:
```python
routine["current"] = new_activity
```
Никто не пишет `routine["current"] = "awake"` и не очищает `"sleeping"`.
LifeEngine умеет пропускать укладывание спать. Но не умеет будить.

**Разрыв 2: `can_awaken` — мёртвое поле**

```python
can_awaken: bool = False  # объявление (npc_state.py:287)
can_awaken = bool(npc_dict.get("can_awaken", False))  # десериализация (npc_state.py:859)
```
Никто не устанавливает `True`. Никто не читает для принятия решения.
Это недостроенный механизм — семя, которое не проросло.

**Разрыв 3: perception_filter блокирует спящего — каузальный тупик**

```python
# perception_filter.py:136-137
incap = {"dead", "unconscious", "sleeping", "спит"}
return state not in incap and activity not in {"sleeping", "спит"}
```

Пока `activity = "sleeping"` не снят, NPC невидим для восприятия.
Создаётся петля:

```text
Спит → не воспринимает → threat_gradient не растёт
     → Physical Urgency Wake не срабатывает → продолжает спить
```

Директива игрока обходит этот тупик (DIS → прямой инъекция в PK через tick_orchestrator:730-731).
Но экологические угрозы (пожар, шум боя, крики) — нет. Они идут через CFRM → perception_filter → заблокированы.

### Доказанная связь сигнала

Ребро `recent_directive_data → perceptual_kernel.recent_directive` существует и работает через два пути:

1. StateApplicator:636-637 (через NPCState)
2. TickOrchestrator:730-731 (прямой write в npc_dict)

LifeEngine читает это поле в трёх местах (строки 1009, 1304, 1505).
Сигнал доходит. Проблема — не в получении сигнала, а в отсутствии действия пробуждения.

### Четыре домена затронуты (§ENIGMA-002 удовлетворён)

| Домен | Проблема | Доказательство |
|-------|----------|----------------|
| Социальный | Директива доходит, но не будит | `interrupts_routine=True` → только bypass |
| Физиологический | Угроза должна будить, но только bypass | `threat_gradient > 0.7` → `return [], None` |
| Телесный | Боль должна будить, но не связана со сном | Нет связи pain → wake |
| Перцептивный | Спящий NPC отрезан от восприятия | `_npc_is_conscious()` → False → deadlock |

### Вероятный будущий ADR

```text
ADR-O-142 [ONTO] Wake Pressure & Arousal Gate

wake_pressure = f(threat, pain, directive_salience,
                  acoustic_intensity, goal_urgency)

sleep_resistance = f(sleep_depth, fatigue, time_in_sleep)

if wake_pressure > sleep_resistance:
    routine["current"] = "awake"
    activity обновляется в scene_state
    perception_filter снимает gate

Одна сущность заменяет 40 отдельных будильников.
```

### Точка интеграции (нуждается в исследовании)

Arousal Gate стоит на пересечении четырёх систем:

```text
PerceptualKernel  →  угроза, неопределённость
BodyState         →  боль, шок, кровопотеря
IdentityPayload   →  директива, salience
LifeEngine        →  расписание, инерция
```

Механизм `activity_overrides` (npc_tick_pipeline:674-677, TickOrchestrator:220, 587) — уже существующий путь для обновления activity в scene_state. Вероятная точка интеграции для записи "awake" после преодоления порога.

### Почему это относится к ветке физиологии смерти

Сильная боль — один из самых мощных будильников. Сейчас боль умеет:
```text
рана → боль → дрожь → гримаса
```
Но не умеет:
```text
рана → боль → пробуждение
```

## АРХИТЕКТУРНАЯ ПЕРСПЕКТИВА

Система прошла семь этапов стабилизации:

```text
S67: Death Lock (онтология жизни/смерти)
S72: Persistence Lock (онтология сохранения состояния)
S73: Movement Lock (онтология арбитража поведения)
S74: Execution Eligibility (онтология права действия + Player = EntityView)
S76: Narrative Continuity (онтология проекции смерти в нарратив)
S77: Somatic Continuity (онтология хронического страдания и его проекции)
S78: Wake Pressure Discovery (археологическое открытие — отсутствующий слой)
```

Каждый этап вводил **causal commitment layer**. S78 не ввёл слой — он обнаружил его отсутствие.

**Открытие S78 изменило понимание R1:**
- R1 был «багом расписания»
- R1 стал «отсутствующей онтологией пробуждения»
- Локальный фикс R1 = создание 40 будильников
- Правильный путь = ADR-O-142 Wake Pressure & Arousal Gate

**Следующий логический шаг** (если появятся 2+ независимых кейса — §ENIGMA-002):
- ADR-O-142 Wake Pressure & Arousal Gate — объединяющий узел для threat/pain/directive/noise/goal → wake
- §ENIGMA-002 уже удовлетворён (4 домена)
- Ожидание: подтверждение что Wake Pressure увеличивает число стабильных каузальных структур
