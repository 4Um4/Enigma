# ENIGMA — ПЛАН TRAIT-134-CAUSAL: полное внедрение карты разрывов до причинного изменения

**Проект:** ENIGMA · **Дерево:** V.0.5.4.3.3, commit `0aeeb3bcc4761e08b3ee3f06c27e9c4a37bf1fdb`
**Базис плана:** аудит `AUDIT-BM-01` (`ENIGMA_AUDIT-BM-01_behavior_mask.md`) + специальное исследование диалогового канала и убеждений (24 канала проверены чтением кода, все ссылки файл:строка действительны для указанного commit).
**Режим:** план на внедрение; производственный код в момент составления не изменялся, тесты не запускались.
**Заказанная цель:** внедрить максимальное количество из 134 формулировок карты разрывов до **полного причинного изменения**, чтобы (СЦЕНАРИЙ-И) НПС на вопрос «что ты думаешь о X?» отвечал художественным текстом, опираясь на всё своё прошлое, и (СЦЕНАРИЙ-П) если игрок переубедит НПС — его убеждения реально изменились после этого и сохранялись.

---

## 0. Резюме для решения (1 страница)

1. **Оба целевых сценария недостижимы не из-за отсутствия механик, а из-за «оборванных хвостов» живых контуров.** Сквозной диалоговый канал игрок→НПС→LLM жив end-to-end (`routes.py:935` → `decision_hub.py:1556-1583` → `dialogue_executor.py:360-466`), но: вопрос неотличим от утверждения (speech_act не доезжает до `DialogueRequest`), предмет вопроса теряется в input-слое (SubjectRef умирает), а «прошлое» НПС — биография, секреты, пропозиции, мировоззрение — собирается в `VerbalizationContext` и выбрасывается (recalled_facts/suppressed_secrets/narrative_hints не потребляет ни один промпт-билдер). Художественному тексту активно мешает жёсткий контракт: 1–2 предложения, max_tokens=100 (`dialogue_executor.py:75, 369-376, 453`).
2. **Убеждения уже имеют полный «рельс причинности»**: три слоя (BeliefState → EpistemicStore → CrystallizedBelief/SQLite) записываются, переживают рестарт и автоматически меняют решения через модификаторы (`epistemic_context_resolver.py:111-163`, `belief_modifier_resolver.py:35-87`, `drive_resolver.py:46-54` — доказано дивергентным тестом). Единственное, чего нет — **канала «речь игрока → убеждение»**: claim из речи возможен только для 3 действий (ACCUSE/THREATEN/HELP), «это не так, потому что…» = no-op, а противоречие (убеждение A, игрок говорит ¬A) не разрешается в принципе — ¬A создаёт параллельную запись, которую никто не читает (`belief_revision_engine.py:78-97`, `epistemic_context_resolver.py:44-50`).
3. **Стратегия плана — не 134 переменные, а 2 новых контура + 1 мост + 7 общих носителей.** (а) **Контур интроспекции** (OpinionQuery): распознанный вопрос о мнении → сборка «прошлого» по предмету → художественный контракт генерации. (б) **Контур переубеждения** (PersuasionEngine): извлечение content-claim → детерминированная формула «вес аргумента vs сопротивление характера» → лестница исходов → ревизия с разрешением противоречий → кристаллизация в SQLite. (в) **Character Calibration** — тот самый недостающий «перевозчик характеров» (сеялка сознательно не сеет TRAIT_SEED/PORTRET/DESIRE_SEED, `chronicle_seeder.py:366-386`). (г) 7 новых **общих** носителей (patience, self-эмоции, affinity, зависимости, ожидания, salience, CAUSES-атрибуции) — каждый закрывает 3–9 строк, читатель обязателен до введения.
4. **Итоговое покрытие:** из 134 строк — **118 механически** (живой носитель + запись из авторских данных + читатель + причинное влияние, режим M) и **16 текстово** (режим T: формулировка участвует в художественном тексте через voice_profile/backstory/самоопределение — механика для них сознательно не заводится, это нарративные формулировки). Ни одна строка не выбрасывается: T-строки тоже работают на СЦЕНАРИЙ-И.
5. **6 фаз, 36 работ, суммарно ~13 недель** при одном разработчике: Фаза 0 «Разблокировка» (2 нед, 20 строк) → Фаза 1 «Интроспекция» (2 нед, 22 строки) → Фаза 2 «Переубеждение» (3 нед, 10 строк напрямую + переубеждаемость всех убеждений Фазы 3) → Фаза 3 «Character Calibration» (4 нед, 106 строк) → Фаза 4 «Межагентный контур» (4 нед, 10 строк) → Фаза 5 «Гигиена» (параллельно, 5 строк). Первая видимая игроку веха — конец 2-й недели (НПС уже отвечает «с памятью»).
6. **Порядок не произволен:** Фаза 0 разблокирует каналы (write-only поля, маска, проброс speech_act/subject — groundwork обоих сценариев); без Фазы 3 сценарии работают «на голом конфиге» (глубина только из individuals/*.json); без Фазы 2 убеждения есть, но их нельзя сдвинуть диалогом; Фаза 4 делает то же самое между НПС (Люся → Борко), а не только игрок → НПС.
7. **Инварианты неприкосновенны:** LLM не пишет состояние (`response_validator.py:221-241`), ClaimEvent ≠ World Truth (`epistemology.py:8-9`), ценз писателей BeliefState (`models/npc/beliefs.py:101-130`, ArchitecturalViolationError), детерминированные формулы убеждений без LLM-голосования, «LLM выключен — мир идентичен».

## 1. Два целевых сценария и критерии готовности

### 1.1 СЦЕНАРИЙ-И «Вопрос о мнении» (интроспекция)

**Формулировка заказа:** игрок спрашивает НПС «а что ты думаешь о том-то?» — НПС, опираясь на всё своё прошлое, выдаёт художественный текст.

**Развёртка цепочки (что должно произойти под капотом):**

| Шаг | Что происходит | Опора (уже живо / новое) |
|---|---|---|
| 1 | Текст игрока распознаётся как вопрос о мнении, выделяется предмет X | Живо: `_is_question` (`intent_compressor.py:333-342`), `extract_subject` → SubjectRef (`:366-400`). Новое: проброс до DialogueRequest (0.5), opinion-маршрут (1.1) |
| 2 | НПС выбирает/удерживает intent TALK с opinion-контрактом | Живо: буст TALK (`decision_hub.py:1556-1583`). Новое: opinion-контракт вместо стандартного (1.4) |
| 3 | Сборка «всего прошлого» по предмету X | Живо: `memory_manager.recall` (`memory_manager.py:547-608`), `retrieve_knowledge` (`knowledge_retrieval.py:37-100`), EpistemicStore, BeliefState, CrystallizedBelief. Новое: PerspectiveAssembler, сводящий это в промпт-блок (1.2–1.3) |
| 4 | Генерация художественного ответа в манере НПС | Живо: voice_profile/backstory/author_notes в промпте, disclosure-директива. Новое: OpinionContract (объём 4–8 предложений, max_tokens≈400), стиль-инструкция из voice_profile (1.4) |
| 5 | НПС может скрыть/приоткрыть правду по секретам | Живо: disclosure-лестница REVEAL/PARTIAL/HINT/REDIRECT/DENY (`disclosure_decision.py:32-94`) — переиспользуется as-is |
| 6 | Ответ валидируется без разрушения инвариантов | Живо: ResponseValidator (4-я стена, «LLM не двигает NPC») — параметры из контракта |

**Definition of Done (приёмочные инварианты):**
1. Ответ содержит **≥1 биографический элемент** (воспоминание из EventMemory/narrative_cache с тегом chronicle:* или origin), **≥1 убеждение** (любой из трёх слоёв), **актуальную эмоцию** (тон/нюанс), **манеру речи** (voice_profile) — проверяется стабами-маркерами в sandbox.
2. **Предмет-зависимость:** вопрос «о страже» и «о Люсе» одному НПС даёт содержательно разный фактический материал (разный recall), но одну манеру.
3. **Секрет-гейт:** вопрос о секрете при низком доверии даёт HINT/REDIRECT/DENY, не REVEAL; при высоком доверии и давлении — PARTIAL/REVEAL.
4. **Объём:** художественный ответ 4–8 предложений в opinion-режиме; обычная реплика вне режима остаётся 1–2 предложения (контракт не «протекает»).
5. **Детерминизм:** при выключенном LLM мир/состояние бит-в-бит идентичны; fallback-ответ деградирует только текстом.
6. **Инвариант телепатии:** в сборку «прошлого» попадает только то, что НПС вправе знать (секреты фильтруются `hidden_from`, память — по accessibility).

### 1.2 СЦЕНАРИЙ-П «Переубеждение» (смена убеждений через диалог)

**Формулировка заказа:** если игрок смог переубедить НПС («это не так»), его убеждения изменились после этого — персистентно и с влиянием на будущее поведение.

**Развёртка цепочки:**

| Шаг | Что происходит | Опора |
|---|---|---|
| 1 | Реплика «это не так, потому что …» извлекается как content-claim: пропозиция с предметом и полярностью | Новое: расширение extraction в fast/slow path (2.1). Живо: speech_act-реестр 18 актов (`epistemology.py:45-72`), Proposition (`:75-91`) |
| 2 | Claim доставляется до эпистемики всех слушателей в радиусе | Живо: мембрана и гейты `claim_event_subscriber.py:135-235`; расширяем реестр semantic_action→Proposition (:89-133) |
| 3 | **PersuasionEngine** вычисляет исход: вес аргумента vs сопротивление характера | Новое: детерминированная формула (2.4) на базе живых компонент: reliability по trust (`trust_based_reliability_provider.py:63-88`), давление диалога (`memory_manager.py:449-452`), resistance секретов (:479-513), traits, вес текущего убеждения |
| 4 | Исход — по лестнице AGREE_FULL / CONCEDE_PARTIAL / DOUBT / STALL / REFUSE — вербализуется (согласие или контр-аргумент) | Новое (2.5); опора: disclosure-стиль контр-аргументов, tone-канал |
| 5 | При согласии — **ревизия с разрешением противоречия**: conf(A) падает, conf(¬A) растёт | Новое: политика компенсации в `belief_revision_engine.py` (2.3); реестр предикатов расширяется |
| 6 | Сильное/повторное согласие **кристаллизуется** (SQLite, переживает рестарт) | Живо: `CrystallizedBeliefStore` (`crystallized_belief_store.py:33-77`), `belief_crystallization_engine` — добавляем ценз-писателя (2.6) |
| 7 | **Будущее поведение меняется автоматически** — живой рельс | Живо: эпистемические модификаторы → drive-модификаторы → DecisionHub (`npc_tick_pipeline.py:478-600` → `decision_hub.py:365-393`); речь — через блок убеждений (1.3) |
| 8 | Ответ на следующий вопрос отражает новые убеждения | Живо после Фазы 1: opinion-ответ читает текущие убеждения (1.2–1.3) |

**Definition of Done:**
1. **Дивергенция:** одинаковый мир, с убеждением «стража куплена» и после успешного переубеждения — разный интент/решения (расширение `epistemic_decision_divergence_test.py`).
2. **Персистентность:** после перезапуска игры убеждение осталось (SQLite `crystallized_beliefs` + scene_state `epistemic_records`).
3. **Обратимость:** можно переубедить обратно (симметрия политики ревизии).
4. **Сопротивление характера:** НПС-«сомневающийся» (строка 103) при равном аргументе даёт DOUBT там, где доверчивый даёт CONCEDE; враг с trust < −30 переубеждается хуже незнакомца (отрицательная reliability уже жива).
5. **Лестница исходов:** формулы дают все 5 исходов на калибровочной сетке; REFUSE вербализуется контр-аргументом, а не молчанием.
6. **Секрет-гард:** переубеждение не вскрывает защищённый секрет — давлением можно продавить признание (живой discovery-контур), но не «выключить» секрет.
7. **Инвариант истины:** убеждение НПС о состоянии мира ≠ истина мира; LLM не является источником исхода переубеждения.
8. **Гистерезис воли:** серия успешных давлений → COERCED (2.8) не «мигает» тик-в-тик (порог + удержание).

### 1.3 Что считается «полным причинным внедрением» формулировки

Формулировка из 134 переводится в режим **M (механическое)**, когда выполнены 4 критерия:

1. **R (распознавание):** детектор (`trait_gap_detector.py`) находит её в словаре соответствий — после 5.1 (лемматизация, emotions в индекс) и реестра Calibration (3.1);
2. **Носитель:** существует поле/структура состояния, в которую **пишет** авторские данные сидер/Calibration (не ручной копипаст, а конвейер chronicle → состояние);
3. **Читатель:** у носителя ≥1 живого потребителя в решениях/речи/восприятии (правило лексикона `character_lexicon.json`: «status=working только при живом потребителе»);
4. **Дивергенция:** сквозной тест подтверждает, что изменение носителя меняет результат (интент/реплику/восприятие) при прочих равных.

Режим **T (текстовый)** — честная альтернатива для нарративных формулировок (16 строк, категория НАРР и речевые привычки): формулировка участвует в художественном слое ответа (СЦЕНАРИЙ-И) через voice_profile/backstory/блок самоопределения; для неё не заводится поле, и это фиксируется в реестре как осознанное решение, а не разрыв.

### 2.3 Шесть мёртвых зон, мешающих обоим сценариям

1. Write-only поля вербализации: `recalled_facts`, `suppressed_secrets`, `narrative_hints`, `stm_buffer` (`npc_tick_pipeline.py:1550-1552`) — собираются, не потребляются.
2. `PLAYER_ASKS_WHY`/EXPLAIN: событие объявлено (`event_types.py:86`), потребитель написан (`decision_hub.py:2030-2059`) — публикатора нет.
3. `subject_id/subject_kind` вопроса умирают на выходе input-слоя (потребителей downstream нет).
4. Противоречие polarity в EpistemicStore не разрешается; читается только polarity=True.
5. COERCED/DECEPTIVE/LOYAL воли — без рантайм-писателей (только BROKEN↔FREE, `break_progress_engine.py:160-188`).
6. Хроника-канон пуст: `guard_borko.json` содержит author_text на 28 пунктов при `entries: []` — декомпозиция не запускалась; TRAIT_SEED/PORTRET/DESIRE_SEED не сеются by design (`chronicle_seeder.py:366-386`).

## 3. Целевая архитектура

### 3.1 Схема двух новых контуров поверх живой системы

```
                    ┌──────────────────────────── ФАЗА 1: ИНТРОСПЕКЦИЯ ────────────────────────────┐
 игрок: «что ты     │ intent_compressor (QUESTION+SubjectRef, живо) → проброс 0.5 →                  │
 думаешь о страже? ─┤ post_decision: opinion-маршрут 1.1 → DialogueRequest(mode=OPINION)             │
                    │ dialogue_executor._generate_with_router:                                       │
                    │   PerspectiveAssembler 1.2:                                                    │
                    │     memory_manager.recall(subject)      ← биография/события (chronicle-теги)  │
                    │     retrieve_knowledge(subject)         ← секреты (disclosure as-is)            │
```

### 3.4 Эпистемическая гигиена (инварианты, которые план не вправе нарушать)

1. **LLM не пишет состояние** — исходы переубеждения считает детерминированный PersuasionEngine; LLM только озвучивает (`response_validator.py:221-241` остаётся).
2. **ClaimEvent ≠ World Truth** — убеждение НПС о состоянии другого НПС (Фаза 4.2) никогда не становится фактом мира (`epistemology.py:8-9`).
3. **Ценз писателей** — PersuasionEngine и CalibrationWriter добавляются в белые списки `_UPDATE_ALLOWED_WRITERS` явно, запись мимо движков по-прежнему ArchitecturalViolationError.
4. **Фильтр знания** — PerspectiveAssembler берёт только то, что НПС вправе знать: recall фильтрует секреты (`memory_manager.py:572-577`), секреты — через disclosure-лестницу, память — по accessibility.
5. **LLM-off идентичность** — оба контура работают при выключенном LLM (fallback-вербализация исходов), авторитетные факторы не зависят от генерации.
6. **Анти-телепатия** — межагентное восприятие (Фаза 4) только через perception-мембрану (радиус/LOS/слух), никаких прямых чтений psyche.
7. **Не плодить переменные** — новое поле вводится ADR-записью с перечнем читателей; реестр «формулировка → поле» запрещает поле-на-слово.

**Веха E (конец недели 13): «Мир видит маски»**
Фаза 4: НПС видят невербалику друг друга, принимают маски за истинное состояние (и ошибаются), секреты и убеждения текут между агентами. Фаза 5 закрывает гигиену и даёт финальный отчёт «до/после» по карте разрывов.
