## 1. ЖЕЛЕЗНОЕ ПРАВИЛО: НИКАКИХ СКРИПТОВ

Это **архитектурный закон**, а не пожелание.

**Что запрещено:**
- Скриптованные сцены вида «если NPC_A встретил NPC_B в локации X в интервале T → запустить диалог Y».
- Флаги «quest_lusya_met = true», «trigger_tavern_fight = true».
- Хардкоженные реплики NPC, привязанные к событиям.
- Любые условные конструкции, которые предопределяют **что именно** произойдёт.

**Что разрешено:**
- **Правила** — общие законы, из которых сцены **возникают**, а не задаются.
- **Drives** — внутренние нужды NPC, которые толкают к действию.
- **Реакции** — ответ PerceptionEngine на воспринятое событие.
- **Эмерджентные матчи** — детекторы типа «если два NPC в одном кластере и friction > порог → возможность DIALOGUE».

## 2. КОНТЕКСТ: ЧТО УЖЕ ЕСТЬ И РАБОТАЕТ

### 2.1. Подсистемы, которые СУЩЕСТВУЮТ и работают (S113-S125)

- **TickOrchestrator** — 13 фаз game loop (Единый pipeline для idle и player path).
- **DecisionHub** — utility-скоринг на основе NPCState + Drives + EventContext. Генерирует вербальные интенты.
- **LifeEngine** — расписания NPC, need-driven движение, random events.
- **AffectiveIntegrator + EmotionTransition** — эмоции как leaky integrator.
- **PerceptionEngine + InterpretationEngine** — восприятие событий NPC.
- **BeliefCrystallizationEngine + PatternDetector + CrystallizedBeliefStore** — формирование убеждений (L2.5).
- **LayeredMemory + L1Chronicle + WorkingMemory** — память NPC (SQLite).
- **SocialEngine + ReputationEngine + RelationshipStore** — слухи, репутация, отношения (SSOT 0-100).
- **DialogueExecutor + TaskScheduler + DialogueMaterializer + DialogueQueue** — материализация реплик с приоритетами LLM.
- **NpcDialogueSubscriber** — замыкает цикл восприятия для NPC-NPC диалогов (эмоции, память, отношения).
- **CombatSubscriber + ImpactEngine + InjuryProcessor** — боёвка (D&D 5e через `combat_math.py`).
- **Frontend**: top-down рендер, speech bubbles (с цветами по tone), mood-иконки, journal (J).

### 2.2. Главная боль: Обрыв цепочки "Изменение Характера"

Цикл «Нужда → Диалог → Мнение → Изменение» обрывается на этапе «Изменение».
NPC могут говорить, менять эмоции и отношения, но **это не приводит к глубоким трансформациям личности**.

**Корень проблемы:**
В S124 был внедрён `LifeProjectResolver` (L2.7), который меняет жизненный вектор (например, с `family_builder` на `isolation`). Но он активируется **только** при флаге `identity_crisis = True`, который выставляет `BreakProgressEngine`.
А `BreakProgressEngine` считает "давление на психику" (`identity_pressure`). На данный момент это давление формируется в основном от *прямых боевых действий*, но **не от накопления социальных микро-травм** (падения доверия в разговорах).

## 3. ЭТАП 1: ЗАМЫКАНИЕ ЦИКЛА ДЕФОРМАЦИИ ИДЕНТИЧНОСТИ (10-14 ДНЕЙ)

Это **сердце всего проекта**. Цель: реализовать замкнутый цикл, чтобы драма возникала из системы, а не из скриптов, и приводила к необратимым изменениям в NPC.

### 3.1. Шаг 1.1 — Социальное Давление на Идентичность (2-3 дня)

**Цель:** NPC-NPC конфликты должны бить по психике настолько сильно, чтобы ломать характер.

**Что сделать:**
1. В `NpcDialogueSubscriber._process_canonical` при сильно негативном tone (ANGRY, MANIPULATIVE) генерировать `IdentityPressurePayload`.
2. Передавать этот payload в `BreakProgressEngine.calculate()`.
3. Падение доверия ниже определённого порога (например, `trust < 20`) должно генерировать всплеск `identity_pressure`.
4. `BreakProgressEngine` должен накапливать это давление и при превышении порога выставлять `identity_crisis = True`.

### 3.2. Шаг 1.2 — Снятие блокировки L2.5 для диалогов (2-3 дня)

**Цель:** Диалоги должны кормить механизм кристаллизации убеждений.

**Что сделать:**
1. Проверить, генерируют ли события `NPC_SPOKE` (с radius < 5.0) `phase_2_events` в Фазе 2 (`SpatialEventDetector`).
2. Если нет — добавить логику: если два NPC говорят (audience=target_id), создавать `SpatialEvent` (type=PROXIMITY_CLOSE/SOCIAL_INTERACT).
3. Без `phase_2_events` `BeliefCrystallizationEngine` (L2.5) никогда не запустится в idle. Диалоги должны формировать убеждения ("я больше не верю людям").

### 3.3. Шаг 1.3 — Тестовая сцена «ТОРНИН → ЛЮСЯ → ГОРАН»

**Это главный тест всего проекта.**

Сценарий: запустить игру в 9:00 игрового времени. Торнин за стойкой, Люся убирает столы, Горан сидит с кружкой. Игрок **ничего не вводит**, только наблюдает.

**Ожидаемая эмерджентная драма:**
1. Торнин (фрустрирован) → DecisionHub генерит `DIALOGUE(tone=ANGRY, target=Люся)`.
2. Торнин кричит на Люсю → `NPC_SPOKE` event.
3. `NpcDialogueSubscriber` ловит это → sadness Люси += 0.4, trust[Торнин] -= 5.
4. Генерируется `IdentityPressurePayload` → `BreakProgressEngine` повышает давление.
5. На следующем тике DecisionHub Люси: `SEEK_COMFORT` utility > threshold → `APPROACH + DIALOGUE(tone=VENTING, target=Горан)`.
6. Люся идёт к Горану, жалуется.
7. Если это происходит систематически, `identity_pressure` Люси превышает порог → `identity_crisis = True`.
8. `LifeProjectResolver` меняет `life_direction` Люси (например, на `isolation` или `revenge`).
9. Люся полностью меняет своё поведение в `DecisionHub`.

**Критерии успеха:**
- Все шаги происходят **без ввода игрока**.
- В `NPCState` видно рост `identity_pressure`.
- Происходит смена `life_direction`.

### 4.3. Принципы мини-игры

1. Игрок = наблюдатель системы, а не решатель квеста.
2. No real-time correctness feedback — игрок никогда не знает, прав ли он.
3. Truth ≠ Observed ≠ Inferred — три слоя строго разделены.
4. Evaluation is post-hoc only — сравнение с TruthState только при выходе.
5. NPCs operate independently — NPC не знает, что его оценивают.
6. **Causal continuity preserved** — NPC-NPC взаимодействия продолжаются, даже если игрок не наблюдает. Эмерджентная драма из Этапа 1 продолжается **параллельно** с мини-игрой.

## 5. ПРАВИЛА ДЛЯ LLM-АРХИТЕКТОРА

### 5.1. Дисциплина

1. **Не нарушай принцип «без скриптов»** (§1).
2. **Не удаляй существующие тесты**, даже failing.
3. **После каждого этапа** — писать отчёт в `reports/history/<date>.md`.

### 5.2. Принципы эмерджентности

1. **Правила, не сценарии.** Опиши как `utility = f(X)` для общего случая.
2. **Drives, not commands.** NPC не «идёт к Горану», а «чувствует SEEK_COMFORT».
3. **Reactions, not triggers.** NPC воспринимает событие → интерпретирует → обновляет эмоции → принимает решение.
4. **Beliefs, not flags.** Вместо `quest_lusya_met = true` — `belief("я встречал Люсю", confidence=0.9)`.
5. **Patterns, not sequences.** Детектор паттернов кристаллизует belief после N повторений.

## 7. ОЖИДАЕМЫЙ РЕЗУЛЬТАТ

Если все этапы пройдены:

1. **Игрок заходит в таверну** и видит живой мир: NPC разговаривают, у них меняются эмоции, возникают конфликты.
2. **NPC могут сломаться под давлением** социальных стрессов: Люся, подвергшись постоянным нападкам Торнина, меняет свой жизненный вектор и становится замкнутой или мстительной.
3. **Игрок пытается разгадать** отношения: подслушивает, наблюдает, пытается шантажировать.
4. **Игрок выходит из таверны** — и видит экран результата: сколько секретов он раскрыл, насколько точно построил модель мира.
5. **Игрок хочет переиграть** — потому что понимает, что в новой сессии драма будет **другой**: NPC могут по-другому отреагировать на стресс, сформироваться иные убеждения, измениться характеры.

**Это и есть «живая игра».**
