## §5 BOTTLENECK CLASSIFICATION

| Hotspot | Класс | Комментарий |
|---|---|---|
| Deepcopy-шторм (62%) | **Architecture (CPU-allocation)** | Не Python-интерпретатор и не алгоритм: это архитектурный режим «копируй-и-проверяй» (S-143, Dual Rail, 2× hash). Work-to-delete, не work-to-accelerate |
| JSON ×2/тик (7%) | **Serialization (architecture)** | Инвариант куплен полной сериализацией мира; уже C-ускорен — Rust не даст >1% net |
| Рост цены тика (+0.055 мс/тик) | **Architecture + Dead-I/O** | Драйверы: (а) мёртвый `SELECT *` без LIMIT растёт с накоплением event_memories (результат выбрасывается); (б) `recent_dialogues` в scene_state никогда не подрезается → объём копий растёт; (в) копии пропорциональны растущему стейту |
| SQLite (0.5-1.3%) | **I/O (неузкое место!)** | H2 «persistence-загрязнение» опровергнута как первопричина: −7% от всего Lab-стека |
| Editor-JSON glob, SHA-256 карты, RelationshipStore rewrite | **I/O (малые)** | Суммарно <1-2%, чинятся mtime-кешами |
| O(N²)-контуры | **Algorithm (неактивны при N=6-30)** | Пары расстояний ×2, LOS N²×W, get_weights N×(N+1) — всё тривиально при N=6; становятся релевантными при N≥100 |
| **Детерминизм** | **CAUSAL BUG (не производительность)** | Одинаковый seed+конфиг → РАЗНЫЙ мир (2×2 верифицировано). E1: wall-clock `time.time()`-timestamp в `scene_state["recent_dialogues"]` (task_scheduler.py:382,389) — ломает канонический хеш. E2: **каузальное расхождение** — wall-clock TTL-фильтр (`:119`) + async ThreadPoolExecutor диалогов → Фаза 4 топики → NPC принимают разные решения (`stress_delta` у разных NPC, `_sleep_start_tick` 3530 vs 3630) |
| LLM-latency (idle!) | **External/Infra** | Idle-контур вызывает LLM (MEMORY_SUMMARIZATION); на железе пользователя — секунды на вызов, в песочнице 0. Не Rust-вопрос |

**Ответ на центральный вопрос §12 (slow because simulation vs slow because infrastructure):** ни то, ни другое в чистом виде — это **«slow because copying»**: архитектурная транспортировка состояния (62%+7%) плюс накопительный рост от мёртвого I/O. «Честная симуляция» — ≈8% тика.

## §7 LAB MODE CANDIDATE

**Возможен? ДА — и без второго каузального ядра.**

Профиль это доказывает прямо: тик = микроскопическое каузальное ядро (~8%) в толстой транспортной обёртке (копии 62% + сериализация 7% + мёртвый I/O + наблюдатели ~7%). Lab Mode меняет **транспорт** (где живёт состояние, сколько раз копируется, когда сбрасывается на диск, какие часы для не-каузальных TTL), не трогая **каузальное ядро**: порядок фаз, математику редьюсеров, KernelRNG и порядок потребления RNG (RCOC).

**Граница (механически проверяемая):** Lab Mode НЕ имеет права менять (а) набор значений, потребляемых решениями (единственное исключение — стейдж 3, где wall-clock никогда не был легитимным каузальным входом: текущий прогон невоспроизводим, сохранять нечего), (б) редьюсерную математику, (в) порядок RNG. Проверка: same-seed канонический хеш + равные drift-счётчики + молчание INV + Mode E MATCH ⇒ тот же каузальный прогон.

**Минимальный контракт Lab Mode:**
- ХРАНИТЬ/СЧИТАТЬ: drift-счётчики A-E, ground truth, канонический хеш (1×/прогон), 9 probes, KernelRNG.
- ОТСЕЧЬ: replay (env), файловые логи (env), per-tick `get_scene_state` (RAM-валидация), WorldSnapshotDTO+asdict (выбрасывается DriftLab'ом), мёртвый narrative SELECT, дубли копий/коммитов.
- В лаборатории: mock-LLM (встроен в проект), `:memory:` SQLite, синхронные диалоги.

**Проекция:** сегодня 62 мин/10k → стейдж 0-2: 6.5-8 мин (плоско) → +стейдж 4: **4.2-5 мин** ✅ (цель §9: 10k как рутинный инструмент).

## §8 RUST CANDIDATES (максимум 3 — все не проходят ратификацию сегодня)

### RC-1: Канонический хешер (INV-TEMPORAL-ISOLATION)
- Input/Output: frozen-структуры тика → 64-бит хеш. Owner: tick_orchestrator. Authority: наблюдатель (mutation rights: none).
- **Expected gain: ≤1% net** (доля json 7.3%, hashlib уже OpenSSL, вход через C-API walk ≥ стоимости C-энкодера). **Verdict: 🔴 DEAD** — Python-фикс (гейт до 1×/100 тиков или orjson) бесплатен.

### RC-2: Геометрическое ядро (LOS/point-segment, spatial_runtime)
- Input/Output: float-кортежи → float. Единственная marshal-чистая граница в кодовой базе.
- **Expected gain: ≈0.3-0.5%** (измеренная доля 0.56%; LOS вообще захардкожен `True` в pipeline_runner.py:70 — вычисления нет). **Verdict: 🔴 DEAD** — доля несущественна.

### RC-3: State-owning v2 kernel (единственный выживший в стилман-тесте)
- Rust владеет каноническим миром (типизированные структуры), Python — FFI-адаптер для LLM/диалогов. Устраняет границу, а не пересекает её.
- **Условия оживления (все обязательны):** (a) заморозка исследовательского протокола/схемы (сегодня 20+ env-флагов ещё переклёвываются по KEEP-листу RATIFICATION); (b) починка E1/E2 **до** порта; (c) доказанная потребность: N≥100 NPC или интерактивный бюджет <5 мс/тик (сегодняшняя цель «10k за ночь» перекрывается Python-фиксами в ~12-30 раз); (d) готовность к 4-8 инженер-недель + постоянному dual-stack налогу. **Verdict: ⚫ UNKNOWN — заблокирован условиями, ни одно не выполнено.**

## §9 FALSIFICATION (почему Rust может быть ошибкой)

1. **Арифметика границ:** максимум ускорения по каждой достижимой для Rust границе: hasher ≤1% net, geometry ≈0.3%, A* <0.3% (V=18 ≈ 300 операций), SQLite ∞→0.6%, DecisionHub-ядро: 10× на 8% минус 3-5% marshalling = 2-5% net за вторую реализацию 12-интентного скоринга с 20+ env-поведениями. **Ни одна граница не даёт >5%.**
2. **Marshal-налог съедает приз:** стоимость dict→Rust→dict (измеренный аналог json round-trip = 1.76 мс на мир) ≥ стоимости копии, которую Rust заменяет (1.62 мс). Rust-ускоритель deepcopy платит пошлину за переход границы, существующей только из-за defensive-copy режима, который надо удалить, а не ускорить.
3. **Детерминизм не решается языком:** расхождение same-seed прогонов живёт в Python-оркестрации (threads + wall-clock вокруг ядра). Rust-ядро под сломанной оркестрацией даёт невоспроизводимые результаты быстрее — это хуже, а не лучше.
4. **Amdahl:** честная логика = 8% тика; даже бесконечное её ускорение ≈ −8%. После Python-фиксов остаток ещё меньше.
5. **Экономика:** 50 строк Python (стейдж 1-2) дают 2.5-3×; Rust-ядро — недели работ ради ≤5% на текущем профиле.
6. **Architectural damage:** вторая имплементация семантики (пусть и «только скоринга») = второй источник истины — прямое нарушение инвариантов 4.4-4.5 операции без доказанной пользы.

## ПРИЛОЖЕНИЕ C: ДЕТЕРМИНИЗМ — открытие вне исходного вопроса

Операция спросила «что ограничивает скорость» — измерение обнаружило более глубокую проблему: **свободный idle-прогон невоспроизводим бит-в-бит при одинаковом seed** (4 прогона, 2 конфига — все 4 финальных хеша различны; дифф двух прогонов: 33/3915 путей).

- **E1 (косметика, ломает хеш):** `time.time()`-timestamp пишется в `scene_state["recent_dialogues"]` (task_scheduler.py:382→389) и попадает в канонический хеш; `_EXCLUDE_FROM_SCENE_HASH` его не исключает.
- **E2 (каузальное):** wall-clock TTL-фильтр UI-кеша (task_scheduler.py:119, ADR-O-343) → тот же отфильтрованный список читает Фаза 4 для topic-extraction (tick_orchestrator.py:1720-1723) + диалоги исполняются асинхронно (ThreadPoolExecutor) → момент попадания исхода диалога в состояние зависит от скорости машины → **NPC принимают разные решения** (зафиксировано: `stress_delta=10` у разных NPC, `_sleep_start_tick` 3530 vs 3630).
- **Следствия:** (1) Mode E «Replay Determinism: MATCH» от 2026-08-12 относится к прошлому состоянию кода — сегодня он бы упал; (2) A/B-эксперименты поверх свободных прогонов каузально невалидны, пока E1/E2 не починены (стейдж 3); (3) исторический тезис «детерминированный replay» верен для записанных сессий (ReplayPlayer), но свободный мир им не обладает — это надо честно отразить в научной публикации (ограничение или фикс).

**Фикс = 3 точечных изменения Python (стейдж 3), не язык ядра.**
