## 0. Доктринальный сдвиг

### 0.1. Предыдущая ошибка

ТЗ №2 v1 учил игрока **механикам**: «нажми TAB → напиши → увиди consequence → раскрой 17 секретов». Это классическая ошибка архитектора: построен механизм генерации сложных историй, и ожидается, что игрок сам поймёт, зачем в этот механизм входить. **Не поймёт.**

### 0.2. Главная корректировка

Игроку не нужно понимать ENIGMA. Игрок должен понять только одно:

> «В этом мире мои действия имеют последствия, а люди помнят то, что я делаю.»

И затем игра должна **доказать это экспериментально** — не через tutorial, а через реальный опыт.

### 0.3. Новая формулировка ENIGMA как игры

**Не:** «Мы создаём RPG без заранее написанного сюжета».
*(Это звучит для игрока как: «Тебе самому придётся придумать, чем заняться».)*

**А:** «Ты входишь в живую историю. Ты не знаешь, чем она закончится — потому что её исход зависит от того, что ты сделаешь».

### 0.4. Принцип

> Автор пишет не историю. Автор пишет **условия возникновения истории**.

Это и есть доктрина ENIGMA.

## I. Архитектурный переворот: три петли, не одна

### I.1. Предыдущая (только симуляционная) петля

```
мир → восприятие → знание → убеждения → решение → действие → последствия → память
```

Это отличная **онтология симуляции**. Но это **плохая петля игрока**.

### I.2. Три петли ENIGMA

ENIGMA как игра состоит из **трёх наложенных петель**:

#### Игровая петля (player gameplay loop)

```
намерение игрока → действие → наблюдение → интерпретация → решение → последствие → новая возможность
```

#### Нарративная петля (narrative loop)

```
зацепка → любопытство → действие → открытие → осложнение → изменение ситуации → новая зацепка
```

#### Симуляционная петля (ENIGMA core)

```
WORLD_TRUTH → PERCEPTION → OBSERVATION → MEMORY → BELIEF → EXPECTATION → MOTIVATION → DECISION → ACTION → WORLD_CHANGE
```

**Связь:** под двумя верхними петлями работает «чудовищная машина ENIGMA» — детерминированный каузальный симулятор с эпистемической честностью. Игрок не видит третью петлю. Игрок видит первые две.

### I.3. Полная архитектура

```
   Authored Narrative Frame  ← единственная авторская часть (3-5 строк текста)
              ↓
        Player Goal          ← выбор при character creation
              ↓
    ENIGMA Simulation        ← существующая машина (TickOrchestrator, EpistemicStore, DecisionHub)
              ↓
     Emergent Events         ← EventBus + SOCIAL_ACTION
              ↓
   Character Reactions       ← NPC beliefs → decisions → actions
              ↓
  Player Interpretation      ← игрок сам смыслит происходящее
              ↓
   Self-generated Story      ← никто не написал. Возникла.
```

## II. Трёхслойная архитектура целей

### II.1. Immediate Goal (что я делаю прямо сейчас)

Простые, осязаемые, краткосрочные:

- найти комнату на ночь
- поговорить с кузнецом
- заработать 10 монет
- выяснить, кто украл лошадь
- подслушать разговор у камина
- продать информацию страже
- познакомиться с служанкой
- украсть кошелёк у пьяного гостя

**Источник:** мир генерирует возможности, игрок выбирает.
**Видимость:** не показывается в UI как «quest». Игрок сам формулирует.
**Длительность:** минуты — часы.

### II.2. Personal Goal (чего я хочу добиться как персонаж)

Долгосрочные мотивации, выбранные при создании персонажа:

- стать уважаемым в деревне
- найти пропавшего родственника
- разбогатеть
- стать известным
- отомстить за прошлое
- открыть собственную мастерскую
- просто выжить
- просто посмотреть, что здесь происходит *(тоже валидный personal goal)*

**Источник:** авторский набор (5-8 вариантов), игрок выбирает один или «никакой».
**Видимость:** отображается в журнале как «моя цель», но без прогресс-бара.
**Длительность:** вся кампания.
**Роль:** даёт игроку **вектор**, не путь. Игрок сам решает, как к ней идти.

### II.3. Emergent Narrative (что случилось со мной в результате моих решений)

Это **территория ENIGMA**. Третий уровень не должен быть заранее написан.

**Источник:** возникает из каузального взаимодействия player goals + world simulation + NPC reactions.
**Видимость:** отражается в журнале как «моя история» — последовательность значимых событий, которые игрок пережил.
**Длительность:** формируется на протяжении всей кампании.
**Пример:** «Я пришёл заработать. Стал свидетелем воровской сделки. Меня заметили. Теперь я либо сообщник, либо мишень. Это уже не та история, ради которой я пришёл — но это *моя* история.»

## III. Authored Narrative Frame

### III.1. Что это

Минимальная авторская рамка, которая даёт игроку **первую страницу**. Не Skyrim-сюжет, не branching narrative. **Условие возникновения истории.**

### III.2. Конкретная рамка для кампании Open_road

```
Ты прибываешь в таверну «Серебряный Волк»
поздним вечером, усталый с дороги.

Через три дня здесь состоится праздник
в честь дня рождения хозяйки деревни.

В деревне что-то происходит.

Ты пока не знаешь что.
```

Всё. Это **уже цель**.

Не: «Реши тайну деревни».
А: «Разберись, что здесь происходит — если тебе вообще есть до этого дело».

### III.3. Почему это работает

1. **Конкретная временная точка** (через 3 дня праздник) — даёт естественный horizon.
2. **Намёк на тайну** («что-то происходит») — даёт любопытство, не обязательство.
3. **Игрок может проигнорировать** («если тебе вообще есть до этого дело») — явное разрешение на agency.
4. **Открытая формулировка** — игрок сам решает, что значит «разберись».

### III.4. Что НЕ входит в рамку

- ❌ Конкретный антагонист
- ❌ Конкретный MacGuffin
- ❌ Список квестов
- ❌ Dialogue trees
- ❌ Linear progression checkpoints
- ❌ «Правильный» финал

### III.5. Реализация

Текст рамки — статичная заставка при первом входе в таверну (после загрузки камеры). ~5 секунд на экране, потом fade out. Не возвращается. Не упоминается снова, если только NPC сами не заговорят о празднике.

В коде: `frontend/onboarding_screen.py` (новый) + `config/campaigns/Open_road/narrative_frame.json`:

```json
{
  "frame_id": "silver_wolf_arrival",
  "text_lines": [
    "Ты прибываешь в таверну «Серебряный Волк»",
    "поздним вечером, усталый с дороги.",
    "",
    "Через три дня здесь состоится праздник",
    "в честь дня рождения хозяйки деревни.",
    "",
    "В деревне что-то происходит.",
    "",
    "Ты пока не знаешь что."
  ],
  "display_duration_sec": 12,
  "fade_out_sec": 2,
  "personal_goal_choice_after": true
}
```

## IV. Lead System (система зацепок)

### IV.1. Что такое зацепка

**Зацепка** — emergent событие, которое игрок может заметить, и которое **предлагает** возможность вмешательства. Не квест. Не маркер. Не objective.

Зацепка — это **нарративный атом**: «что-то в мире привлекло твоё внимание».

### IV.2. Источники зацепок

| Источник | Пример | Как рождается |
|---|---|---|
| Подслушанный разговор | NPC говорит другому NPC что-то подозрительное | `SOCIAL_ACTION` event + `PerceptualKernel` игрока в радиусе |
| Странное поведение NPC | Люся нервно оглядывается у восточного выхода | `EmbodiedTrace` с `nervous_marker` |
| Физическая аномалия | Запертая дверь, обычно открытая | `DynamicAffordanceField` state change |
| NPC подходит к игроку сам | Борко: «Эй, ты. Новенький? Пойдём, поговорим.» | `DecisionHub` NPC выбирает `INTERRUPT_PLAYER` intent |
| Упоминание в случайном диалоге | Горан упоминает «те коробки, что Орм ковал» | `ClaimEvent` propagates через `EpistemicStore` |
| Визуальная деталь | Кровь на полу у стойки | `ManifestationDTO` с `blood_visibility > 0` |
| Временной триггер | Полночь — странный звук из подвала | `Phase 0.5` time-driven event |
| Player-driven зацепка | Игрок спрашивает про Тень — NPC реагирует странно | `SOCIAL_ACTION(QUESTION, topic=SHADOW)` + `confession_pressure > threshold` |

### IV.3. Как зацепка становится видимой игроку

Когда `PerceptualKernel` игрока регистрирует событие, которое проходит порог `salience > 0.4`:

1. В `PlayerPerceptionDTO.peripheral_cues` добавляется `PerceptionCue`.
2. `frontend/narrative_renderer.py` отрисовывает cue как **визуальный акцент** в мире (не UI-overlay): иконка `?` над головой NPC, подсветка объекта, изменение цвета реплики.
3. В журнал добавляется запись в секцию **CLUES** (см. §VII.3).
4. **Игра НЕ говорит игроку «следуй за этой зацепкой».** Игра только показывает, что заметила что-то.

### IV.4. Игрок может:

- **Следовать зацепке** — подойти, спросить, investigate.
- **Проигнорировать зацепку** — пойти дальше. Зацепка остаётся в журнале, но не обновляется.
- **Забыть зацепку** — через N тиков без взаимодействия, она «остывает» (confidence decay).
- **Вернуться к зацепке позже** — если мир всё ещё порождает связанные события.

### IV.5. Зацепки и 17 секретов

17 секретов из `truth_state_tavern.json` — это **substrate**, не goal. Секреты — потенциальное содержание зацепок. Зацепка может вести к секрету, может вести в тупик, может вести к ложному следу.

**Игрок не видит «17 секретов».** Игрок видит «какие-то зацепки». Некоторые из них раскроют секреты. Некоторые — нет.

## V. Онтологический Onboarding (вместо механического)

### V.1. Принцип

> Начало должно быть почти хирургически простым.

Не объяснять 20 страниц правил. Не показывать список возможностей. Не давать tutorial-popup'ы с «WASD — движение».

**Обучать не кнопкам. Обучать онтологии игры:**

> мир что-то делает → ты это замечаешь → можешь вмешаться → мир реагирует.

### V.2. Старт игры — фазы

#### Фаза A: Пустота

```
        ENIGMA

   (чёрный экран, 3 секунды)
```

Затем fade in таверны. Игрок видит сцену. **Никаких подсказок.**

#### Фаза B: Тишина

```
   (мир живёт: NPC двигаются, разговаривают между собой,
    Торнин протирает стойку, Люся несёт поднос,
    Борко стоит у двери — всё без участия игрока)
```

Через 5-7 секунд — **первый cue**:

```
   (где-то у камина — обрывок разговора)
   
   Горан: ...я говорю тебе, эти коробки слишком тяжёлые
          для обычного товара.
   
   Орм:   Тише. Тут чужие.
```

Визуально: иконка `♪` над камином. Игрок ещё не знает, что это. Но он слышит.

#### Фаза C: Табличка

```
   Ты слышишь разговор.

   Нажми TAB, чтобы взаимодействовать с миром.
```

**Минимальная подсказка.** Не «WASD — движение», не «E — interact». Только: **TAB = войти в мир**.

#### Фаза D: Первое действие

Игрок жмёт TAB. Появляется строка ввода:

```
   [________________________________]
```

**Без подсказок.** Без примеров. Без списка команд.

Игрок может напечатать что угодно. Например:

> «Подойду поближе и послушаю, о чём они говорят.»

#### Фаза E: Понято

```
   ПОНЯТО
   
   Вы:
     подходите ближе к камину
     и слушаете разговор.
   
   [мир меняется...]
```

Происходит реальное:
- `PlayerIntentResolver` резолвит намерение → `SOCIAL_ACTION(MOVE+OBSERVE, target=fireplace_area)`
- `SpatialService` двигает игрока
- `PerceptualKernel` обновляется — игрок теперь в радиусе слышимости
- `EmbodiedTrace` от Горана и Орма становится `visible=True` для игрока
- Журнал получает запись в CLUES: «Горан и Орм обсуждали какие-то тяжёлые коробки»

#### Фаза F: Демонстрация следствия

После первого действия:

```
   Твои слова — это намерение.
   
   ENIGMA понимает, что ты хочешь сделать,
   а мир решает, что произойдёт.
   
   Люди здесь помнят.
```

**Короткая.** 3 строки. 5 секунд. Fade out.

#### Фаза G: Появление зацепки

```
   ┌─────────────────────────────┐
   │  НОВАЯ ЗАЦЕПКА              │
   │                             │
   │  Странный разговор о        │
   │  коробках у камина.         │
   │                             │
   │  Ты можешь:                 │
   │    • следовать за ней       │
   │    • проигнорировать её     │
   └─────────────────────────────┘
```

**Это единственный «tutorial-UI» за всю игру.** После него — больше никаких overlay-подсказок. Только мир и журнал.

#### Фаза H: Свобода

```
   Теперь ты сам решаешь,
   что делать дальше.
   
   Это не та игра, где есть
   правильный ответ.
   
   Это игра, где есть твой ответ.
```

Fade out. **Tutorial окончен.** Игрок свободен.

### V.3. Что важно

1. **Tutorial не симулирует успех.** Если игрок напечатал «убить Торнина» — игра не скажет «нельзя». Мир отреагирует: Борко подбежит, начнётся драка, игрока могут выгнать или убить.
2. **Tutorial не повторяется.** Если игрок пропустил фазу F — он не увидит её снова. Журнал сохранит всё.
3. **Tutorial минимален.** ~2 минуты от запуска до «теперь ты свободен». Не 20 минут dialog trees.
4. **Tutorial учит онтологии, не интерфейсу.** После него игрок знает: «мир замечает → я могу вмешаться → мир реагирует → люди помнят». Этого достаточно.

## VI. Пример emergent истории

### VI.1. Сценарий

Игрок начинает с personal goal: **«хочу заработать»**.

### VI.2. Траектория

| Tick | Что происходит | Почему |
|---|---|---|
| 0 | Игрок выбирает personal goal «разбогатеть» | Character creation |
| 5 | Игрок подходит к Торнину, спрашивает про работу | Player action: «Есть работа для меня?» |
| 6 | Торнин: «Принеси 10 золотых от Горана, он должен за неделю.» | `DecisionHub(tornin) → OFFER_WORK` |
| 15 | Игрок находит Горана, требует долг | Player action |
| 16 | Горан: «У меня нет. Спроси у Орма, он мне должен.» | `DecisionHub(goran) → DEFLECT` |
| 25 | Игрок идёт к Орму | Spatial movement |
| 26 | Орм: «Я заплачу, если ты принесёшь мне железо со склада Тени.» | `DecisionHub(orm) → COUNTER_OFFER` |
| 35 | Игрок идёт к складу Тени, подслушивает разговор | Player action: «подойду и послушаю» |
| 36 | Слышит, как Тень говорит кому-то: «Шёлк перехвачен, кто-то сдал.» | `SOCIAL_ACTION` + perception |
| 37 | **Новая зацепка**: «Тень ищет предателя» | Lead generated |
| 45 | Игрок возвращается к Орму, говорит: «Я знаю, что Тень ищет предателя.» | Player action:_INFORMATION_TRADE |
| 46 | Орм бледнеет: «Откуда ты знаешь?» | `DecisionHub(orm) → FEAR` |
| 47 | Орм: «Хорошо. Вот твоё железо. И забудь, что видел меня.» | `DecisionHub(orm) → BRIBE` |
| 55 | Игрок приносит железо Торнину | Player action |
| 56 | Торнин: «Хм. Странное железо. Откуда?» | Suspicion raised |
| 57 | Игрок: «От Орма.» | Truthful answer |
| 58 | Торнин: «Хорошо. Вот твои 10 золотых.» | `DecisionHub(tornin) → PAY` |
| 60 | **Игрок заработал 10 золотых.** | Immediate goal achieved |
| 100 | Игрок возвращается в таверну через неделю | Time skip |
| 101 | Тень подходит к игроку: «Борко сказал, что ты спрашивал про меня.» | `DecisionHub(shadow) → CONFRONT` |
| 102 | **Новая зацепка**: «Тень знает, что ты интересовался.» | Lead generated |
| 103 | Тень: «Может, ты и я — мы найдём общий язык. Или может, ты станешь проблемой.» | `DecisionHub(shadow) → THREAT+OFFER` |

### VI.3. Что произошло

- Игрок начал с простого immediate goal: заработать 10 золотых.
- Через цепочку каузальных interactions он оказался вовлечён в криминальную storyline.
- Тень теперь имеет `belief(player = potentially_dangerous_or_useful)`.
- Борко рассказал Тени — потому что Борко подкуплен Гораном, и Горан что-то заподозрил.
- **Эту историю никто не писал.** Она возникла из:
  - personal goal игрока («разбогатеть»)
  - существующих secrets (lusya_basement, shadow_investigation, borko_bribe, goran_contraband)
  - causal machinery (EpistemicStore, DecisionHub, EventBus)
  - интерпретации игрока (он решил торговать информацией)

### VI.4. Это и есть ENIGMA

История родилась. Ты её не написал. Но ты создал машину, которая позволила ей возникнуть.

## VII. Журнал как проекция субъективного опыта

### VII.1. Принцип

Журнал — **не quest log**. Журнал — **субъективная модель мира игрока**, проекция его `PlayerBeliefModel` и `ObservationLog`.

### VII.2. Структура журнала (4 секции)

#### PEOPLE

```
ЛЮСЯ
─────
Я думаю:  что она что-то скрывает.
Уверенность:  ██████░░░░ 61%
Последнее наблюдение:
  она резко сменила тему,
  когда я спросил о Тени.

Мои действия по отношению к ней:
  • спросил о происхождении (tick 14)
  • пригрозил (tick 32)

[если confidence ≥ 0.85 — помечается как "уверен"]
[если подтверждается каузально — "раскрыто"]
```

### VII.3. Принципы журнала

1. **Нет `secret_id` как результата player input.** Игрок не пишет «раскрыть lusya_basement». Секрет выводится из каузальности.
2. **Журнал — проекция `EpistemicStore` игрока.** `PlayerBeliefModel` уже частично это делает (см. `mvp_tavern_controller.py`), но UI должен быть redesigned.
3. **Confidence bar — явно.** Игрок видит, насколько он уверен. Это и есть открытие центральной фичи.
4. **Зацепки остывают.** Если игрок не возвращается к зацепке 80+ тиков — она переходит в «остывшие». Не удаляется, но визуально тускнеет.
5. **Гипотезы формулирует игрок.** Не игра. Игра только показывает evidence и обновляет confidence на основе новых наблюдений.

## VIII. Цикл игрока и нарративная петля

### VIII.1. Игровая петля (подробно)

```
1. НАМЕРЕНИЕ ИГРОКА
   • игрок печатает свободный текст
   • PlayerIntentResolver → IntentDTO
   • пример: «Хочу подслушать разговор Горана и Орма»

2. ДЕЙСТВИЕ
   • SOCIAL_ACTION event в EventBus
   • мир реагирует через существующий pipeline
   • SpatialService двигает игрока
   • PerceptualKernel обновляется

3. НАБЛЮДЕНИЕ
   • игрок видит/слышит результат
   • EmbodiedTrace от NPC становится visible
   • PlayerPerceptionDTO обновляется
   • в журнал добавляется clue

4. ИНТЕРПРЕТАЦИЯ
   • игрок сам осмысляет, что увидел
   • игрок может сформулировать гипотезу
   • PlayerBeliefModel.update_from_evidence

5. РЕШЕНИЕ
   • игрок решает, что делать дальше
   • следовать зацепке? проигнорировать? пойти к другому NPC?

6. ПОСЛЕДСТВИЕ
   • мир реагирует на решение
   • NPC beliefs обновляются
   • могут возникнуть новые зацепки
   • могут быть потеряны старые

7. НОВАЯ ВОЗМОЖНОСТЬ
   • новый cue, новый NPC, новый разговор
   • цикл замыкается
```

### VIII.2. Нарративная петля (подробно)

```
1. ЗАЦЕПКА
   • мир генерирует salient event
   • игрок замечает (или нет)

2. ЛЮБОПЫТСТВО
   • игрок заинтригован
   • формулирует immediate goal: «узнать, что это было»

3. ДЕЙСТВИЕ
   • игрок вмешивается: подходит, спрашивает, подслушивает

4. ОТКРЫТИЕ
   • игрок узнаёт что-то новое
   • confidence растёт (или падает — если был ложный след)

5. ОСЛОЖНЕНИЕ
   • новое знание порождает новые вопросы
   • или привлекает внимание других NPC
   • или меняет отношение к игроку

6. ИЗМЕНЕНИЕ СИТУАЦИИ
   • мир уже не тот, что был
   •NPC знают больше об игроке
   • игрок знает больше о мире

7. НОВАЯ ЗАЦЕПКА
   • из осложнения рождается новая возможность
   • цикл продолжается
```

### VIII.3. Когда петли ломаются

**Игровая петля ломается, если:**
- `PlayerIntentResolver` не понимает свободный текст (см. ТЗ №1 S199).
- Игрок не получает observable feedback на действие (нет `EmbodiedTrace`, нет journal update).
- Мир не реагирует (NPC не обновляют beliefs).

**Нарративная петля ломается, если:**
- Нет новых зацепок (мир «умер»).
- Все зацепки остыли (игрок игнорировал их слишком долго).
- Игрок не понимает, к чему ведёт его investigation (нет confidence bar в UI).

## IX. Условие завершения игры

### IX.1. Игрок решает сам

Нет «правильного» момента выхода. В любой момент игрок может:

> «Я выйду из таверны.»

Это **явное действие игрока**, не scripted event. Игрок может сделать это через 10 минут или через 10 часов.

### IX.2. End screen — статистика, не оценка

После выхода — экран со статистикой:

```
ТЫ ПОКИДАЕШЬ ТАВЕРНУ «СЕРЕБРЯНЫЙ ВОЛК»

Ты провёл здесь:  3 дня 14 часов
(286 игровых тиков)

ЗАЦЕПКИ
  заметил:  7 из ~15
  следовал:  4
  раскрыл:  2

СЕКРЕТЫ
  был уверен в:  3
  из них верных:  2
  из 17 возможных

ЛЮДИ
  у тебя были значимые контакты с:  5 из 6 NPC
  самые тёплые отношения:  Горан (trust 0.7)
  самые холодные:  Тень (trust 0.1, fear 0.8)

ТВОЯ ИСТОРИЯ
  (5 ключевых событий, которые ты пережил)
  
  1. Подслушал разговор о коробках (tick 7)
  2. Торнин поручил взыскать долг (tick 6)
  3. Узнал, что Орм связан с Тенью (tick 47)
  4. Тень подошёл к тебе с угрозой (tick 101)
  5. Ты продал информацию Борко (tick 150)

ЭПИЛОГ
  Через неделю после твоего отъезда
  в таверне произошёл пожар.
  
  (это generated из world state — не authored)
```

### IX.3. Нет «правильного» финала

- Раскрыл 0 секретов и просто пожил в таверне? Валидный playthrough.
- Раскрыл все 17? Тоже валидный, но редкий.
- Убил Торнина и был выгнан? Валидный.
- Стал любовником Люси и сбежал с ней? Валидный.

**Игра не оценивает.** Игра только показывает, что было.

## XI. KPI успеха

### XI.1. Качественные

- [ ] Новый игрок без инструкции через 10 минут имеет хотя бы одну observable реакцию мира на своё действие.
- [ ] Новый игрок через 30 минут может сформулировать, что он «пытается сделать» — без подсказок игры.
- [ ] 5 playtest'еров прошли кампанию — у каждого **разная** история в end screen.
- [ ] Хотя бы один playtest'ер раскрыл хотя бы один секрет — **без подсказок от игры**, только через собственное любопытство.
- [ ] Хотя бы один playtest'ер ушёл из таверны, не раскрыв ни одного секрета — и при этом не чувствует, что «проиграл».

### XI.2. Количественные

| KPI | Целевое значение |
|---|---|
| Длительность onboarding (фазы A-H) | ≤ 3 минуты |
| Время до первого observable consequence | ≤ 5 минут |
| Доля игроков, которые через 10 минут могут назвать цель | ≥ 70% |
| Доля игроков, которые через 30 минут хотят продолжать | ≥ 60% |
| Среднее число уникальных историй на 5 playtest'еров | ≥ 4 (т.е. почти у каждого своя) |
| `PlayerIntentResolver` accuracy (из ТЗ №1 S203) | ≥ 85% |

### XI.3. Главный тест

**«Test of Living Story»:**

1. Пять новых игроков, без инструкции, без знания проекта.
2. Каждый играет 60 минут.
3. После — каждый рассказывает свою историю своими словами.
4. Если истории **существенно разные** — ENIGMA работает.
5. Если истории **похожи** (одни и те же beats) — игра слишком scripted, не emergent.
6. Если истории **хаотичны без смысла** — игра слишком неструктурирована, игроки потеряны.

**Цель:** 5 разных историй, каждая из которых имеет нарративную связность.

## XII. План реализации

### XII.1. Очерёдность

```
ТЗ №1 S199-S203 (6-7 недель)  ──→  ТЗ №2 v2 (4-5 недель)
                                        ↓
                                  Неделя 1: NarrativeFrame + LeadDetector + Journal redesign
                                  Неделя 2: Onboarding фазы A-H
                                  Неделя 3: EndScreenStatsBuilder + emergent epilogue
                                  Неделя 4: Playtest'ы + tuning
                                  Неделя 5 (buffer): фикс на основе playtest'ов
```

**Итого: 10-12 недель от старта S199 до первого играбельного MVP.**

### XII.2. Контрольные точки

| Неделя | Что готово | Тест |
|---|---|---|
| 1 | `NarrativeFrame` config + `LeadDetector` + journal 4 секции | unit tests, ручной прогон |
| 2 | Onboarding фазы A-H на pygame | playtest 1 игрока |
| 3 | End screen + epilogue generator | playtest 3 игроков |
| 4 | Tuning на основе feedback | playtest 5 игроков |
| 5 | Buffer / fix | финальный smoke test |

### XII.3. Риски

1. **Игроки всё равно не понимают, что делать.** Mitigation: после фазы H добавить необязательную «подсказку от внутреннего голоса» — но только если игрок 60 секунд ничего не делает. Не обязательная.

2. **Зацепок слишком много / слишком мало.** Mitigation: tuning `salience threshold` в `LeadDetector`. Начать с conservative (мало зацепок) — добавлять по мере playtest'ов.

3. **End screen generiрует скучный epilogue.** Mitigation: epilogue generator должен использовать не только world state, но и `PlayerBeliefModel` — что игрок *думает*, что произошло, а не только что объективно произошло.

4. **5 playtest'еров — слишком мало для валидации.** Mitigation: это минимум для MVP. Дальше — Steam Next Fest demo с сотнями игроков.

## XIII. Определение первого настоящего ENIGMA-MVP (обновлённое)

> **Новый игрок запускает таверну, видит минимальную нарративную рамку («ты прибыл, через 3 дня праздник, что-то происходит»), выбирает personal goal, и через 5 минут замечает первую зацепку. Через 30 минут игрок сформулировал собственную immediate goal и пытается её достичь. Через 60 минут у игрока есть субъективная история, которую он может рассказать. End screen показывает, что эта история — одна из многих возможных.**

### XIII.1. Декомпозиция MVP-критерия

| Критерий | Зависимость | Тест |
|---|---|---|
| Игрок запускает таверну | PyInstaller bundle (UX-анализ) | smoke test на чистой VM |
| Видит нарративную рамку | `NarrativeFrame` config + `onboarding_screen.py` | manual playtest |
| Выбирает personal goal | Character creation screen | manual playtest |
| Замечает зацепку за 5 мин | `LeadDetector` + `PerceptualKernel` | automated: `test_first_lead_appears_within_5min.py` |
| Формулирует immediate goal за 30 мин | `PlayerIntentResolver` (ТЗ №1 S199) | IPT-PLAYER-001 |
| Достигает или не достигает её | `DecisionHub` + `SOCIAL_ACTION` (ТЗ №1 S201) | emergent, не scripted |
| Имеет субъективную историю за 60 мин | Журнал + epilogue | «Test of Living Story» (5 playtest'еров) |
| End screen показывает альтернативы | `EndScreenStatsBuilder` + epilogue generator | manual: разные playthrough'ы → разные end screens |

## Приложение D. Примеры personal goals

| Goal ID | Название | Описание (что видит игрок) | Механика |
|---|---|---|---|
| `wealth` | Разбогатеть | «Я пришёл сюда за золотом. Любой ценой.» | Tracking: total_gold_earned |
| `respect` | Стать уважаемым | «Я хочу, чтобы меня знали и уважали в этом месте.» | Tracking: avg_trust_with_npcs |
| `find_relative` | Найти родственника | «Я ищу следы своей сестры. Она была здесь три года назад.» | Hooks: NPC могут упоминать сестру в разговорах, если у них есть соответствующий belief |
| `revenge` | Отомстить | «Кто-то в этой таверне убил моего брата. Я узнаю кто.» | Tracking: any NPC с `belief(player = enemy_of_brother)` |
| `survive` | Просто выжить | «Мне некуда идти. Я просто хочу пережить зиму.» | Tracking: days_survived, hp_maintained |
| `observe` | Просто посмотреть | «Я путник. Я просто хочу посмотреть, что здесь происходит.» | No specific tracking — валиден любой playthrough |
| `open_shop` | Открыть мастерскую | «Я хочу открыть своё дело в этой деревне.» | Tracking: gold + relationships with crafters (Orm, Tornin) |

**Игрок может выбрать только один personal goal.** Это даёт вектор, не путь.

## Приложение E. Сравнение TZ2 v1 vs TZ2 v2

| Аспект | TZ2 v1 | TZ2 v2 |
|---|---|---|
| Концепция | Учит механикам | Учит онтологии |
| Onboarding | 11 stages, жёсткая последовательность | 8 фаз, ~2 минуты, потом свобода |
| Цель игрока | Раскрыть 17 секретов | Сформулировать и прожить собственную историю |
| 17 секретов | Checklist цели | Substrate для зацепок |
| Журнал | Quest log style | 4 секции: PEOPLE / RELATIONSHIPS / CLUES / SECRETS |
| Tutorial | Обязательный, жёсткий | Минимальный, потом свобода |
| Финал | «Раскрой все секреты» | Игрок сам решает, когда выйти |
| End screen | Не определён | Статистика + emergent epilogue |
| Personal goals | Не определены | 5-8 вариантов, выбор при character creation |
| Зацепки (leads) | Не определены | Центральная концепция |
| Authored narrative | Не определена | Минимальная рамка (3-5 строк) |
| Игрок учит | Кнопкам и командам | Онтологии игры |
