# ТЗ АУДИТ-01 — Честный IPT и гигиена доказательного слоя

> **Статус:** НА УТВЕРЖДЕНИИ МАСТЕРА. Последнее слово — за Мастером (§R.7).
> **Основание:** независимый аудит кода V.0.5.4.3.6 от 2026-10-15 (прогон IPT, полный сюит по чанкам, AST-замеры связности; среда: Linux, LLM-off, 3 ГБ RAM). Все факты этого ТЗ воспроизведены живым прогоном, не переписаны из отчётов.
> **Владение:** ветвь Б «Мир и платформа» (доказательный слой). Не трогает RE/AG1/W-код, не трогает зоны DLG/MOT.
> **Приоритет:** до DLG-0. Обоснование: IPT — источник правды для всех гейтов; пока счётчик IPT врёт (в сторону приукрашивания), каждый subsequent «гейт GREEN» наследует заниженную строгость.
> **Почему этого нет в роадмапе:** роадмап описывает продуктовые треки и слой маяков §9.13, но не инструментальность самого IPT. После исполнения находки ложатся в регистр §7.11 (Пакет 5) — один факт, одно место.

## 0. Границы и принципы

1. **Ноль изменений прод-поведения.** Все пакеты behavior-neutral; доказывается диф-тестами и полным сюитом. Трогается только тестовая/инструментальная поверхность и размещение файлов.
2. **Fail-loud вместо silent-skip.** Пропуск проверки — не успех. Это обобщение правила 4 §9.13 («падение по инфраструктуре маяком не считается») на весь доказательный слой: пропущенный инвариант обязан быть виден как пропуск, а не притворяться зелёным.
3. **Не ослаблять существующие проверки.** Ни один ассерт не удаляется, ни один инвариант не становится мягче. Строгость только растёт.
4. **Прецеденты канона:** IRON RIVER-комментарий `IPT.py:1986–1991` (осознанный выбор «skip, а не вечный красный» — сохраняется как семантика отдельного инварианта, но перестаёт искажать агрегат); XPASS→регресс §9.9; вердикт Мастера по test_p2_provenance (S-реестр, FR-11.2).

## Пакет 1 (P0) — IPT: честный счётчик и живой §14.1

### Факт (БЫЛО)

Чистый прогон `python backend/tests/IPT.py` на V.0.5.4.3.6 печатает `ИТОГО: 53 passed / 0 failed`. Из них **4 инварианта — вакуумно зелёные**:

| Инвариант | Что печатает | Якорь |
|---|---|---|
| INV-NPC-CARDINALITY | «SpatialRegistry не загружен.» → `passed=True` | `IPT.py:1530` |
| INV-EVENT-CARDINALITY | «SpatialRegistry не загружен.» → `passed=True` | `IPT.py:1842` |
| **INV-TICK-CARDINALITY (Закон Единичного Времени §14.1)** | «артефакт отсутствует, writer'а в дереве нет — тест пропущен.» → `passed=True` | `IPT.py:1992–1996` |
| INV-REPLAY-DETERMINISM | `WARNING`, «Replay test skipped due to …» → `passed=True` | `IPT.py:1604` |

Причина вакуума: все три CARDINALITY-инварианта начинаются с `SpatialRegistry.get_or_load(world.campaign_id)`, артефакт `compiled/spatial_registry.json` не существует и **не имеет writer'а в дереве** (grep-факт самого IRON RIVER-комментария; проверено 2026-10-15: `build_graph.py` в корне генерирует только `docs/ARCHITECTURE_FLOW_GENERATED.md`, каталоги `backend/test_data/compiled/` и `config/compiled/` отсутствуют).

Счётчик считает пропуски как успехи: `passed = sum(1 for r in results if r.passed)` (`IPT.py:2402`), строки ИТОГО — `IPT.py:2418/2424/2427`, exit code зависит только от `failed > 0` (`IPT.py:2431`).

**Следствие:** в МЕТА MUTATIONS и шапке роадмапа «Базлайн: IPT 53/53» — фактически «49 проверено + 4 пропущено». Закон §14.1 (один тик = один сдвиг времени независимо от числа локаций) сейчас не проверяет никто.

### IPT-1.1 — Статус SKIPPED в InvariantResult

**СТАЛО:** `InvariantResult` получает различение исходов (поле `status: PASSED | SKIPPED | FAILED` или эквивалентный флаг `skipped: bool`; поле `passed` сохраняется для обратной совместимости вызовов). Пропуск выставляет `SKIPPED` и **обязан** нести в `message` причину пропуска поимённо (какого входа не хватает). Счётчик ИТОГО печатает три числа: `X passed / Y skipped / 0 failed`, а после списка результатов — поимённый перечень skipped с причинами. Exit code не меняется (skip не роняет прогон), но в отчёт сессии и МЕТА идёт пара «X passed / Y skipped».

**Гейт IPT-1.1:** на чистом чекауте прогон IPT печатает `Y skipped > 0` с поимённым разбором; попытка записать в МЕТА «IPT 53/53» при Y>0 — невозможно синтаксически (формат «X/Y + skipped Z»).

### IPT-1.2 — Вход для CARDINALITY-тройки: registry in-memory

**СТАЛО:** TestWorld создаёт SpatialRegistry **каноническим API класса** (factory/фикстура — не подмена объекта, не мок-наследник) на мире из ≥2 локаций. Инварианты получают живой вход; skip-ветки `:1529–1530 / :1841–1846 / :1985–2006` сохраняются как fail-safe для сред без кампании (семантика IRON RIVER уважена), но в базлайне `skipped=0` для этой тройки.

**Гейт IPT-1.2 (оживление §14.1):** мир из N≥2 локаций, один `idle_tick` → `game_time_seconds` сдвинулся ровно на `GAME_TICK_INTERVAL_SECONDS` при любом N. Контрольный диф: N=2 vs N=5 — дельта времени идентична. INV-TICK-CARDINALITY зелёный **по существу**, не по пропуску.

**Развилка вердикта Мастера (выбрать одно):**
- **(а)** TestWorld-фикстура строит registry in-memory из карты тестовой кампании (минимальный дифф, артефакт-файл остаётся не нужен);
- **(б)** появляется недостающий writer артефакта — компиляция кампании (естественное место: save-контур Map Editor S349 / старт кампании), инварианты читают его как раньше. Дороже, но закрывает и прод-потребности загрузчика.

### IPT-1.3 — INV-REPLAY-DETERMINISM: WARNING-ветка становится честной

**СТАЛО:** except-ветка `:1604` возвращает `SKIPPED` с причиной (какой шаг реплея недоступен) вместо `WARNING, passed=True`. Основной путь инварианта не трогается; если пропуск воспроизводится в базлайне — это отдельная находка с якорем, а не молчаливая норма.

**Гейты пакета 1:** ruff 0; AST-линтеры PASS; полный IPT-прогон: `X passed / Y skipped / 0 failed`, Y поимённо; полный pytest-сюит — счёт passed не уменьшился, новых RED нет; compileall OK.

## Пакет 2 (P1) — Известный RED перестаёт приучать к красному

### Факт (БЫЛО)

`tests/gameplay/test_p2_provenance_origin_vs_seeded` падает открытым кодом в каждом прогоне (13 ≠ 16: канон `config/npc/chronicles/guard_borko.json` по FR-11.2 «канон вместо legacy» затирает 3 origin-воспоминания Борко; вердикт Мастера — файл сохраняется КАК ЕСТЬ, гейт дорабатывает владелец CCH-4). Пока RED живёт как обычный FAILED, сюит нормализует красный: четвёртый лишний RED от неизвестного дефекта психологически неотличим от «того самого».

### СТАЛО

Тест помечается `@pytest.mark.xfail(strict=False, reason="ROADMAP-вердикт Мастера FR-11.2: канон guard_borko вместо legacy; владелец CCH-4")`. В отчёте — честный `xfailed`. Когда владелец CCH-4 починит гейт — тест подаст **XPASS** (сигнал по §9.13-2: снять xfail → регресс §9.9 → запись §10).

**Граница:** сам тест и канон-файл Борко не изменяются. Меняется только маркер.

**Гейт пакета 2:** полный сюит показывает 0 FAILED, все ожидаемые красные — в xfailed с заполненным reason; reason содержит roadmap-ID/вердикт (правило 1 §9.13: «тест без ID — не vision, а баг-репорт» — здесь ID = вердикт FR-11.2 + владелец).

## Пакет 3 (P1) — Инфраструктурная нейтральность GC-11

### Факт (БЫЛО)

`tests/gameplay/test_gc11_relationship_causality.py` — два теста (`test_gc11_compliment_writes_nonzero_ram`, `test_gc11_event_shifts_decision_landscape`) падают при LLM-off: диагноз напечатан в самих ассертах («NARRATIVE-обрыв при LLM-off», `:80`, `:114`). На машине Мастера (LLM жив) тесты зелёные — расхождение подтверждено независимым прогоном 2026-10-15. Сторонний/CI-прогон видит 2 лишних RED, которых нет в канонной среде.

### СТАЛО (развилка вердикта Мастера)

- **(а) Явный skipif:** `@pytest.mark.skipif(not llm_alive(), reason="INFRA: GC-11 требует живого LLM (NARRATIVE-канал); правило §9.13-4")` — дёшево, честно, но тест перестаёт ловить LLM-off-регрессии этого пути;
- **(б) F5-путь:** тест переводится на MockProvider (лаборатория уже умеет) — тест детерминирован в любой среде и проверяет тот же каузальный шов. Дороже, ценнее.

**Гейт пакета 3:** полный сюит в среде без LLM даёт тот же счёт, что и с LLM, минус явно помеченные skip'ы с reason; в среде с LLM счёт идентичен канонному.

- **Граница:** файлы, на которые ссылается канон (протоколы S-сессий в reports/, dna_history.jsonl, артефакты SUPERBOX-приёмок), не переименовываются и не удаляются — только перенос с фиксацией в §10, если меняется путь.
