# TZ_SCI-01 — Научный эксперимент «Верность самообъяснения NPC» (Self-Explanation Fidelity)

path: /project/docs/Почти Актуальные TZ/TZ_SCI-01_Self_Explanation_Fidelity.md
Назначение: Техническое задание на воспроизводимый эксперимент, который проверяет, насколько объяснения NPC своих решений (Слой 10 / NL-11) совпадают с реальными причинами решений (DecisionTrace, трек MOT), и сравнивает это с LLM-агентом без причинной трассы. Результаты сохраняются только в md-артефактах.
Зависимости: трек MOT (§18: MOT-3, MOT-6, MOT-7), трек NL-01 (§12: NL-11, NL-9), методология SUPERBOX и протокол fresh-extraction (статья, §5.1), `architecture/flags.yaml`, реестр COV-0, F5-лаборатория, IPT.
Основные сущности: `ExperimentProfile`, `AblationRunner`, `ExplanationAnnotator`, `ReportWriter`, артефакты `PREREG.md` / `RUN_<id>.md` / `RESULTS.md` / `AUDIT_RED.md`.

## 1. Мотивация и честная позиция

1. **Что уже сделано и доказано (статья v1):** детерминированное эпистемическое ядро; убеждения как состояние, а не текст; исполняемые контракты SUPERBOX. Позиционирование статьи — «системный вклад, не новая теория» **[C]**.
2. **Что осталось недоказанным:** статья v1 не сравнивает архитектуру с baseline и ограничена одной локацией и 6 NPC **[C]** (раздел Limitations статьи).
3. **Что обещают MOT и NL-11:** мотив записывается в момент решения (MOT-L1), NPC видит его только через ограниченный интроспективный доступ (MOT-L2, MOT-7), самообъяснение может быть искренне ошибочным (NL-INV-SELF-INTERP) **[C]**.
4. **Научная возможность:** ни один из этих механизмов нельзя назвать «доказанным», пока не измерено, **насколько самообъяснение соответствует реальной причине**. Для LLM-агентов такая причина обычно недоступна; у ENIGMA она записана. Это шанс на измеримый, а не декларативный результат.
5. **Позиция честности (наследуется от статьи):**
   - не заявляем новую психологическую теорию;
   - не заявляем «человекоподобность» и полную Theory of Mind;
   - красные вердикты публикуем (`AUDIT_RED.md`);
   - различаем **доказательство** и **проверку конструкции** (см. §5.4).

## 2. Исследовательские вопросы и гипотезы

### 2.1. Центральный вопрос (RQ0)

> Можно ли в игровой симуляции с записанной причинной трассой **измерить**, насколько объяснение агента совпадает с реальной причиной его решения, и отличается ли это от LLM-агента без трассы?

### 2.2. Частные вопросы

- **RQ1 — Валидность трассы.** Совпадает ли `DecisionTrace` с причинностью, выявленной независимым методом (контрфактическая абляция фактора)? *Без положительного ответа остальное теряет смысл: трасса — «истина движка» только если проверена.*
- **RQ2 — Верность структурного самообъяснения.** Насколько структурный выход `MotiveAccess` (до LLM) соответствует трассе; какие типы ошибок возникают (§5.1).
- **RQ3 — Верность поверхностной речи.** Сохраняет ли LLM-озвучка структурный выход (разрыв «структура → текст»)? Измеряется на уровне текста.
- **RQ4 — Смесь против лесенки.** Влияет ли режим MOT-5 (смесь мотивов) на полноту самообъяснения по сравнению с лесенкой причин?
- **RQ5 — Сравнение с baseline.** Как соотносятся показатели верности ENIGMA и LLM-only агента, измеренные **одним и тем же** интервенционным протоколом?

### 2.3. Гипотезы (замораживаются в `PREREG.md` до первого финального прогона)

| ID | Гипотеза (направление) | Тип | Что считается опровержением |
|----|------------------------|-----|------------------------------|
| H1 | Топ-мотив трассы входит в множество причин, выявленных абляцией, существенно чаще случайного | валидность трассы | доля совпадений ≤ порога θ₁ |
| H2 | Структурное самообъяснение ENIGMA имеет MR < MR(LLM-only) при одинаковом протоколе | сравнение | MR(ENIGMA) ≥ MR(LLM-only) |
| H3 | Разрыв «структура → текст» (RQ3) мал: LLM не добавляет конфабуляций сверх структурного выхода | верность озвучки | прирост конфабуляций > θ₃ |
| H4 | Режим «смесь» повышает Cause Recall при одновременных мотивах относительно лесенки | эффект MOT-5 | разница CR ≤ 0 или не выше θ₄ |
| H5 | Ошибки самообъяснения ENIGMA содержательно объяснимы правилом доступа (trace → access), а не шумом | объяснимость | доля необъяснимых ошибок > θ₅ |

Пороги θ₁…θ₅ **не пишутся в код и не выбираются после данных**: они фиксируются в `PREREG.md` на этапе SCI-6 (по результатам пилота и power-анализа), закон MOT-L8 «числа — не в теле функции» **[C]** распространяется на эксперимент.

## 3. Входные условия запуска (Entry Gate)

Эксперимент **не стартует**, пока не выполнено всё ниже. Это гейт, не рекомендация.

1. **Вердикт Мастера по треку MOT.** В дорожной карте §18 помечен DRAFT: «до вердикта разделы не являются основанием для старта работ» **[C]**. Значит, и это ТЗ без вердикта — только план.
2. **Пакеты закрыты своими гейтами:**
   - MOT-3 (DecisionTrace, GC-52 replay-exactness);
   - MOT-4 (исход → trace, GC-53) — желательно, нужен для сценариев с prediction error;
   - MOT-5 (смесь, GC-54) — **нужен для RQ4**; без него RQ4 исключается из эксперимента, а не подменяется;
   - MOT-6 (читатели: EXPLAIN, GC-55);
   - MOT-7 (MotiveAccess, GC-56).
3. **Слой 10 / NL-11:** самообъяснение реализовано; GC-49 (расхождение самообъяснений NPC) зелёный **[C]**.
4. **База доказательств зелёная:** IPT, FULL pytest, ruff/AST-линтеры; перепроверка критичных инвариантов отдельно, не только агрегата IPT (TZ_AUDIT-01 §1.3 предупреждает, что агрегат может вводить в заблуждение) **[C]**.
5. **Требование к выходу MOT-7 (проверяется в SCI-0):** `MotiveAccess` обязан отдавать **структурный** результат (перечень «процитированных» мотивов + режим: ясно / смутно / скрыто от себя / ложно приписано) **до** вербализации. Если его нет — это блокер, а не повод анализировать текст «на глаз» **[H]**.
6. **Stop-rule (аналог §9.11):** если измерение невозможно без ручной подстановки причин в промпт или без правки рантайма — канал не замкнут; эксперимент откладывается.

## 4. Дизайн эксперимента

### 4.1. Общая схема (внутрисубъектная, контрфактическая)

```
Для каждого сценария S, каждого агента A, каждого seed:
  1. Базовый прогон  -> решение d (intent, target) + trace (ENIGMA)
  2. Запрос объяснения -> E_struct (структура) и E_text (речь)
  3. Для каждого кандидата-фактора f из F(S):
       контрфактический прогон с нейтрализованным f (остальное и seed — те же)
       f причинен для d  <=>  решение изменилось
  4. Сопоставление: C(d) (причины по абляции) vs E(d) (цитируемые причины)
  5. Запись в raw/*.jsonl + отчёт md
```

### 4.2. Семейства сценариев

Каждое семейство параметризуется (seed, архетип, черты, давление), минимум по два варианта сложности. Числа параметров — в PREREG.

| ID | Сценарий | Что проверяет | Опора в существующем коде/доках |
|----|----------|---------------|----------------------------------|
| SCN-A | «Голод + обида» одновременно | смесь против лесенки (RQ4), множественные причины | MOT-5, GC-54 **[C]** |
| SCN-B | Расширение «Горан»: кража → свидетели → решение → вопрос «почему?» | сквозная петля с реальной эпистемикой | `goran_vertical_slice_test` (12/12) **[C]** |
| SCN-C | Трудное решение при низком self-restraint / высоком стрессе | искренняя ложная атрибуция (доступ) | MOT-7, GC-56 **[C]** |
| SCN-D | Решение «по причине, которой у агента нет в контексте» (ловушка конфабуляции) | отличие конфабуляции от ошибки атрибуции | NL-INV-MODES **[C]** |

Размер мира в v1: **одна локация, ≤ 6 NPC** (как статья). Масштабирование — вне scope, фиксируется как ограничение.

### 4.3. Условия (arms)

| Код | Условие | Назначение |
|-----|---------|------------|
| **E-FULL** | ENIGMA: MOT-5 смесь ON, MotiveAccess ON | основное условие |
| **E-LADDER** | ENIGMA: лесенка (MOT-5 OFF), MotiveAccess ON | RQ4 |
| **C-POS** | MotiveAccess = «полный доступ» | положительный контроль: MR обязан быть ≈ 0 |
| **C-NEG** | MotiveAccess = перемешанный/случайный | отрицательный контроль: E не должно коррелировать с C |
| **B-LLM1** | LLM-only: тот же persona-промпт и журнал наблюдений, та же модель/температура, k сэмплов | baseline 1 |
| **B-LLM2** | LLM + «поток памяти» (в духе generative agents) | baseline 2 |
| **B-CEIL** *(опционально)* | та же схема на более сильной модели | «потолок»: нужен только для ответа «а если модель побольше?»; **не рантайм проекта**, только измерение |

Замечание: в B-LLM1/2 «причины» не записаны, поэтому C(d) для них получается **только интервенционно** (§4.4). Это единый протокол для всех условий.

### 4.4. Интервенционный протокол (источник «истины» для сравнения)

1. Определить множество кандидат-факторов `F(S)` (голод, обида, привязанность, угроза, мнение о ком-то, …) **в PREREG до прогона**.
2. Для каждого `f ∈ F(S)` существует процедура нейтрализации `neutralize(f)`: для ENIGMA — изменение входа мира/состояния через штатный путь (без правки кода), для LLM-baseline — удаление/нейтрализация соответствующего факта из журнала наблюдений.
3. `f ∈ C(d)` ⇔ при `neutralize(f)` изменилось решение (intent **или** target) при том же seed.
4. Для LLM-baseline решение недетерминировано: на каждый вариант запускается k прогонов, `f ∈ C(d)` определяется по статистически значимому сдвигу распределения решений (критерий — в PREREG).
5. **Кросс-проверка трассы (RQ1):** для ENIGMA сравниваем C(d) по абляции с мотивами из `DecisionTrace` (§5.1, метрика `TraceValidity`).

### 4.5. Измерение объяснения: два уровня

- **Структурный (до LLM):** выход `MotiveAccess` → множество `E_struct`. Детерминирован. Для baseline структурного уровня нет — только текстовый.
- **Текстовый (после LLM):** `E_text` — множество факторов, извлечённых из текста объяснения аннотатором (§5.3).
- Разрыв `E_struct → E_text` измеряется как **verbalization fidelity** (RQ3).

### 4.6. Воспроизводимость

1. Протокол fresh-extraction (чистая распаковка релиза на каждый класс прогонов) **[C]** — обязателен: песочница сохраняет состояние между запусками, и накопленная история переворачивает вердикты (статья §5.9).
2. Фиксируются и пишутся в каждый `RUN_<id>.md`:
   - `version.txt` и git-коммит; sha256 `architecture/flags.yaml`;
   - sha256 GGUF-модели, версия llama.cpp, температура, `context_size`, число воркеров;
   - список seeds; профиль флагов (`ExperimentProfile`);
   - режим сериализации (DEBT-QUIESCE — асинхронный недетерминизм остаётся открытым долгом **[C]**; эксперимент идёт в сериализованном режиме и сообщает, что это ограничение).
3. Прогон «LLM выключен»: структурный уровень и трасса побайтно идентичны (MOT-L1, GC-52) **[C]**.
4. Эксперимент не включает ROLLOUT-PENDING-флаги вне COV-0-протокола: используется отдельный `ExperimentProfile`, а **дефолты `flags.yaml` не меняются** **[C]**.

### 4.7. Объём выборки и статистика

1. **Пилот:** небольшое N на ячейку — только чтобы оценить дисперсию и отладить пайплайн; результаты пилота **не публикуются как выводы**.
2. **Финал:** N по power-анализу (расчёт — задача SCI-6; цифра фиксируется в PREREG).
3. Интервалы: Wilson для долей, bootstrap 95% для разностей; размер эффекта (odds ratio или Cliff's δ) — **обязателен рядом с p-значением**.
4. Поправка на множественные сравнения (Holm) для H1–H5.
5. **Pre-registration:** гипотезы, метрики, пороги θ, правило остановки и план анализа замораживаются в `PREREG.md` **до** финального прогона; хэш файла записывается в `RUN`-отчёты.
6. Негативные и нулевые результаты публикуются наравне с позитивными.

## 5. Метрики

### 5.1. Определения (формулы — Приложение A)

- **C(d)** — причины по абляции; **E(d)** — цитируемые в объяснении; **T(d)** — мотивы из трассы (только ENIGMA).
- **Cause Recall (CR)** — доля реальных причин, названных в объяснении.
- **Misattribution Rate (MR)** — доля названных причин, которые **присутствовали в контексте, но не были причинны**.
- **Confabulation Rate (CFR)** — доля названных причин, которых **не было во входах агента вообще**.
- **Omission Rate (OR)** = 1 − CR.
- **Dominant-Cause Hit (DCH)** — назван ли главный по вкладу мотив.
- **TraceValidity (RQ1)** — доля решений, где мотивы трассы согласуются с C(d) по абляции.
- **Verbalization Fidelity (RQ3)** — согласие `E_text` с `E_struct`.
- **Explainability of Errors (H5)** — доля ошибок, предсказуемых правилом `MotiveAccess` из trace и состояния агента.
- **Mode Distribution** — распределение исходов NL-11: рационализация / «просто так» / обвинение обстоятельств / приписывание мотива другому **[C]**.

### 5.2. Соответствие законам проекта

- Искреннее заблуждение ≠ ложь (NL-INV-MODES): в v1 NL-12 (активная ложь) **отключён и вне scope** **[C]**; любая ложь в данных = дефект, а не результат.
- Causal-debugger для игрока запрещён (NL-11): эксперимент читает трассу **только в тестовом контуре**, не через игровой интерфейс **[C]**.
- NL-INV-NO-NUMBERS: числа скрытых переменных не озвучиваются в тексте; аннотатор не должен «подсказывать» себе значениями **[C]**.

### 5.3. Аннотатор объяснений

1. **Уровень 1 (детерминированный):** словарь мотивов + лемматизация (в проекте уже есть pymorphy3 **[C]**), правила отрицания («не из-за голода»).
2. **Уровень 2 (независимый LLM-аннотатор):** другая модель/промпт, чем у озвучки, чтобы не разделять смещения.
3. **Уровень 3 (человек):** случайная подвыборка размечается вручную (минимум двумя разметчиками, если возможно привлечь не только автора); измеряется κ Коэна между всеми уровнями.
4. Расхождения аннотаторов не «разрешаются молча»: публикуются доли согласия, спорные случаи уходят в `AUDIT_RED.md`.

### 5.4. Что здесь доказательство, а что проверка конструкции

Обязательный раздел отчёта. Без него результат легко завысить.

| Результат | Статус |
|-----------|--------|
| Доступ деградирует при низком self-restraint → MR растёт | **проверка конструкции** (так задумано в MOT-7), не открытие; показываем как manipulation check |
| TraceValidity (RQ1) | **эмпирический результат**: трасса может оказаться неверна |
| Verbalization fidelity (RQ3) | **эмпирический результат**: озвучка может искажать структуру |
| Сравнение CR/MR с LLM-baseline | **эмпирический результат**, зависит от модели и промптов |
| «У baseline нет трассы» | **свойство архитектуры**, не результат измерения |

## 6. Хранение результатов в md

### 6.1. Структура каталога (предложение; утверждает Архитектор/Мастер)

```
docs/experiments/SCI-01/
  README.md                 # индекс прогонов, ссылки, статус
  PREREG.md                 # заморожено до финала; хэш в каждом RUN
  RUN_<YYYYMMDD>_<id>.md    # один файл на прогон, append-only
  RESULTS.md                # агрегат по финальным прогонам
  AUDIT_RED.md              # все красные вердикты и расхождения аннотаторов
  raw/
    <run_id>_decisions.jsonl
    <run_id>_explanations.jsonl
    <run_id>_ablations.jsonl
    MANIFEST.sha256         # хэши сырых файлов
```

### 6.2. Правила

1. **Append-only:** `RUN_*.md` не перезаписываются; повторный прогон = новый файл.
2. Любая цифра в `RESULTS.md` ссылается на `run_id` и на строку/файл в `raw/`.
3. `ReportWriter` формирует md **программно** из `raw/`, без ручной вставки чисел.
4. В каждом отчёте обязательны блоки: конфигурация, воспроизводимость (§4.6), результаты по гипотезам, контрольные условия, красный аудит, ограничения.
5. Раздел «Красные вердикты» **не может быть пустым без письменного обоснования** (принцип статьи: отчёт, который всегда зелёный, непроверяем).
6. Шаблоны — Приложения B–D.

## 8. Угрозы валидности и ограничения

1. **Циркулярность:** трасса — «истина» самого движка. *Смягчение:* RQ1 + независимая абляция; baseline измеряется тем же протоколом без трассы.
2. **Автор системы = автор сценариев.** *Смягчение:* PREREG до данных; сценарии SCN-D включают ловушки, которые автор не оптимизировал; по возможности внешний разметчик.
3. **Зависимость от аннотатора.** *Смягчение:* три уровня + κ; публикация расхождений.
4. **Один мир / ≤ 6 NPC.** Масштаб не измерен. *Смягчение:* явное ограничение; SCN-варианты разной сложности.
5. **Эвристически подобранные константы** (в т. ч. множитель травмы ×6 не из данных) **[C]**. *Смягчение:* анализ чувствительности по ключевым константам — как отдельный подэксперимент SCI-7.
6. **Зависимость от модели озвучки.** Результаты RQ3/RQ5 привязаны к конкретным GGUF-моделям. *Смягчение:* фиксируем хэши; B-CEIL как проверка устойчивости.
7. **Антропоморфная интерпретация.** Запрещены формулировки «NPC понимает себя / осознаёт»; допустимо: «объяснение соответствует/не соответствует записанной причине».
8. **Асинхронный недетерминизм (DEBT-QUIESCE)** **[C]** — сериализованный режим, явное предупреждение в отчёте.
9. **Вне scope v1:** активная ложь (NL-12); исследование игроков (воспринимаемая правдоподобность); масштаб > 6 NPC; сравнение с человеческими данными.

## Приложение A. Формулы

Пусть для решения `d`: `F` — кандидат-факторы; `C ⊆ F` — причинные по абляции; `E ⊆ F ∪ X` — цитируемые (`X` — факторы, которых не было во входах агента); `P ⊆ F` — присутствовавшие во входах; `T` — мотивы трассы.

```
CR   = |E ∩ C| / |C|                    (если |C| = 0 -> не определена, исключается и считается отдельно)
MR   = |(E ∩ P) \ C| / |E|              (если |E| = 0 -> не определена)
CFR  = |E ∩ X| / |E|
OR   = 1 - CR
DCH  = 1, если доминирующий по вкладу фактор ∈ E, иначе 0
TraceValidity = доля d, где top-k(T) ∩ C ≠ ∅   (k и порог — в PREREG)
VerbFid = |E_struct ∩ E_text| / |E_struct ∪ E_text|   (Жаккар)
ErrExpl = доля ошибок E vs C, предсказанных правилом MotiveAccess по (trace, state)
```

Агрегация: по агентам внутри ячейки, затем по seeds; доверительные интервалы — Wilson/bootstrap.
