## ТЗ-10: Аффективная система — подключение чтения

**Статус:** ❌ МЁРТВАЯ | **Критичность:** CRITICAL | **Волна:** 1-2

---

### Суть проблемы одной строкой

Вся аффективная система **записывает** травмы и эмоции, но **никто их не читает**. Плюс один баг вызовет NameError в runtime.

---

### Баг 1 (CRITICAL): `apply_conditioning()` — переменные вне scope

**Файл:** `backend/app/services/affect.py` строки 306-316

```python
# СЕЙЧАС (сломано):
async def scan_affective_resonance(npc_state, event, ...):
    _action = event.get("action")      # локальная переменная scan_affective_resonance
    _target = event.get("target")      # локальная переменная scan_affective_resonance
    ...
    if will_response.identity_damage > 0.2:
        apply_conditioning(...)        # вызывает вложенную функцию
    ...

def apply_conditioning(npc_state, resonance, will_response):
    ...
    if resonance.trigger_strength < 0.1:  # строка 306
        logger.info(f"Action: {_action}")  # ← NameError! _action не в scope
    ...
    npc_state.affective_imprints.append(   # строка 315
        AffectiveImprint(trigger=_action)   # ← NameError! _action не в scope
    )
```

**Что происходит:** `_action` и `_target` — локальные переменные функции `scan_affective_resonance()`. Функция `apply_conditioning()` их не видит. Если `identity_damage > 0.2` и `trigger_strength < 0.1` — **краш NameError**.

**Как чинить:**
```python
# ВАРИАНТ А: сделать _action и _target параметрами apply_conditioning()

def apply_conditioning(npc_state, resonance, will_response, action: str, target: str):
    ...
    if resonance.trigger_strength < 0.1:
        logger.info(f"Action: {action}")
    ...
    npc_state.affective_imprints.append(
        AffectiveImprint(trigger=action, target=target, ...)
    )

# В scan_affective_resonance() — передать:
if will_response.identity_damage > 0.2:
    apply_conditioning(npc_state, resonance, will_response, _action, _target)
```

### Баг 2 (HIGH): Весь affective pipeline — write-only

**Файлы для поиска:** `backend/app/services/affect.py`, `backend/app/services/affective/*.py`, `backend/app/services/npc/npc_tick_pipeline.py`

Вот что реализовано, но **нигде не вызывается** из основного конвейера:

| Функция | Файл | Что делает | Вызывается? |
|---------|------|-----------|-------------|
| `scan_affective_resonance()` | affect.py | Определяет, резонирует ли событие с травмой | ❌ Нет |
| `distort_pressure()` | affect.py | Искажает давление через призму травмы | ❌ Нет |
| `apply_conditioning()` | affect.py | Записывает AffectiveImprint | ❌ Нет (плюс NameError) |
| `integrate_affective_pressure()` | affective_integrator.py | Интегрирует внешнее давление в эмоцию | ❌ Нет |
| `derive_affective_pressure()` | pressure_derivation.py | Вычисляет давление из контекста | ❌ Нет |
| `resolve_emotion_transition()` | emotion_transition.py | Переход между эмоциями | ❌ Нет |

**Как чинить — подключить в `npc_tick_pipeline.py`:**

```python
# В npc_tick_pipeline.py, после фазы восприятия (interpretation),
# добавить блок аффективной обработки:

async def _process_affective(self, npc_state: NPCState, event, ctx) -> NPCState:
    """Фаза: аффективная обработка (ПОДКЛЮЧИТЬ)"""
    
    # 1. Проверить резонанс события с травмами NPC
    resonance = await scan_affective_resonance(npc_state, event, ctx)
    if resonance is None:
        return npc_state  # нет резонанса — пропустить
    
    # 2. Исказить давление через призму травмы
    distorted_pressure = distort_pressure(ctx.current_pressure, resonance)
    
    # 3. Обновить эмоцию NPC
    new_emotion = resolve_emotion_transition(
        current_emotion=npc_state.emotion,
        pressure=distorted_pressure,
        affective_load=npc_state.affective_load,
    )
    npc_state.emotion = new_emotion
    
    # 4. Если событие травмирующее — записать AffectiveImprint
    will_response = compute_will_response(npc_state, resonance)
    if will_response.identity_damage > 0.2:
        apply_conditioning(
            npc_state, resonance, will_response,
            action=event.get("action"),    # ← фикс NameError
            target=event.get("target"),    # ← фикс NameError
        )
    
    # 5. Интегрировать внешнее давление
    npc_state.affective_load = integrate_affective_pressure(
        npc_state.affective_load, distorted_pressure
    )
    
    return npc_state
```

### Баг 3 (HIGH): `shock_impulse` из боя не доходит до психологии

**Файл:** `backend/app/services/combat/impact_engine.py` строка ~157

```python

# impact_engine.py генерирует shock_impulse:

# Но НИКТО этот shock_impulse не читает.
# PhysiologyDecayHandler его затухает, но эмоций не меняет.
# Получается: удар = боль + HP урон, но НИКАКОГО страха/стресса.
```

**Как чинить — мост через EventBus:**

```python
# Шаг А: В impact_engine.py — после генерации shock_impulse,
# опубликовать событие:
if result.shock_impulse > 0.1:
    await self.event_bus.publish(CombatShockEvent(
        npc_id=target_npc_id,
        shock_impulse=result.shock_impulse,
        source="combat_impact",
    ))

# Шаг Б: Создать подписчика (в events/reaction_subscriber.py 
# или новом affective_combat_bridge.py):
class CombatShockAffectiveBridge:
    """Мост: боевой шок → аффективная система"""
    
    async def on_combat_shock(self, event: CombatShockEvent):
        npc_state = self.state_store.get(event.npc_id)
        
        # Преобразовать shock в стресс и страх
        npc_state.stress = min(1.0, npc_state.stress + event.shock_impulse * 0.3)
        
        # Если шок сильный — сменить эмоцию на страх
        if event.shock_impulse > 0.5:
            npc_state.emotion = EmotionTag.FEARFUL
        
        # Интегрировать как аффективное давление
        npc_state.affective_load = integrate_affective_pressure(
            npc_state.affective_load,
            source_pressure=event.shock_impulse,
            source_type="combat_shock",
        )
        
        # Записать AffectiveImprint (боевая травма)
        if event.shock_impulse > 0.7:
            npc_state.affective_imprints.append(
                AffectiveImprint(
                    trigger="combat",
                    target="aggressor",
                    pain_signature=event.shock_impulse,
                    fear_signature=event.shock_impulse * 0.8,
                    trigger_strength=event.shock_impulse,
                )
            )
```

### Баг 5 (MEDIUM): `AffectiveDecayHandler` работает с dict, не с NPCState

**Файл:** `backend/app/services/affective/affective_decay_handler.py` строки 39-62

```python

npc.get("affective_load") # ← dict access
npc.get("emotion")        # ← dict access

# Но остальной конвейер использует NPCState dataclass:
npc_state.npc_id          # ← attribute access
npc_state.affective_load  # ← attribute access
npc_state.emotion         # ← attribute access
```

**Как чинить:**

```python
# ВАРИАНТ А: добавить адаптер в начале handler'а
def _to_npc_state(self, npc_data) -> NPCState:
    if isinstance(npc_data, NPCState):
        return npc_data
    return NPCStateAdapter.from_snapshot(npc_data)  # dict → NPCState

# ВАРИАНТ Б: изменить типизацию handler'а
async def decay_affective(self, npcs: List[NPCState]) -> List[StateDelta]:
    for npc in npcs:
        # Теперь npc — NPCState, не dict
        if npc.affective_load > 0.01:
            delta = AffectiveDecayDelta(
                npc_id=npc.npc_id,
                new_load=npc.affective_load * 0.95,  # экспоненциальное затухание
            )
            deltas.append(delta)
    return deltas
```
