# UI DOCTRINE ENIGMA v1.0

## Конституция интерфейса

**Статус:** Архитектурный закон.

**Назначение:** Определяет фундаментальные принципы интерфейса ENIGMA. Любой элемент UI обязан соответствовать данной доктрине. Если новая функция нарушает один из законов — функция считается архитектурно неверной независимо от качества реализации.

---

# I. Главная цель интерфейса

Интерфейс ENIGMA не предназначен для передачи информации.

Он предназначен для передачи **опыта восприятия мира**.

Игрок должен чувствовать, что наблюдает за живой реальностью, а не управляет набором игровых систем.

Интерфейс является продолжением симуляции.

Он не существует отдельно от неё.

---

# II. Закон первичности мира

Мир всегда важнее интерфейса.

Интерфейс имеет право существовать только тогда, когда помогает увидеть происходящее в мире.

Если элемент заставляет игрока смотреть на окно вместо сцены — этот элемент архитектурно неверен.

Основной объект внимания игрока:

* NPC
* пространство
* действия
* движение
* последствия

а не панели.

---

# III. Закон причинности

Каждый элемент интерфейса обязан иметь реальную причину появления.

Запрещается отображать информацию без события, породившего её.

Правильная последовательность всегда выглядит так:

```
Мир
↓

Событие
↓

Восприятие

↓

Интерфейс
```

Никогда наоборот.

---

# IV. Закон эпистемической честности

Интерфейс знает только то, что имеет право знать игрок.

Любая информация обязана пройти через фильтр восприятия.

Запрещается отображать:

* реальные эмоции NPC;
* внутренние намерения;
* значения Utility;
* Belief;
* Trust;
* Fear;
* скрытые цели;
* любые внутренние состояния модели.

Разрешается отображать исключительно наблюдаемые последствия:

* голос;
* позу;
* взгляд;
* движение;
* жест;
* паузу;
* дыхание;
* проявление.

---

# V. Закон телесности

Игрок воспринимает мир через собственное тело.

Следовательно, состояние тела изменяет способ отображения мира.

Интерфейс не сообщает:

> "Вы устали на 63%."

Он позволяет почувствовать усталость.

Например:

* тяжёлое движение камеры;
* замедление интерфейса;
* снижение читаемости;
* ухудшение слуха;
* снижение контрастности;
* дрожание изображения.

Интерфейс показывает не параметры организма.

Он показывает последствия этих параметров.

---

# VI. Закон внимания

Внимание игрока является конечным ресурсом.

Каждый элемент интерфейса имеет стоимость внимания.

Интерфейс обязан распределять этот ресурс максимально экономно.

Если одновременно отображается слишком много элементов — менее важные обязаны исчезнуть, объединиться или отложиться.

Перегруженный интерфейс считается ошибкой архитектуры.

---

# VII. Закон локальности

Информация должна появляться максимально близко к своей причине.

Если NPC начал работать — игрок должен увидеть это возле NPC.

Если дверь открылась — сообщение должно родиться возле двери.

Если предмет поднят — информация появляется возле предмета.

Интерфейс не имеет права отрывать следствие от причины.

---

# VIII. Закон временности

Любой элемент интерфейса обязан иметь жизненный цикл.

Каждый элемент имеет:

* условие появления;
* время существования;
* условие исчезновения.

Информация не должна жить дольше события, которое её породило.

Исключением являются только элементы долговременной памяти игрока.

---

# IX. Закон когнитивных слоёв

Интерфейс состоит из нескольких уровней внимания.

### Первый слой

Мир.

Он существует всегда.

---

### Второй слой

Кратковременное восприятие.

Например:

* речь;
* действия;
* проявления;
* звуки;
* предупреждения.

Появляется только во время события.

---

### Третий слой

Осознанный анализ.

Например:

* журнал;
* инвентарь;
* карта;
* исследования.

Игрок открывает его самостоятельно.

---

### Четвёртый слой

Метаинформация.

Настройки.

Отладка.

Статистика.

Эти элементы не участвуют в игровом восприятии.

---

# X. Закон единого языка

Все элементы интерфейса обязаны говорить на одном визуальном языке.

Недопустимо смешение:

* реализма;
* мультяшности;
* эмодзи;
* неона;
* современного flat-дизайна;
* случайных иконок.

Каждый новый элемент должен выглядеть так, словно существовал в игре с самого начала.

---

# XI. Закон минимального вмешательства

Лучший интерфейс — тот, который исчезает.

Игрок не должен постоянно замечать существование UI.

Во время наблюдения за миром интерфейс обязан растворяться.

Во время анализа — становиться доступным.

Во время опасности — помогать.

Во время спокойствия — молчать.

---

# XII. Закон расследования

ENIGMA является игрой о понимании мира.

Следовательно, интерфейс никогда не сообщает готовые выводы.

Он предоставляет только наблюдения.

Выводы строит сам игрок.

Журнал хранит:

* увиденное;
* услышанное;
* замеченное;
* сделанные игроком гипотезы.

Он не раскрывает объективную истину.

---

# XIII. Закон симуляции

Интерфейс подчиняется тем же законам, что и мир.

Он не может нарушать:

* причинность;
* эпистемологию;
* ограничения восприятия;
* ограничения памяти;
* ограничения времени.

Интерфейс является частью симуляции, а не внешней системой.

---

# XIV. Главный критерий качества

После реализации любого элемента разработчик обязан ответить на четыре вопроса.

1. Возник ли этот элемент из события мира?
2. Имеет ли игрок право знать эту информацию?
3. Помогает ли элемент наблюдать мир, а не заменяет ли его собой?
4. Можно ли удалить этот элемент без потери понимания происходящего?

Если хотя бы один ответ отрицательный — элемент требует переработки.

---

## Итоговая формула ENIGMA

> **Мир рождает события. События проходят через восприятие. Восприятие формирует интерфейс. Интерфейс помогает игроку построить собственную модель мира.**
