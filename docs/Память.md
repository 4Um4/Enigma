# ENIGMA — MEMORY SYSTEM (FINAL ARCHITECTURE)

---

# 0. ЦЕЛЬ

Создать память, которая:

* влияет на решения (через числа)
* создаёт ощущение истории (через события)
* формирует личность (через сжатие)
* деградирует со временем
* искажается, но остаётся правдоподобной
* масштабируется под 10–50 NPC и ограниченный контекст LLM

---

# 1. ОБЩАЯ АРХИТЕКТУРА

```text
Event
↓
MemoryManager
  ├─ L1: Numerical Memory (weights)
  ├─ L2: Event Memory (events)
  └─ L3: Identity Memory (traits)
↓
DecisionHub (использует L1 + L3)
↓
LLM (использует только L2 + state snapshot)
```

---

# 2. L1 — NUMERICAL MEMORY (ОСНОВА РЕШЕНИЙ)

## Формат

```python
trust
fear
stress
debt
```

---

## Обновление

```python
Δweights =
    |Δtrust|
  + |Δfear|
  + |Δstress|
```

---

## Назначение

* используется ТОЛЬКО DecisionHub
* определяет expected_success
* НЕ передаётся в LLM

---

---

# 3. L2 — EVENT MEMORY (СМЫСЛОВАЯ ПАМЯТЬ)

## Формат

```python
EventMemory:
    event_type
    actors
    summary
    emotional_intensity
    importance
    timestamp
    decay_rate
    clarity
    confidence
```

---

## Ограничения

* хранится ограниченно (Tier-based)
* передаётся в LLM: max 2–4 события
* НЕ участвует напрямую в логике решений

---

---

# 4. РАСЧЁТ ВАЖНОСТИ (IMPORTANCE)

## КЛЮЧЕВАЯ ФОРМУЛА

```python
importance =
    Δweights_component
  + emotional_intensity
  + identity_impact
```

---

## Компоненты

### 4.1 Δweights_component

```python
Δweights_component =
    |Δtrust| + |Δfear| + |Δstress|
```

---

### 4.2 emotional_intensity

Зависит от:

* типа события
* текущего состояния NPC

---

### 4.3 identity_impact

```text
насколько событие:
— ломает ожидания
— подтверждает убеждения
```

---

## Примеры

| Событие        | importance  |
| -------------- | ----------- |
| помощь         | средняя     |
| предательство  | высокая     |
| спасение жизни | критическая |

---

---

# 5. ЖИЗНЕННЫЙ ЦИКЛ ПАМЯТИ

```text
Fresh → Detailed → Compressed → Abstract → Forgotten
```

---

## Пример

```text
Fresh:
“вчера он украл серебряный кубок ночью”

Compressed:
“он меня обокрал”

Abstract:
“ему нельзя доверять”
```

---

👉 Abstract → уходит в L1/L3

---

---

# 6. ЗАБЫВАНИЕ (DECAY)

## Базовая формула

```python
importance *= exp(-decay_rate * time)
```

---

## Усиление через связи (вместо random)

```python
importance += reinforcement_from_related_events
```

---

## Связи:

* тот же персонаж
* тот же тип действия
* та же тема (деньги, семья, насилие)

---

---

# 7. ИСКАЖЕНИЕ ПАМЯТИ (MEMORY DRIFT)

## Уровень ясности

```python
clarity = f(importance, time)
```

---

## Типы искажения

### 7.1 Temporal Drift

“вчера… или неделю назад…”

---

### 7.2 Detail Loss

теряются детали события

---

### 7.3 Attribution Drift

путается источник события

---

### 7.4 Emotional Bias

эмоции искажают восприятие

---

---

# 8. CONFIDENCE (УВЕРЕННОСТЬ В ПАМЯТИ)

```python
confidence ∈ [0..1]
```

---

## Использование

```python
recall_probability = importance * confidence
```

---

## Эффект

NPC может:

* помнить точно
* сомневаться
* забыть
* искажать

---

---

# 9. КРИТИЧЕСКАЯ ПАМЯТЬ (НЕЗАБЫВАЕМОЕ)

```python
if importance > critical_threshold:
    decay_rate → ~0
```

---

## Примеры

* спасение жизни
* сильная травма
* ключевые события личности

---

---

# 10. L3 — IDENTITY MEMORY (ЛИЧНОСТЬ)

## Формирование

```python
if Σ related_events > threshold:
    create_trait()
```

---

## Примеры

```text
частый обман → distrust_player
частая помощь → trust_bias
насилие → fear_bias
```

---

## Назначение

* влияет на DecisionHub
* НЕ зависит от конкретных событий
* сохраняется при забывании

---

---

# 11. ВЫБОР ПАМЯТИ ДЛЯ LLM

## Приоритет

```python
priority =
    importance
  * recency
  * emotional_intensity
  * relevance_to_context
```

---

## Ограничение

```text
max 2–4 события
```

---

---

# 12. ПЕРЕДАЧА В LLM

LLM получает:

```text
- summary
- emotional_tag
- clarity
- confidence
```

---

LLM может:

* интерпретировать
* достраивать детали

---

LLM НЕ может:

* менять факты
* создавать новые события
* влиять на решения

---

---

# 13. ПОВЕДЕНИЕ NPC

## Ответы формируются через:

```text
событие + уровень ясности + уверенность
```

---

## Пример

Высокая ясность:

→ точное воспоминание

Низкая ясность:

→ искажённое:

“кажется… он что-то сделал…”

---

---

# 14. ДЕГРАДАЦИЯ В ЛИЧНОСТЬ

```text
события → паттерны → traits → поведение
```

---

👉 события исчезают
👉 личность остаётся

---

---

# 15. TIER-СИСТЕМА (МАСШТАБ)

| Tier   | Event Memory |
| ------ | ------------ |
| minor  | 0–2          |
| middle | 3–5          |
| major  | 5–10         |

---

## Оптимизация

* lazy loading
* только активные NPC используют память
* snapshot для LLM

---

---

# 16. БАЛАНС СИСТЕМЫ

```text
точность памяти: 60–70%
искажение: 30–40%
```

---

## Влияние памяти на решения:

```text
25–40%
```

---

---

# 17. КРИТИЧЕСКИЕ ПРИНЦИПЫ

---

### 1. Память не случайна

```text
она усиливается через связи
```

---

### 2. Важность ≠ только числа

```text
есть эмоции и личность
```

---

### 3. Забываются детали, не смысл

---

### 4. LLM не думает

```text
она только выражает память
```

---

### 5. NPC не помнит факты

```text
он помнит отношение
```

---

---

# 18. ФИНАЛЬНАЯ МОДЕЛЬ

```text
NPC не хранит историю как лог.

Он:
— переживает события
— сжимает их в смысл
— забывает детали
— и живёт с тем, во что верит
```

---

# 19. ФИНАЛЬНЫЙ ПРИНЦИП

```text
Важно не то, что произошло.

Важно то,
что осталось внутри NPC после этого.
```
