КРИТИЧЕСКИ ВАЖНО — работа с файлами:

### ⚠️ РАЗЛИЧИЕ .py и .md файлов

**Для `.py` файлов (код):** точечные команды, не запрашивать целиком (кроме случая ниже).
**Для `.md` файлов (документация):** ОБЯЗАТЕЛЬНО читать ЦЕЛИКОМ.

### ЗАПРЕЩЕНО для .md файлов:
```powershell
Get-Content docs/MUTATIONS.md | Select-Object -Last 60      # ❌ НЕПРАВИЛЬНО
Get-Content docs/MUTATIONS.md | Select-Object -First 60     # ❌ НЕПРАВИЛЬНО
Get-Content "docs/ADR (Architecture Decision Records).md" | Select-Object -Index (900..1007)  # ❌ НЕПРАВИЛЬНО
```

### ОБЯЗАТЕЛЬНО для .md файлов:
```powershell
Get-Content docs/MUTATIONS.md                               # ✅ ПРАВИЛЬНО (без пайпов)
Get-Content "docs/ADR (Architecture Decision Records).md"   # ✅ ПРАВИЛЬНО
```

**Почему:** 60 строк из 700 = 8% файла. LLM видит хвост, не видит структуру, нумерацию, начало секций. Результат — сломанные документы: дублирующая нумерация, разбитые таблицы, незакрытые code fences. Именно так были сломаны ADR, MUTATIONS, DTO Registry, этот файл (два раздела 3.7).

**Исключение для .md > 2000 строк:** читать по частям через `Select-Object -Index (0..499)`, `(500..999)`, и т.д. Но ОБЯЗАТЕЛЬНО все части. `Select-Object -Last` запрещён ВСЕГДА.

### Для .py файлов (код) — точечные команды PowerShell:

Поиск по паттерну:
Select-String -Path "path/to/file.py" -Pattern "pattern1|pattern2"

Чтение конкретных строк:
Get-Content path/to/file.py | Select-Object -Index (N..M) | ForEach-Object -Begin {$i=N+1} -Process {"$i`: $_"; $i++}

Поиск по всем файлам директории:
Get-ChildItem -Path "app/" -Filter "*.py" -Recurse | Select-String -Pattern "pattern" | Select-Object -Property Path -Unique

**Все команды PowerShell для одного шага — в одном блоке кода.**
Если нужно выполнить 5 команд — выводишь один блок с 5 командами, разделёнными пустой строкой, и пронумерованные отдельной строкой нумерации чтобы не загрязнять вызов в терминале.
Не разбивать на 5 отдельных блоков — это экономит ходы и контекст.
(Пример: 
# 10. WorldTopologyProvider: полная структура
Get-Content backend/app/services/spatial/world_topology_provider.py | Select-Object -Index (0..60)
)

Только если без полного `.py` файла невозможно — запросить его явно с обоснованием. Для `.md` — всегда целиком.

3.5 ДОПОЛНИТЕЛЬНО

**Когда PowerShell достаточно (90% случаев):**
```
Select-String -Pattern "def method" 
Get-Content | Select-Object -Index (N..M)
```
Текстовый поиск — быстро, надёжно, соответствует разделу 3.

**Когда AST необходим (10% случаев):**

| Ситуация | Почему PowerShell не справляется |
|---|---|
| Orphan-методы | Текстовый поиск видит `def`, но не видит **вложенность** — функция внутри функции выглядит одинаково |
| Mixing tabs/spaces | PowerShell показывает пробелы, но не показывает **как Python их интерпретирует** |
| Проверка сигнатуры без контекста | `Select-String` даёт строку, но не парсит аргументы — AST даёт точный список |
| Мёртвый код после return | Нужна семантика (код после return в том же блоке), а не просто наличие `return` |

**Правило, которое я буду соблюдать:**

1. Сначала — PowerShell (раздел 3)
2. Если результат неоднозначный или подозрительный — AST
3. AST-команды запрашиваю у тебя для выполнения — не придумываю вывод
4. Никогда не заменяю AST-проверку на "давай файл целиком"
5. Любые твои предложения мы обсудим - мы не меняем код, пока не подтвердим Я и Мастер что мы согласны с твоим мнением!

Это не нарушает раздел 3 — это **расширение** для случаев, когда текстовый анализ недостаточен.



Запрещено:
— гадать содержимое файлов
— придумывать код вне контекста

4. ФОРМАТ ИЗМЕНЕНИЙ (СТРОГО)

БЫЛО: <одна уникальная строка для поиска в VS Code>
СТАЛО: <код с отступами для замены в VS Code>
IPT: <имя инварианта, который проверяет этот фикс> ✅/❌
КРАСНЫЕ ИНВАРИАНТЫ: было N 🔴 → стало M 🔴

**Поля IPT и КРАСНЫЕ ИНВАРИАНТЫ обязательны.** Если LLM не может заполнить 
IPT (инвариант не подходит) — пишет `IPT: N/A (инвариант не применим к этому фиксу)`.

**Пример:**

Файл: backend/app/services/phases/post_decision.py
БЫЛО:
```
    if not ctx.communication_intents:
        return
```
СТАЛО:
```
    if not ctx.communication_intents:
        _verbal = sum(1 for d in ctx.decisions if d.intent in DecisionHub._VERBAL_INTENTS)
        if _verbal > 0:
            raise SimulationIntegrityError(
                invariant_id="INV-DIALOGUE-PIPELINE",
                message=f"Phase 6: communication_intents пуст, но {_verbal} вербальных решений",
                suspect_files=["backend/app/services/npc/life_engine.py:719",
                               "backend/app/services/pipeline_runner.py:87"],
                file=__file__, line=23,
            )
        return
```
IPT: ✅ INV-DIALOGUE-PIPELINE passed (verbal=4, dialogues=4)
КРАСНЫЕ ИНВАРИАНТЫ: было 1 🔴 → стало 0 🔴

ПРАВИЛА ВЫВОДА:
0. ПЕРЕД КАЖДОЙ ЗАМЕНОЙ указывать точный путь к файлу в формате: Файл: path/to/file.py
1. Значения (путь, строка поиска, код замены) выводить в блоках кода без указания языка. Метки (Файл:, БЫЛО:, СТАЛО:) — обычный текст вне блоков.
2. В БЫЛО — строго одна строка. Идеально для вставки в поле поиска VS Code. чистый код с реальными отступами.
3. В СТАЛО — чистый код с реальными отступами. Идеально для вставки в поле замены VS Code.
4. Если нужно удалить несколько старых строк — Так же указывай чистый код с реальными отступами
5. Никакого лишнего текста между блоками кода.

То есть правильно:

Метки Файл:, БЫЛО:, СТАЛО: — ОБЫЧНЫЙ ТЕКСТ ВНЕ БЛОКОВ КОДА
Содержимое БЫЛО и СТАЛО — В БЛОКАХ КОДА (тройные обратные кавычки) без указания языка

11. ПРАВИЛО ПАРАЛЛЕЛЬНЫХ СЕССИЙ (Anti-Race Condition Protocol)
В проекте могут параллельно работать несколько LLM-ассистентов.
— **ID Сессий:** Номер сессии (`S##`) присваивается строго при **завершении** работы и записи в `MUTATIONS.md`. Если ты видишь последнюю сессию `S95`, твоя будет `S96`. Никогда не присваивай номер на старте.
— **ID ADR:** Перед созданием нового ADR обязательно прочитай `docs/ADR (Architecture Decision Records).md`. Номер ADR (например, `ADR-155`) берётся как максимальный существующий числовой ID + 1. Никогда не используй ID сессии в качестве ID ADR (например, `ADR-S93` — это только префикс для контекста, но сам ADR должен иметь сквозной номер, если это не онтологический сдвиг вроде `ADR-O-XXX`). При параллельной работе каждый ассистент должен проверять, не занял ли кто-то уже этот номер.

13. АРХИТЕКТУРНОЕ ПРИНУЖДЕНИЕ (Enforcement Layer)

Любое изменение, затрагивающее домены (fear, trust, pain, will, memory, intent) или добавляющее новые DTO/фазы, требует заполнения ADR-контракта перед написанием кода.

### ADR-PRE-FLIGHT CHECKLIST (Заполняется ДО кодинга):
1. **Тип АДР:** [STANDARD | ONTOLOGY (ADR-O)]
2. **Затронутые домены:** [список]
3. **Связанные потребители (Downstream):** [кто еще читает эти данные?]
4. **Бюджет ресурсов:** Прогноз изменения RAM/VRAM/Tick Latency.
5. **Откат (Rollback):** Как откатить это изменение, если оно сломает симуляцию?
6. **Регрессия:** Имя теста в `tests/sandbox/` (обязательно в правильной директории: `micro/`, `system/`, `stress/` или `phenomenology/`), который подтвердит работоспособность каузальной цепи.

**ЗАПРЕТ:** Если АДР меняет `fear`, `trust`, `obedience`, `morality` (ADR-O класс), код пишется ТОЛЬКО после ручного аудита связей через PowerShell Gates.

### PowerShell Gates (Запускаются ПЕРЕД коммитом или после работы другой LLM)

> **Автоматизация:** Все три GATE можно прогнать одной командой через `scripts/gate_audit.py` (см. ниже). Ручные PowerShell-команды — для точечного аудита конкретного паттерна.

**GATE 1: Hidden Coupling Audit (Проверка связей перед изменением)**
```powershell
Get-ChildItem -Path "backend/app/services/" -Filter "*.py" -Recurse | Select-String -Pattern "fear_delta|trust_delta|fear_drive" | Select-Object -Property Path -Unique
```

**GATE 2: Domain Leakage Audit (Проверка, что Combat не пишет в Emotion/Perception)**
```powershell
Get-Content backend/app/services/combat/combat_subscriber.py | Select-String -Pattern "stress_delta|emotion_tag|PerceptionPayload"
```

**GATE 3: DTO Border Audit (Проверка, что frontend не лезет в backend)**
```powershell
Get-ChildItem -Path "frontend/" -Filter "*.py" -Recurse | Select-String -Pattern "from backend.app"
```

**Единый скрипт (когда будет реализован):**
```powershell
python scripts/gate_audit.py
```
Логика скрипта (реализовать):
- GATE 1: `rg --type py "fear_delta|trust_delta|fear_drive" backend/app/services/` → список файлов с совпадениями. Если целевой модуль не в списке — нет скрытых связей.
- GATE 2: `rg --type py "stress_delta|emotion_tag|PerceptionPayload" backend/app/services/combat/` → список совпадений. Если есть `stress_delta` или `emotion_tag` в `combat_subscriber.py` → Domain Leakage (CRITICAL).
- GATE 3: `rg --type py "from backend.app" frontend/` → список файлов. Если непусто → DTO Border Violation (CRITICAL).
- Возвращает exit code 0 (всё чисто) или 1 (нарушение). Для CI/CD.
- Отчёт: `[GATE 1] PASS/FAIL (N files)`, `[GATE 2] PASS/FAIL`, `[GATE 3] PASS/FAIL (N files)`.

### 3.6 АРХЕОЛОГИЧЕСКИЙ ПРОТОКОЛ (обязательно перед ЛЮБЫМ изменением кода)

Археология — не опциональный шаг. Это единственный способ получить знание вместо предположения.

**Правило: НЕ ЗНАЕШЬ — КОПАЙ. НЕ УГАДЫВАЙ.**

#### Шаг 1: Определить объект изменения
```
PIPELINE_OBJECT:  что меняется
OWNER:            кто владеет
TYPE:             dataclass / dict / DTO / enum
```

#### Шаг 2: Археология через PowerShell
```powershell
# Определение класса
Select-String -Path "path" -Pattern "class TargetClass"

# Сигнатура конструктора / поля
Get-Content path | Select-Object -Index (N..M)

# Все читатели поля
Get-ChildItem -Path "backend/app/" -Filter "*.py" -Recurse | Select-String -Pattern "\.field_name"

# Все писатели поля
Get-ChildItem -Path "backend/app/" -Filter "*.py" -Recurse | Select-String -Pattern "field_name\s*="
```

#### Шаг 3: Owner Discovery
```
Владелец истины:  модуль/файл
Читатели:         список
Писатели:         список (если >1 → DOUBLE TRUTH риск)
```

Если владелец не найден → **STOP. ARCHÄOLOGY REQUIRED.**

#### Шаг 4: Runtime Archaeology (если структура данных неизвестна)
```python
# Внедрить в точку CREATE или TRANSFORM:
print(f"[ARCHAE] type={type(obj).__name__}, keys={list(obj.keys())[:15]}")
print(f"[ARCHAE] field={obj.get('field_name', '<MISSING>')}")
```

Запуск → чтение лога → уточнение диагноза → **только потом** фикс.

#### Шаг 5: Фабрика вместо Конструктора

Запрещено в тестах:
```python
# ОБЪЕКТ МЕЧТЫ — LLM угадала поля
obj = NPCState(npc_id="player", will_state=None, stress=0.0, ...)
```

Разрешено в тестах:
```python
# ОБЪЕКТ РЕАЛЬНОСТИ — создан через фабрику из реальных данных
obj = NPCStateAdapter.from_legacy(real_dict)
# Если нужно переопределить — replace, не конструктор
import dataclasses; obj = dataclasses.replace(obj, npc_id="test")
```

#### Шаг 6: Round-Trip Validation (для сериализационных адаптеров)
```python
obj = Adapter.from_legacy(d)
Adapter.write_to_legacy(obj, d)
obj2 = Adapter.from_legacy(d)
assert obj.field == obj2.field  # поле не потерялось
```

### 3.7 СЕРИАЛИЗАЦИОННЫЙ ТЕСТ-ПРОТОКОЛ (обязательно при любом изменении from_legacy / write_to_legacy)

---

**Итоговая трёхуровневая защита:**

```
§13 Epistemic Grounding  →  Не предполагай. Сначала добудь факт.
  └── Археологический протокол  →  Как именно добывать: PowerShell → Owner → Runtime
        └── §12 Round-Trip Integrity  →  Проверь, что данные не теряются при сериализации
```

Сериализационные адаптеры — главная точка молчаливых багов. Каждый раз когда LLM пишет тест с прямым конструктором — она угадывает дефолты и ошибается.

**ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА:**

1. **Никаких прямых конструкторов в тестах адаптера.** Объект создаётся ТОЛЬКО через `from_legacy(real_dict)`. Если нужен специфический объект — `dataclasses.replace()` после создания.

2. **Real Data First.** Перед тестом — внедрить print-диагностику ключей в `from_legacy`, увидеть РЕАЛЬНЫЕ ключи рантайма, и только потом писать тест.

3. **Round-trip обязателен.** Тест: `from_legacy(d) → write_to_legacy(obj, d) → from_legacy(d2)` — поля d и d2 должны совпадать.

4. **Ключи — константы.** Все строковые ключи в from_legacy/write_to_legacy должны быть модульными константами. Inline-строки = следующий баг.

**АНТИПАТТЕРН (приводит к багам):**
```python
# LLM угадала will_state=None → краш при write_to_legacy
s = NPCState(npc_id='player', stress=0.0, will_state=None, ...)
```

**ПРАВИЛЬНО:**
```python
# Объект создан через from_legacy — гарантированно валидный
d = {'npc_id': 'player', 'psyche': {'state': 'free'}, 'social_stats': {}}
s = NPCStateAdapter.from_legacy(d)
# Если нужно изменить — replace, не конструктор
import dataclasses
s = dataclasses.replace(s, npc_id='test_override')
```

### 3.8 INVARIANT PROBE TEST (IPT) — замена Smoke-test

После каждого патча — обязательная проверка инвариантов симуляции.
НЕ unit-тест, НЕ pytest. Один скрипт, 5 секунд, минимальный мир без LLM.

**Команда запуска:**

```powershell
python backend/tests/IPT.py
```

**Что проверяет IPT:**
- INV-TIME-GROW: game_time_seconds растёт после 3 idle_tick
- INV-TICK-GROW: tick увеличивается на каждом idle_tick
- INV-NPC-MOVE: хотя бы 1 NPC сменил позицию за 5 тиков
- INV-DIALOGUE-PIPELINE: вербальные интенты превращаются в реплики
- INV-TRAV-DICT: active_traversals — dict (не list)
- INV-NPC-NAME: каждый NPC имеет поле name

**Правила:**
1. IPT запускается ДО закрытия шага. Не запустил — шаг не закрыт.
2. Если IPT красный — ФИКС НЕ ЗАВЕРШЁН. Читай suspect_files в выводе.
3. В формате БЫЛО/СТАЛО (см. §4) — обязательное поле `IPT:`.
4. IPT дополняет (не заменяет) pytest tests/.

**ЗАПРЕЩЕНО:**
- Закрывать шаг со словами "тесты пройдут, я уверен" — IPT запускается ВСЕГДА.
- Использовать `python -c "from X import Y; Y()"` как замену IPT.
- Добавлять в IPT больше 15 инвариантов.

### 3.9 SMOKE-TEST (python -c) — точечная проверка метода

Для быстрой проверки конкретного метода без написания полноценного теста. Используется когда IPT не покрывает узкий кейс, а писать `test_*.py` ещё рано.

**Правила:**
1. Команда выполняется из корня проекта с `cd backend` (чтобы `from app.` работал)
2. Внутри `python -c` — **одинарные кавычки** для строк, **без вложенных двойных** (иначе SyntaxError)
3. Если нужен `f-string` с кавычками — вынести в переменную заранее
4. После блока — `cd ..` для возврата в корень
5. Команда должна быть **самодостаточной** — не зависеть от состояния игры

**Когда обязательно:**
- После фикса любого метода, упомянутого в баг-репорте
- Перед тем как переходить к следующему багу
- После изменения DTO/контрактов данных
- После чистки `__pycache__` — убедиться что новый код компилируется

**Что проверять:**
- Метод не крашится на пустом входе
- Метод не крашится на реалистичном входе
- Возвращаемый тип совпадает с ожидаемым
- Boundary conditions (0.0, None, пустой список)

**Пример из практики:**
```powershell
cd backend; python -c "
from app.services.social.directive_interpretation_subscriber import DirectiveInterpretationSubscriber
import types
npc_states = [{'id': 'thief_shadow', 'name': 'Тень', 'social_stats': {'fear_of_player': 0.3, 'trust': 10}}]
event = types.SimpleNamespace(payload={'semantic_action': 'MOVE', 'target_reference': 'тень', 'target_id': 'thief_shadow', 'social_pressure': 0.8})
sub = DirectiveInterpretationSubscriber()
deltas = sub.handle(event, npc_states)
print('Deltas count:', len(deltas))
for d in deltas:
    print('  npc_id=', d.npc_id, 'domain=', d.domain)
"; cd ..
```

### 3.11 КРАСНЫЕ ИНВАРИАНТЫ — ОБЯЗАТЕЛЬНОЕ ЧТЕНИЕ ПЕРЕД СТАРТОМ

Перед любым изменением кода LLM обязана:

1. Открыть `reports/LAST_SESSION.md`
2. Найти секцию `## 🔴 КРАСНЫЕ ИНВАРИАНТЫ — ТИХИЕ ДЕГРАДАЦИИ`
3. Если секция содержит хотя бы один 🔴 CRITICAL — работа над новой фичей 
   ЗАПРЕЩЕНА. Сначала чинятся красные инварианты.
4. Если секция 🟢 — можно работать над новой фичей.
5. Если секция содержит 🟡 WARNING — можно работать, но нарушение 
   фиксируется в MUTATIONS.md как «известный долг».

**Источники красных инвариантов (оба пишут в одну секцию LAST_SESSION.md):**
- ⚡ RUNTIME: `SimulationIntegrityError` в pipeline — игра упала с диагнозом
- 📈 POST-MORTEM: `InvariantHealthChecker` в CausalObserver — тихая деградация 
  обнаружена после завершения игры

**Слой ДО (IPT, см. §3.8)** — отдельный канал, запускается LLM во время фикса.
Не путать: IPT — до коммита, КРАСНЫЕ ИНВАРИАНТЫ — после игры.

**Принуждение через формат (см. §4):**
В БЫЛО/СТАЛО обязательны поля `IPT:` и `КРАСНЫЕ ИНВАРИАНТЫ:`.
Без них патч не считается завершённым.
