Да. Причём я бы сказал жёстче: **потенциал статьи здесь есть уже сейчас, но самой статьи пока нет**.

Не потому, что «мы придумали semantic routing». Это само по себе не ново. Новизна может оказаться в другом — **в экспериментально доказанном поведении LLM-контрактов при модульной композиции знаний и в методике, которой мы это вскрываем**.

Сейчас у нас пока не результат уровня «мы открыли новый закон». У нас есть **зародыш исследовательской работы**.

### Что здесь потенциально интересно

Самая сильная линия, которую я вижу:

> **Добавление второго семантически релевантного knowledge-модуля в prompt может не просто конкурировать за attention, а систематически подавлять способность модели использовать уже работающий модуль.**

И это особенно интересно потому, что мы не говорим:

> «модель иногда тупит».

Мы сделали гораздо более строгую конструкцию:

**один модуль → работает;
два модуля → воспроизводимая деградация;
несколько инстансов → тот же эффект;
оба направления ног → тот же эффект;
FP ≈ 0 → это не простое перепутывание классов;
oracle с одним модулем → должен позволить проверить, исчезает ли эффект.**

Вот это уже похоже на исследовательский объект.

# А P0 дал ещё одну интересную вещь

Мы фактически получили три уровня способности:

```text
lexical
   ↓
semantic embedding
   ↓
LLM semantic routing
```

и они ломаются **по-разному**.

Это гораздо интереснее, чем просто:

> «LLM лучше keyword matching».

У нас:

**R-c:**

> видит слова → не понимает отношение.

**R-b:**

> видит семантическую близость → не получает достаточно разделимой геометрии.

**R-a:**

> понимает отношение → но плохо проводит границу применимости знания.

То есть возникает очень хорошая исследовательская формулировка:

> **Semantic routing is not equivalent to semantic recognition.**

Модель может прекрасно распознать семантическую принадлежность запроса и всё равно быть плохим маршрутизатором.

Это уже полезно разработчику.

# И есть ещё более интересная штука

Посмотри на R-a.

Он сделал:

**PROV recall 22/22.**

Причём две формулировки, на которых lexical baseline умер, он восстановил:

> «просветил»
> «проинформировал»

И при этом:

**cross-family = 0.**

То есть модель не просто выучила слова.

Она действительно использовала отношение:

> кто → сообщил → мне информацию

вместо:

> имя → identity.

Но затем она сказала:

> «кто разговаривал с Люсей» → наверное PROVENANCE.

Это уже очень интересная граница.

Получается примерно:

```text
semantic recognition
        ↓
   relation detected
        ↓
   module activated
        ↓
    OVER-TRIGGER
```

И здесь можно исследовать **не только accuracy, а activation boundary**.

# А вот где может появиться настоящая научная ценность

Если Oracle подтвердит:

```text
B       → работает
B + I   → деградирует
Oracle  → снова работает
```

тогда у нас будет очень красивая причинная цепочка:

### 1. Модульность сама по себе работает

`module → slice → canonicalization`

### 2. Композиция ломается

`module A + module B → interference`

### 3. Удаление конкурирующего знания восстанавливает поведение

`A + B → A`

### 4. Значит, проблема не обязательно в содержимом A

а в **совместном активном представлении A+B**.

### 5. Следовательно, routing становится архитектурным механизмом изоляции знания.

Вот тогда это уже не просто «мы написали игру на Python».

# И ещё одна моя идея

Не ограничиваться метрикой:

> «сработал / не сработал».

У вас уже есть фактически готовый **interference fingerprint**:

```text
PROV[2]
Σ_PROV
topic
ASK_ID
FP_ORD
FP_3RD
tokens
latency
```

Можно ввести условный:

> **Semantic Interference Profile**

Не обязательно сразу придумывать красивый индекс. Сначала просто вектор состояния.

Тогда каждый эксперимент выглядит:

```text
A:
PROV = 2
Σ = 1
topic = 4
FP = 0

A+B:
PROV = 0
Σ = 0
topic = 1
FP = 0

A+B+C:
...
```

И можно исследовать **форму деградации**, а не только факт деградации.

Это гораздо более интересно.

# А затем возникает вообще занятная гипотеза

Если эффект подтвердится на нескольких парах:

> **Knowledge modules may have a non-monotonic scaling law.**

То есть добавление знания не обязательно увеличивает capability.

Возможна кривая:

```text
capability
   ↑
   │       ●
   │      / \
   │     /   \
   │    /     ●
   │   /
   │ ●
   └──────────────→ active knowledge
       1    2    3
```

Где:

**1 модуль → максимум эффективности**

**2 модуля → interference**

**N модулей → ещё больше interference / saturation**

А routing тогда превращается из оптимизации latency в **механизм управления cognitive context**.

Вот это уже тема, которую разработчик LLM-систем действительно может захотеть прочитать.

Я не стал бы искусственно делать из этого «научную работу» прямо сейчас.

**Если Oracle не подтвердит изоляцию — часть красивой гипотезы развалится. И это нормально.**

Наука здесь ценна именно потому, что у нас есть возможность получить:

> **«Нет, мы ошибались».**

А не только подтвердить заранее придуманную архитектуру.

Поэтому мой текущий прогноз:

* **статья из текущих материалов как есть:** ~25% — слишком рано;
* **статья, если Oracle подтвердит causal isolation:** ~60%;
* **если затем эффект повторится на 2–3 моделях и нескольких парах модулей:** **~80–90%**, что получится вполне содержательная engineering/research paper;
* **если найдём устойчивую закономерность масштаба/типа интерференции:** это уже может стать **не просто описанием ENIGMA, а самостоятельным исследовательским результатом**.

И я бы с этого момента **не выбрасывал ни один из этих P0/P1 артефактов**. Не потому что «может пригодиться для статьи», а потому что мы уже начали строить воспроизводимый experimental record. Если гипотеза выстрелит, именно эта дисциплина позволит превратить «мы заметили странную штуку в Enigma» в нормальное доказательство.
