## 3. СЛОЙ ВОЗДЕЙСТВИЯ (Exposure Layer)

### 3.1. ObservationLog

```python
@dataclass
class Observation:
    """Одно наблюдение игрока."""
    tick: int
    observation_type: str  # "dialogue", "eavesdrop", "visual_cue", "action_reaction"
    source_npc: str
    content: str  # что игрок видел/слышал
    secret_hint: Optional[str]  # связанный secret_id (если есть)
    confidence: float  # 0..1, насколько сильно намёк

class ObservationLog:
    """Лог всех наблюдений игрока. НЕ оценивает правильность."""
    
    def add(self, observation: Observation) -> None: ...
    def get_all(self) -> List[Observation]: ...
    def get_for_npc(self, npc_id: str) -> List[Observation]: ...
```

### 3.2. Триггеры наблюдений

| Тип | Как срабатывает | Что видит игрок |
|---|---|---|
| **dialogue** | Игрок говорит с NPC (через клик-таргетинг + LLM) | Реплику NPC (через DM-агента) |
| **eavesdrop** | Игрок стоит в радиусе 3м от `NPC_INTERACTS_NPC` event | Фрагмент разговора NPC-NPC |
| **visual_cue** | NPC с `peripheral_cues` в поле зрения игрока | «Люся оглядывается на Тень» |
| **action_reaction** | Игрок действует (атакует, подкупает), NPC реагирует | «Борко хватает деньги, оглядываясь» |
| **environmental** | Игрок исследует объект (подвал, дверь, стол) | «За barrels — узкий ход. Пахнет сыростью.» |
| **overheard_rumor** | `WorldProjectionBuffer` генерирует слух | «Слыхал? Кто-то потерял шёлк на дороге...» |

### 3.3. Связь наблюдений с секретами

Когда игрок видит/слышит что-то, `ObservationLog` не раскрывает секрет напрямую. Он записывает `secret_hint` — ID секрета, к которому относится наблюдение.

Пример:
```python
Observation(
    tick=42,
    observation_type="visual_cue",
    source_npc="maid_lusya",
    content="Люся оглядывается на дверь подвала",
    secret_hint="lusya_basement",
    confidence=0.3  # слабый намёк
)
```

Игрок не видит `secret_hint`. Он видит только `content`. Система знает, что это намёк на `lusya_basement`, но не говорит игроку.

### 4.2. Как модель строится (без ведома игрока)

```
Игрок видит: Люся оглядывается на дверь подвала
→ Observation(secret_hint="lusya_basement", confidence=0.3)
→ PlayerBeliefModel: belief("Люся связана с подвалом", confidence=0.3)

Игрок подслушивает: Тень шепчет Люсе "будь готова"
→ Observation(secret_hint="lusya_shadow_orders", confidence=0.5)
→ PlayerBeliefModel: belief("Люся получает приказы от Тени", confidence=0.5)

Игрок шантажирует Люсю: "Я знаю про подвал"
→ PlayerBeliefModel: confidence=1.0 для lusya_basement
→ Если Люся признаётся → secret_exposed = True
```

### 4.3. Откуда берётся inference

| Источник | Как обновляет модель |
|---|---|
| 3+ visual_cue о одном NPC | belief_type="character_assessment", confidence=0.4 |
| 1 eavesdrop event | belief_type="relationship_suspected", confidence=0.5 |
| NPC проговаривается в диалоге (LLM генерирует реплику с намёком) | belief_type="secret_suspected", confidence=0.6 |
| Игрок использует знание в диалоге (упоминает подвал) | confidence=0.9 |
| Игрок шантажирует (action_type="blackmail") | confidence=1.0 |

## 5. ОТСУТСТВИЕ UI ПРОВЕРКИ (The Black Box Principle)

### 5.1. Что игрок ВИДИТ во время игры

- NPC на карте (позиции, движения)
- Реплики NPC (через DM-агента)
- peripheral_cues (замер, отвод взгляда — БЕЗ объяснения почему)
- Атмосферу (тёмный угол, шум камина)
- Свои действия и их физические последствия

### 5.2. Что игрок НЕ ВИДИТ

- Trust/fear числа
- Список секретов
- Прогресс раскрытия
- Confidence игрока
- Правильность своих выводов
- Количество оставшихся секретов

### 5.3. Принцип

> Игрок никогда не знает, правильно ли он понял. Он только видит реакции NPC. Если он ошибается — NPC реагирует непредсказуемо. Если прав — NPC нервничает.

### 6.2. EvaluationEngine

```python
@dataclass
class EvaluationResult:
    """Результат сравнения PlayerBeliefModel vs TruthState."""
    
    # 1. Secret accuracy
    secrets_total: int  # 16
    secrets_identified: int  # сколько игрок угадал
    secrets_misidentified: int  # игрок был уверен, но ошибался
    secrets_missed: int  # не заметил
    
    # 2. Causal graph accuracy
    causal_links_total: int  # 20
    causal_links_identified: int  # игрок понял связь между секретами
    causal_graph_score: float  # 0..1
    
    # 3. Method quality
    methods_used: Dict[str, int]  # {"observation": 7, "dialogue": 3, "eavesdrop": 2, "coercion": 1}
    
    # 4. Social impact
    relationship_deltas: Dict[str, Dict[str, float]]  # {npc_id: {trust_delta, fear_delta}}
    
    # 5. Detailed breakdown
    per_secret_results: List[SecretEvaluation]
    per_npc_results: List[NpcEvaluation]

@dataclass
class SecretEvaluation:
    secret_id: str
    npc_id: str
    player_confidence: float  # 0..1
    was_correct: bool  # True если игрок правильно идентифицировал
    discovery_method: str  # "dialogue", "eavesdrop", "coercion", "accident"
    supporting_observations: int

class EvaluationEngine:
    """Сравнивает PlayerBeliefModel с TruthState."""
    
    def evaluate(
        self,
        truth: TruthState,

        observations: ObservationLog,
        actions: List[InterventionEvent],
        relationship_deltas: Dict[str, Dict[str, float]],
    ) -> EvaluationResult:
        ...
```

## 9. DESIGN PRINCIPLES

1. **Игрок = наблюдатель системы.** Система = скрытая причинная модель. Выход = момент оценки.
2. **No real-time correctness feedback.** Игрок никогда не знает, прав ли он.
3. **Truth ≠ Observed ≠ Inferred.** Три слоя данных, разделённые строго.
4. **Evaluation is post-hoc only.** Сравнение PlayerBeliefModel с TruthState — только при выходе.
5. **NPCs operate independently.** NPC не знает, что его «оценивают». Он живёт свою жизнь.
6. **Causal continuity preserved.** NPC-NPC взаимодействия продолжаются, даже если игрок не наблюдает.
7. **Replay incentive = epistemic error.** Игрок возвращается не за наградой, а за более точной моделью мира.

## 10. SUCCESS METRIC

Игрок выходит из таверны с:
- неполной, но когерентной системой убеждений
- измеримым расхождением с ground truth
- стимулом к переигровке, вызванным эпистемической ошибкой, а не наградой
