## 1. НОВЫЕ ЭМЕРДЖЕНТНЫЕ BEHAVIOURS (обнаружены S89)

### E1: Cross-location NPC movement
NPC ходят **между локациями** (guard_borko: city_gate → tavern_silver_wolf:right_table).
Это первый случай когда NPC покидают рабочее место для удовлетворения потребностей.

### E2: BUG_V_GUARD — position identity collision
При завершении traversal NPC прибывает в узел, где уже находится → `from_node == target_node` → TRAVERSAL SKIPPED.
Это корректный guard, но указывает на потенциальную race condition между traversal completion и schedule intent.

### E3: SHADOW_COMPILER FAILED
`target=merchant_goran field=position value=tavern_silver_wolf:corner_table` — Shadow Compiler не может скомпилировать позицию с namespace-префиксом `tavern_silver_wolf:corner_table`.

## 2. ОСТАВШИЕСЯ ПРОБЛЕМЫ (ПРИОРИТЕЗИРОВАННЫЕ)

### P1: shelter_urge saturation (guard_borko, merchant_goran)
**Симптом:** `shelter_urge:1.00 activity=resting has_am=False` — потребность растёт до 1.0, но semantic fallback не находит BED в city_gate/market_square.
**Причина:** Нет BED-узлов в city_gate и market_square.
**Фикс:** Добавить BED-узлы в JSON карт или расширить semantic fallback (resting → DEFAULT при отсутствии BED).

### P2: BUG_V_GUARD — DUPLICATE_POSITION_CHANGE
**Симптом:** NPC завершает traversal в узел, где уже физически находится.
**Причина:** Schedule intent генерируется для позиции, которую NPC уже занимает (например eating→main_hall, но NPC уже в main_hall).
**Риск:** Потеря comparisons при каждой смене активности.
**Фикс:** Проверять `current_position == target_position` ДО создания traversal.

### P3: SHADOW_COMPILER namespace mismatch
**Симптом:** `value=tavern_silver_wolf:corner_table` — canonical ID вместо bare node_id.
**Причина:** Cross-location SceneChange содержит namespace-prefixed node_id, но Shadow Compiler ожидает bare name.
**Фикс:** Strip location prefix в Shadow Compiler для same-location позиций.

### P4: drift_C=1 (0.25%) — единичный случай
**Статус:** Ниже целевого порога. Исследовать при повторении.

### P5: drift_B=270 (DEPRECATION — Rule 122)
**Статус:** Информационный. Boundary mutation до apply_changes. Не влияет на gameplay.
