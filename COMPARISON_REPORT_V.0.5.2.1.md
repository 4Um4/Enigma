## 1. Критический параметр решения

**Критический параметр**: доля структурных изменений против доли новой логики.

- 1566/1588 файлов (98.6%) — это переносы (`rename`) в основном из `backend/*` в `frontend/*`.
- Реальная новая логика сосредоточена в небольшом числе backend-модулей:
  - `backend/app/services/events/intent_event_adapter.py`
  - `backend/app/services/game_loop/dm_phase.py`
  - `backend/app/services/game_loop/npc_orchestration.py`
  - `backend/app/services/game_loop/finalize_phase.py`
  - `backend/app/core/tick_orchestrator.py` (существенное усиление фаз)

Вывод: за день сделан **архитектурный поворот**, а не «набивка строк».

## 2. Возможные сценарии при минимальном смещении входных данных

### Сценарий A — «Стабильный прогон» (наиболее вероятный)
- Новая фазность (`dm_phase` → `npc_orchestration` → `finalize_phase`) стабилизирует последовательность мутаций состояния.
- `IntentEventAdapter` даёт единый шлюз `CommunicationIntent -> EventDTO`, снижая расхождения формата событий.
- `tick_orchestrator` получает более строгую основу для памяти/тем/решений по фазам.

### Сценарий B — «Тихие регрессии от миграции путей»
- Из-за массовых переносов модулей/ассетов (`backend -> frontend`) возможны неочевидные проблемы импортов/путей ресурсов.
- На уровне git всё выглядит как rename, но runtime может зависеть от старых относительных путей.

### Сценарий C — «Дрейф контекста в DM/NPC-фазах»
- Если `shared_context` частично не заполнен, новые фазы могут давать неполный контекст для NPC pipeline.
- Риск особенно в ветках fallback-логики (`try/except` с мягкими warning).

## 3. Что может перевернуть итоговый вывод

- Если в проекте есть внешние зависимости, жёстко ожидающие старые пути `backend/map_editor/*`, ценность миграции резко падает из-за high-cost интеграционных фиксов.
- Если DecisionHub/MemoryProcessor в следующих шагах не будут доведены до полной интеграции фаз 6-8 (`tick_orchestrator` пока с TODO), часть архитектурного выигрыша останется «проектным намерением».
- Если не покрыть e2e-тестом новый порядок фаз, можно получить ложную стабильность: код компонуется, но причинность NPC-решений деградирует.

## 4. Альтернативные варианты с вероятностной оценкой (0-100%)

1. **Фактически сделано ценное архитектурное усиление + успешная миграция слоёв** — **70%**
2. **Сделан в основном технический перенос файлов, а бизнес-ценность ограничена** — **20%**
3. **Перенос создаст больше проблем, чем пользы, из-за путей и интеграций** — **10%**

Почему оценка не 100%: масштаб rename очень большой, а такие изменения статистически часто несут хвост интеграционных дефектов.
