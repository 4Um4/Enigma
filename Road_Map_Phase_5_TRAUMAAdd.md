# Фаза 5: Система переработки травм и долгосрочного восстановления (Trauma Processing & Recovery)

Данный документ описывает план внедрения механик долгосрочного психологического восстановления NPC, разделяя концепции «подавления» (Suppression) и «интеграции» (Integration) травматичного опыта.

---

## 1. Предмет внедрения

Внедрение архитектурного слоя **TraumaProcessingModel**, который заменяет прямое восстановление целостности личности (Identity Integrity) на сложную систему переработки травм. 

**Ключевые компоненты:**
*   **Структура `TraumaState`**:
    *   `raw_intensity`: Базовая сила травмы (неизменна при подавлении, снижается только при интеграции).
    *   `processed_intensity`: Текущая активная сила травмы, влияющая на решения.
    *   `suppression_level`: Уровень подавления (замещения).
    *   `integration_level`: Уровень переработки (истинного исцеления).
    *   `trigger_sensitivity`: Чувствительность к триггерам (растет при высоком подавлении).
*   **Suppression Path (Путь Замещения)**: Временная маскировка травмы через сильные новые стимулы (религия, насилие, одержимость, зависимости). Снижает `processed_intensity`, но сохраняет `raw_intensity` и повышает риск нервного срыва при триггерах.
*   **Integration Path (Путь Переработки)**: Редкий и сложный процесс истинного исцеления в условиях безопасности. Снижает `raw_intensity` и формирует черту `scarred_but_stable`.
*   **Когнитивный диссонанс (Belief vs Behavior)**: Разделение того, что NPC осознает (`belief_state`), и того, что он делает по привычке (`behavior_pattern`).

## 2. Локация/Область

Изменения затрагивают ядро симуляции жизни и принятия решений (Backend Python Logic):
*   **Memory Layer (`trauma_processing.py`)**: Новый модуль для хранения и маршрутизации травм.
*   **`app/services/npc/life_engine.py`**: Добавление методов `process_trauma_suppression()` и `process_trauma_integration()` в ежедневный цикл (tick/day processing).
*   **`app/services/npc/state_applicator.py`**: Обновление `processed_trauma` на основе текущих уровней подавления/интеграции.
*   **`app/services/npc/decision_hub.py`**: Перевод расчетов с `raw_intensity` на `effective_trauma` (`processed_intensity`).
*   **`app/services/npc/npc_state.py`**: Расширение модели данных для хранения `TraumaState`.

## 3. Обоснование (Зачем)

*   **Устранение "Билета в один конец"**: Решает проблему отсутствия выхода из состояния `BROKEN` (выявленную в аудите системы Слома), не скатываясь в казуальное "магическое исцеление".
*   **Глубокий психологический реализм**: Позволяет симулировать ПТСР, зависимости, фальшивое восстановление и внезапные срывы.
*   **Долгосрочные последствия**: Действия игрока (абьюз) оставляют перманентные шрамы. Даже если NPC кажется "нормальным" (высокий `suppression_level`), его психика изменена.
*   **Нарративная глубина**: Создает почву для когнитивного диссонанса, когда NPC понимает, что в безопасности, но продолжает действовать по паттернам жертвы.

## 4. Ресурсы и стоимость (Почем)

*   **Время реализации**: 2-3 недели (1 спринт на математику и структуры данных, 1 спринт на интеграцию с LLM и тесты).
*   **Человеческие ресурсы**: 
    *   1 Backend Developer (Python, архитектура `LifeEngine`).
    *   1 Prompt Engineer (настройка системных промптов для отыгрыша когнитивного диссонанса).
*   **Инфраструктура**: Незначительное увеличение объема хранимых данных в БД (добавление объекта `TraumaState` в JSON состояния NPC). Вычислительная нагрузка минимальна (математика обрабатывается на стороне Python, а не LLM).

## 5. Пошаговый план реализации (с учетом рисков из `Баги.md`)

### Этап 1: Расширение структур данных (Дни 1-3)
*   **Действие**: Создание класса `TraumaState` и интеграция его в `NPCState`.
*   **Риск (`Баги.md`)**: Ошибки парсинга JSON при сериализации/десериализации сложных вложенных объектов.
*   **Дебаггинг/Минимизация**: Использовать строгую валидацию Pydantic. Написать миграционные скрипты для старых сохранений, чтобы инициализировать пустой `TraumaState` у существующих NPC.

### Этап 2: Математика LifeEngine (Дни 4-7)
*   **Действие**: Реализация формул `suppression_gain` и `integration_gain` в `LifeEngine`. Настройка деградации и роста параметров во время отдыха/сна.
*   **Риск (`Баги.md`)**: Асинхронные гонки данных (Race Conditions) при одновременном обновлении состояния из разных потоков.
*   **Дебаггинг/Минимизация**: Обернуть обновление `TraumaState` в транзакционные блоки или использовать существующие механизмы блокировки (locks) в `StateApplicator`.

### Этап 3: Интеграция с DecisionHub и Триггерами (Дни 8-10)
*   **Действие**: Внедрение системы триггеров. Если происходит событие-триггер, а `suppression_level` высок -> резкий скачок `processed_intensity` -> срыв.
*   **Риск (`Баги.md`)**: Переполнение контекстного окна (Context Overflow) при передаче всей истории травм.
*   **Дебаггинг/Минимизация**: В промпт для LLM передавать **только** `processed_intensity` и активные триггеры текущей сцены. Сырые данные (`raw_intensity`) остаются исключительно на бэкенде для математики.

### Этап 4: Настройка LLM и Когнитивного диссонанса (Дни 11-14)
*   **Действие**: Разделение `belief_state` и `behavior_pattern` в промптах. Обучение модели отыгрывать противоречия (например, "Я знаю, что он мне не навредит, но руки все равно дрожат").
*   **Риск (`Баги.md`)**: Галлюцинации LLM (модель игнорирует системные ограничения и "исцеляет" NPC по своей инициативе).
*   **Дебаггинг/Минимизация**: Жестко прописать в `System Prompt`: *"Ты НЕ МОЖЕШЬ игнорировать behavior_pattern. Даже если твои мысли (belief) позитивны, твои физические действия (behavior) диктуются травмой"*. Использовать `ConstraintEngine` (из Фазы 4) для блокировки "слишком здоровых" действий.

### Этап 5: Тестирование долгосрочных симуляций (Дни 15-18)
*   **Действие**: Прогон NPC через 30+ игровых дней для проверки баланса между Suppression и Integration.
*   **Риск (`Баги.md`)**: Дублирование или потеря памяти на длинных дистанциях.
*   **Дебаггинг/Минимизация**: Написать unit-тесты, симулирующие пропуск времени (time skip) без вызовов LLM, чтобы проверить исключительно математику деградации травмы и накопления зависимостей (`addiction traits`).
