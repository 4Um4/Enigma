Рекомендованный пошаговый план для ЛЛМ

Проверка: GET /api/interface/players/demo-campaign.

Если пусто: задать пользователю вопрос о совместном создании персонажа.

Сбор данных: собирать характеристики шаг за шагом через диалог.

Формирование объекта: собрать JSON или структуру для бэкенда.

Отправка в бэкенд: POST /api/interface/players/demo-campaign с данными.

Старт игры: после подтверждения ЛЛМ переходит к основному сценарию, блок «Выберите персонажа» исчезает.


Потенциальные ошибки, которые ломают цикл:

ЛЛМ получает пустой или некорректный контекст (players пусто) → повторяет запрос.

Бэкенд не поддерживает динамическое создание персонажей → нужна фиксация промпта модели, чтобы она сама создавалась «в памяти» и отправлялась в API.

Фронтенд жёстко привязан к полям персонажа → нужно расширить шаблон промпта, чтобы игрок и мастер могли совместно формировать объект.


Как можно поробовать это сделать:

Чтобы правильно запустить диалог без этого тупика, ЛЛМ нужно дать следующие инструкции:

Проверять существование персонажа:

Если игрока нет → начать с вопроса «Хочешь создать персонажа вместе со мной?».

Не требовать выбора из списка, пока пользователь не захочет.

Инициировать совместное создание персонажа:

Шаг 1: Определить ключевые характеристики (имя, раса/тип, класс/роль, начальные навыки).

Шаг 2: Вести диалог с уточнениями, но не фиксировать значения до согласия игрока.

Шаг 3: Генерировать JSON/структуру персонажа для бэкенда только после финализации игроком.

API-интерфейс:

ЛЛМ должен поддерживать вызовы типа POST /api/interface/players/demo-campaign с динамическими данными, а не ждать фиксированного выбора.

Все GET-запросы должны обрабатывать пустой список как «создание нового».

Поведение фронтенда:

Вместо бесконечного «Пожалуйста, выберите персонажа» → показать кастомный интерфейс «Создать персонажа с мастером».

После подтверждения отправлять объект в бэкенд, тогда API перестанет возвращать ошибку.
